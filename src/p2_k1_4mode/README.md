# SC520CS / 安路 PH1P35：K1 四模式

独立工程，来自 `E:/fpga/contest-s2/src/p1_colorbar` 的摄像头版本。原工作目录及原位流保持原样。本目录的硬件基础通路是 SC520CS、MIPI、ISP、DDR、720p HDMI，保留原有安路 Logo 与 OSD 计数。

## 使用

1. 打开 `OUR_project/hdmi_base_src/td_project/OUR_K1_4mode.al`，工具版本 TD 6.2.168116（6.2.1）。
2. 编译结果归档于 `bitbank/OUR_K1_4mode.bit`。首次验证使用 PROGRAM_SRAM；断电后需重新下载。
3. 上电为彩色原图。板载 **KEY1（D5，低有效）** 每次按下切换：原图 → 灰度 → 中值 → 边缘 → 原图。
4. 按下稳定约 20 ms 后计一次；长按不重复，松开稳定后才接受下一次按下。模式在新帧生效，DDR 帧缓存还会带来显示延迟。

## 处理与接口

| 模式 | 行为 |
|---|---|
| 0 原图 | AWB 后 RGB888 原样输出，保留摄像头色彩 |
| 1 灰度 | `Y=(77R+150G+29B+128)>>8`，黑 0、白 255 |
| 2 中值 | 灰度图的精确 3×3 九点中值；用九级奇偶排序流水线 |
| 3 边缘 | 中值后 Sobel，`abs(Gx)+abs(Gy)`；局部中心灰度 <64 / <128 / 其余时阈值 112 / 88 / 64；黑底白边 |

四像素/拍，全宽 1280、720 行。中值和 Sobel 使用因果窗口，分别取当前像素及其前两行、前两列；因此中值图内容相对原图约右下偏 1 像素，边缘约 2 像素。前两行/列中值旁路灰度，Sobel 不满窗口处输出黑，避免未初始化 RAM 产生雪花。不会裁切或减少像素数量。

所有模式固定流水延迟；模式只在输出 SOF 锁存。KEY1 模式在 50 MHz 域以格雷码递增，经过摄像头时钟域两级同步。原有 `I_button`（N2/J14）保持其原用途，新加 `I_key1` 专门接 D5。

AWB 的帧起始脉冲提前于像素，既有 DDR 输入 FIFO 依赖该提前量复位。因此 `isp_top` 给图像算法生成与第一组有效像素一致的 SOF，同时给 DDR 保留 AWB 原始的提前复位信号。没有把随像素延迟后的 SOF 直接用于 FIFO 复位。

## RGB 与 HDMI

- SC520CS 使用 2-lane RAW10；沿用现有 BGGR 解码与 AWB，算法插在 AWB 后。
- 算法输入是 RGB888，`[95:72]` 是第一个像素，单像素 `[23:16]=R,[15:8]=G,[7:0]=B`。新算法内部灰度范围始终为 0–255，不把 RAW10 直接当成 RGB，也不把有限范围亮度公式混入全范围像素。
- 灰度、中值、边缘均严格输出 R=G=B；边缘只有 `000000` 和 `FFFFFF`。保留 HDMI 核的 `VIDEO_FORMAT="RGB"`、VIC=4 和 720p 时序。
- HDMI 加密核的 AVI 量化范围声明未在可读接口中暴露，本次没有宣称已验证显示器最终采用的量化范围。验收时用黑白区域确认，若显示器可选 RGB 范围，先用全范围对照。0–255 与 16–235 不匹配一般影响黑白电平；仅凭照片中的偏蓝不能确定链路故障或根因。
- 实际 PLL 配置沿用当前工程：TD 报告 HDMI 像素时钟约 75.002 MHz，按 1650×750 总时序约 60.61 Hz；并非文档早先写的精确 74.25 MHz/60 Hz。本次不重新生成已工作的 PLL。摄像头字节时钟按官方 828 Mbps / 8（约 103.52 MHz）约束。

## 文件与复现

- `rtl/image_modes4.v`：灰度、排序中值、边缘、帧边界选择。
- `rtl/window4.v`：三块轮转同步行 RAM、四像素并行窗口。
- `rtl/k1_mode.v`：按键同步、20 ms 消抖、格雷码循环。
- `OUR_project/.../isp/isp_top.v`：AWB 与处理通路、DDR 封包连接。
- `tools/build.ps1`：命令行综合、布局布线、生成 bit；默认 TD 在 `E:/fpga/bin`，可设置 `TD_BIN`。
- `tools/verify.py`：独立 Python 黄金模型，生成刺激并用 Icarus 逐像素比较。默认 1280×16×4 模式；`TEST_HEIGHT=720` 验证完整四帧。需要 Python 3 和 Icarus（脚本当前路径为本机工具目录）。
- `tools/verify.ps1 -Full`：完整运行像素、真实参数按键和 DDR 接口三组测试。行 RAM 在仿真中使用项目已有 PH1P ERAM 行为模型，综合时使用安路真实原语。
- `sim/tb_key.v`：真实 50 MHz / 20 ms 消抖测试。
- `sim/tb_isp_adapter.v`：隔离模拟 AWB 输出，验证提前 SOF、模式 0 字节顺序及 96→128 封包；不模拟加密 MIPI/DDR/HDMI PHY。
- `sim/`：验证日志、构建日志与生成的仿真数据；`BUILD_REPORT.md`：最终构建结果。

借鉴了本地 `FPGA_Image_Processing` 中窗口与中值的算法思路；该参考使用单像素视频同步与 FIFO。本工程新写四像素/拍、同步 RAM 轮转和排序流水线，没有移植 Xilinx IP。旧工程已有的官方板级模块及素材保持来源。

## 上板验收

先记录烧录位流 SHA256，再观察原图色彩和白纸、黑物体。连续按 K1 至少两轮，确认四态顺序、长按不连跳、Logo 与 OSD 全程存在。对比灰度和中值的平坦区域噪点，以及边缘模式在桌面、暗墙和物体轮廓的表现。强光与暗光切换后观察恢复，连续运行 30 分钟记录是否有横条、撕裂、闪黑或卡死。

仿真和编译不能替代上板观测。新阈值是初始工程参数，真实 SC520CS 噪声与曝光场景仍需实测；未把照片中的雪花标为已消除，也未把稳定运行或官方评分条款标为已验收。

2. 若提示缺文件，说明层级被改动过：必须保持 `src/p2_k1_4mode/OUR_project/hdmi_base_src/td_project/` 这个深度。

### 队友怎么用

- **只要能看效果**：按上面「位流怎么拿」取 `.bit` 烧写。上电为原图；板载 **KEY1（D5，低有效）** 每按一次切换：原图 → 灰度 → 3×3 中值 → 自适应阈值 Sobel → 原图，20 ms 消抖，长按不连跳。
- **要改算法**：打开 `OUR_project/hdmi_base_src/td_project/OUR_K1_4mode.al`，重新 Syn + Phy 出位流。
- **要跑验证**：`tools/verify.ps1 -Full`（需 Python 3 与 Icarus；行 RAM 用项目内的 PH1P ERAM 行为模型）。
- **两块位流互不替代**：`src/p1_colorbar/` 是队友的算法/OSD 路线，本目录是 K1 四模式路线；烧哪块看到哪套行为，都能反复重烧。
