### B4-OSD-v5（★ 现行 · 待上板 · 2026-10-18 13:43）

**烧 `OUR_b4osd_v5_darkfloor.bit`**。与上一版（v4 阈值）**唯一差别是四档阈值的常量**，硬件结构一行没动：

| 档位（用 5×5 均值判亮度） | v4 地板 | **v5 地板** | 等效最小可检阶跃 Δmin = thr/10 |
|---|---|---|---|
| 暗 `m25 < 64` | 192 | **144** | 19.2 → **14.4** |
| 次暗 `< 128` | 160 | **132** | 16.0 → **13.2** |
| 中 `< 192` | 128 | **116** | 12.8 → **11.6** |
| 亮 `≥ 192` | 96 | **96**（不变） | 9.6 → 9.6 |

> Δmin = thr/10 的推导：`mag = |S1−S2| + |S3−S4|`，竖直阶跃只有水平差分项贡献、5 行累加 → **mag = 10Δ**。

**上板该看的两件事（按重要性排序）**

| 操作 | 期望现象 | 若不对说明什么 |
|---|---|---|
| ① **正常光照对着手/桌子缓慢移动** | 暗处（阴影里、桌下）的弱轮廓**比 v4 更容易出来** | 没变化 → 可能烧的还是老位流，核对 SHA256 |
| ② **盯住暗而平坦的面**（黑色外壳、暗墙、关灯的桌面） | 应当**仍是干净的**，没有细碎白点连片 | 出现雪花 → 144 对这个场景还是偏低，退回 160 或加大 I_k |
| ③ 强光/灯光直射处 | 与 v4 一致，细节不糊 | 亮档没改，**这里不该有任何变化**；若变了说明改错了 |

**资源与时序（实测，非估算）**

| 指标 | v4 阈值版 | **v5 阈值版** |
|---|---|---|
| 综合 slice | 16,393（77.27%） | **16,393（77.27%）** |
| 综合 LUT / ERAM / DSP | 20,008 / 63 / 9 | **20,008 / 63 / 9** |
| P&R 后 slice | 16,710（78.76%） | **16,616（78.32%）** |
| P&R 后 slice reg / ERAM / DSP | 14,071 / 60 / 9 | **14,071 / 60 / 9** |
| Setup WNS | +0.005 ns | **+0.101 ns** |
| Hold WNS | +0.020 ns | **+0.020 ns** |
| 违例 | 0 | **0** |

> 只换常量却省了 94 slice、时序好了 96ps —— 因为常量变小后 `thr_calc` 的比较器与减法器被优化掉了几级。**这是意外收益，不是必然**：以后再改这几个数，不要假设资源会持平。

**仿真侧证据**（`tools\analyze_dark_threshold.py`，12 种子平均、虚警全为 0.00%）

| 场景 | v4 检出率 | **v5 检出率** |
|---|---|---|
| 暗背景 Δ=8（无噪声） | 1.1% | **44.6%** |
| 暗背景 Δ=10（无噪声） | 27.2% | **95.9%** |
| 暗背景 + ±10 噪声 | 22.9% | **68.8%** |
| 暗背景 Δ=8（理想无噪声、无强边种子） | 0% | **0%** |

> 最后一行要留意：因果迟滞（`strong | (weak & 邻域已判决边)`）在没有强边种子时**整条弱边都不点亮**，这是设计行为不是 bug。所以「纯暗场里一条孤立弱边」本来就检不出，别拿它当失败判据。

### B4-OSD（上一版 · v4 阈值 · 已上板验证 Logo）



**现行烧 `OUR_b4_osd_official_pending.bit`（官方实现）**

| 操作 | 现象 |
|---|---|
| 准备 | 插 SC520 摄像头 + HDMI + Type-C，Program SRAM 烧 `OUR_b4_osd_official_pending.bit` |
| 上电 | 等 5~10 秒 awb 收敛 → **实时摄像头画面**（算法现象同 A3-v4） |
| **判定点 ①** | **左上角 (0,0) 起 160×160 安路 Logo**（深蓝 `#1f315c` + 红 `#ec1c2d`），Logo 区内还有青色 `#00e6ff` 的 `ANLOGIC` 字样 |
| **判定点 ②** | **(375,120) 起 200×24 区域**显示**黄色** `#fff200` 的 `安路 CNT: <数字>`，数字**逐帧递增**（证明 OSD 是活的，不是烧死的图片） |
| 面板外 | 必须与原图一致 |

自研版（`OUR_b4_osd_selfdev_pending.bit`）的现象不同：左上 **(16,16) 208×156 浅灰面板 + 2px 深蓝描边**，Logo 在 (24,24) 146×94，底部两行 `ANLOGIC` / `PH1P35 720P`，颜色 `#1C2D4E`/`#ED1C24`/`#E0E0E0`。**别烧混**。

**v4 阈值下三种实现的对照（同一工程、同一约束；v5 的数字见上一节）**

| 指标 | A3-v4（基线） | 官方 OSD | 自研 OSD |
|---|---|---|---|
| P&R 后 #slices | 14,177（66.82%） | **16,710（78.76%）** | 14,654（69.07%） |
| #LUT6 | 12,187 | 14,632 | 12,292 |
| #RAMs / #DSPs | 60 / 8 | 60 / **9** | 60 / 8 |
| OSD 本体（分层面积） | — | **2,753 LUT + 229 FF + 1 DSP** | 593 LUT + 95 FF |
| Setup WNS | +0.376 ns | **+0.005 ns** | +0.787 ns |
| Hold WNS | +0.020 ns | +0.020 ns | +0.020 ns |

**三条要记住的结论**

1. **官方 OSD 比自研重 4.6 倍**（2753 vs 593 LUT）：它是 160×160×25bit 位图 ROM + 中文字库 + 完整 mux 树，自研版是 2bit/pixel 压缩位图 + 5×7 字模。
2. **官方版 Setup 只剩 5 ps**。原因已定位：`hdmi_mixer.v:619` 用 `S_logo_y * LOGO_W`（DSP 乘法器）**组合**算 ROM 地址再进输出 mux，像素域 13.33ns 预算里走 15.7ns。官方 lab_ex3 自己综合阶段也是 **-1.296ns**，靠 P&R 拉到 +0.103ns；我们这边是 -2.475 → **+0.005**。**能跑，但换 seed / 改逻辑都可能翻负**，正式出片前用 `MultiSeed.tcl` 多跑几组。
3. 想拿回余量又不想动结构：把那一行改成移位 `({3'b0,S_logo_y}<<7) + ({3'b0,S_logo_y}<<5) + S_logo_x`，可去掉 DSPMULT 与两级 ADDER（自研版就是这么做的，+0.787ns）。改动 1 行，行为不变。

> Hold +0.020ns 三版**完全一样**，说明这点薄余量是官方通路（DDR `usr_clk` 133M 域）的本征值，与 OSD 无关。

### ⚠️ A2 的已知问题（烧写前请知悉）

编译（11:12）后核对资源发现**算法综合异常**：

| 证据 | 数值 |
|---|---|
| 综合日志 | `extracting RAM for lb1/lb2/eb` + `PH1P_LOGIC_RAMFIFO(ADDR_WIDTH=10)` |
| 问题 | 地址位宽 10 → **1024 深**，而数组需要 **1280 深** |
| 层次资源 | `edge_adaptive_pixel` ＝ **48 LUT / 0 ripple / 37 seq / 0 eram**（近 20 个加法器的 Sobel 不可能这么小） |

**算法功能本身已在仿真中验证通过**（4 图 × 919440 像素，edge 与 mag 全 0 误差），
问题在"TD 综合时把行缓存识别成 `LOGIC_RAMFIFO` 且深度推错"。
排查过程与后续可选路径见 `..\..\memory\PROGRESS.md` 的「算法 RTL 回退记录」。
