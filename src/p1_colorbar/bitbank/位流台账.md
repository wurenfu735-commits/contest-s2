## 上板验收清单

### P1（已通过）

| 操作 | 现象 |
|---|---|
| 上电 | 八彩条 + 底部状态带（下半绿色 = PLL 已锁定） |
| 按 **KEY1** | 图案循环（棋盘 → 渐变 → 灰阶 → 彩条）；LED1 闪 0.2s；LED3/4 = 图案编号 |
| 按 **KEY2** | 立即回彩条 |

资源：reg 1409 / LUT6 941 / IO 13　　时序：Setup WNS +14.071ns、Hold WNS +23ps、0 违规

### A3-v2（待验证 · 摄像头版 · thr48 调参）

| 操作 | 现象 |
|---|---|
| 准备 | **插好 SC520 摄像头**（MIPI 恢复时钟是整条通路的"心跳"，不插=黑屏）、HDMI 接显示器、烧 `OUR_a3_camera_thr48_pending.bit` |
| 上电 | **等 5~10 秒让 awb 白平衡收敛**，屏幕显示**黑底白色物体轮廓**（参数 = `I_mode 2'd2` 我们的判决、`I_k 2'd0` 最低灵敏度、`THR_FLOOR 48`） |
| 判定 | 对着挥手/翻书 → **白轮廓随景物清晰变化、噪声大幅减少** → ✅ 算法在真实通路上工作 |
| 现象 A（太黑） | 轮廓太少/全黑 → 阈值 48 偏高，回调 32 |
| 现象 B（还噪） | 仍大片雪花 → 噪声 Sobel 幅值超 48 → 走方案 B：加 3×3 前置平滑 |
| 异常 | 黑屏 → 查摄像头排线/HDMI/烧错 bit；彩色原图 → 不可能（I_mode=2） |

**A3-v1 上板记录（2026-10-16 16:45）**：烧 `OUR_a3_camera_pending.bit`（THR_FLOOR=16 / I_k=2）画面 = **灰度雪花**。二分实验（临时改 `I_mode=0` 原图直通）确认：**摄像头→ISP→DDR→HDMI 通路 100% 正常（彩色实时画面）**，问题收敛为"真实暗部噪声经 Sobel 放大 + 自适应阈值 18 过低 → 假边缘连片"。故出 v2 调参版。

资源（v2，与 v1 同结构）：全设计 #lut 10548 / #reg 13990 / #slice 18.56% / #eram 50 / #dsp 8　　时序：**SWNS +0.464ns、HWNS +0.020ns、0 违规**（最紧域 = DDR `usr_clk` 133M，官方通路本征）

### A2（待验证）

| 操作 | 现象 |
|---|---|
| 上电 | 彩条原图，**LED3/LED4 全灭**（模式 00） |
| 按 **KEY1** | 8 种图案循环 |
| 按 **KEY2** ×1 | 态 1 ＝ 官方判决（LED4 亮 = 01） |
| 按 **KEY2** ×2 | **态 2 ＝ 我们的判决**（LED3 亮 = 10）← **判定点** |
| 按 **KEY2** ×3 | 态 3 ＝ 左右分屏（LED3+LED4 亮 = 11） |
| **关键场景** | KEY1 切到图案 **4/5/6**（低对比度）后进入态 3 → **左半屏几乎全黑（官方漏检）、右半屏清晰白线（我们检出）** |

**判定点说明**：

- 态 2 **出正常边缘图** → 算法正常，继续做完整验收
- 态 2 **全黑 / 与态 0 原图相同** → 算法没进网表（见下"已知问题"）

### ⚠️ A2 的已知问题（烧写前请知悉）

编译（11:12）后核对资源发现**算法综合异常**：

| 证据 | 数值 |
|---|---|
| 综合日志 | `extracting RAM for lb1/lb2/eb` + `PH1P_LOGIC_RAMFIFO(ADDR_WIDTH=10)` |
| 问题 | 地址位宽 10 → **1024 深**，而数组需要 **1280 深** |
| 层次资源 | `edge_adaptive_pixel` ＝ **48 LUT / 0 ripple / 37 seq / 0 eram**（近 20 个加法器的 Sobel 不可能这么小） |

**算法功能本身已在仿真中验证通过**（4 图 × 919440 像素，edge 与 mag 全 0 误差），
问题在"TD 综合时把行缓存识别成 `LOGIC_RAMFIFO` 且深度推错"。
排查过程与后续可选路径见 `..\..\memory\PROGRESS.md` 的「算法 RTL 回退记录」。
