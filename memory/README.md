# memory\ —— 记忆分区导读

## 这个目录是什么

项目的"大脑"：**只放两种东西——不变的事实与规则、按阶段变化的进度与实测数据**。
任何会话（人脑或 AI）丢了上下文，从这里读起就能恢复。

## 有什么

| 文件 | 性质 | 内容 |
|---|---|---|
| `MEMORY.md` | **不变的事实**（长期维护） | 关键事实（SC520、**v5 算法**、红线）、41 条已踩坑、编写规范、调研边界铁律、路线调整 |
| `PROGRESS.md` | **变化的进度**（按阶段追加） | 每阶段的成果、资源/时序实测数据、决策记录、当前暂停点。**只留 10-17 起的阶段** |
| `archive/PROGRESS_历史_20261014-1016.md` | 历史进度档案 | 10-14~10-16 的早期阶段数据（2026-10-19 从主文件切出），仅供查细节 |
| `DSH环境缺陷反馈_待提交.md` | 待办件 | 整理好待提交给 DSH 的环境缺陷反馈 |
| `backup_dsh_before_reinstall.bat` | 本机脚本 | 本机环境备份脚本，与项目内容无关，可忽略 |

## 怎么用

1. **新会话恢复**：先读 `MEMORY.md` 再读 `PROGRESS.md`（完整顺序见 `docs\00_阅读指南.md`「新会话恢复指令」）。
2. **每阶段收尾**：把实测数据（资源/时序/验证结果）按阶段追加进 `PROGRESS.md`，注明日期；**踩到新坑**写进 `MEMORY.md` 第五节并编号顺延。
3. **规则冲突时以 MEMORY 为准**：文档与它矛盾就是文档过时了，改文档、不要改记忆。
4. 历史记忆**不删不覆盖**，只追加新条目；本目录的权威地位见 `docs\02_文件存放规划.md`。
