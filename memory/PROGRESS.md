### 资源代价（这是本轮最大的发现）

| 版本 | 全片 slice | `hdmi_mixer`/`osd_overlay` 层 | Setup WNS |
|---|---|---|---|
| 无 OSD（v4） | 14,177（66.82%） | — | +0.376 ns |
| **官方 OSD（现行）** | **16,710（78.76%）** | 2,753 LUT + 229 reg + 1 DSP | **+0.005 ns** |
| 自研 OSD（备选） | 14,654（69.07%） | 593 LUT | +0.787 ns |

官方 OSD 一次性吃掉 **+2,533 slice**，并把时序余量从 376 ps 压到 **5 ps**。成因已定位（`docs/17` 第三节）：
1. **位图 ROM 位宽差 12.5 倍** —— 两者条目数**完全相同**都是 6,388 条，但官方 25bit/像素（159,700 bit）、自研 2bit/像素（12,776 bit）。159,700 ÷ 64 ≈ 2,500 LUT，与实测 2,753 对得上；
2. **`hdmi_mixer.v:619` 的 `S_logo_y * LOGO_W`** 组合乘法吃掉 1 DSP + 85 ripple；
3. **关键**：官方 ROM 是 `always @(*)` **异步读**，异步读在任何 FPGA 上都无法推断成块 RAM → 这 159,700 bit **结构上注定摊在 LUT 上**，不是参数没调好。

### 资源总账（`syn.log` 实测，纠正了一个流行误区）

Slice 16,454/21,216（**77.55%**）· ERAM **63/108**（58.33%，剩 45 块）· **DSP 9/40（22.50%，剩 31 个）** · Slice Reg 14,454/42,432（34.06%）。

> **我们缺 Slice，不缺 DSP。** 所以开源 Sobel 工程普遍强调的"kernel 全展开成移位加法、做到 0 DSP"对我们**是负优化** —— 省下的 DSP 换来更多 LUT 和进位链，正好打在唯一短缺的资源上。反过来应该把 LUT 重的乘加**往 DSP 里搬**。详见 `docs/17` 第二节推论 2。

## v5 暗区阈值优化 + 重新构建 —— 2026-10-18

**起因**：用户反馈「稍微暗一点的环境容易检测不出来」。这是真问题，不是错觉。

### 定量定位（关键在于把"暗"算成一个灰度数）

`mag = |S1−S2| + |S3−S4|`，**竖直阶跃只有水平差分项贡献、5 行累加 → `mag = 10Δ`**（45° 斜边约 20Δ）。所以判决门槛折算成"最小可检阶跃"就是 **Δmin = thr/10**。v4 的四档 192/160/128/96 → **Δmin = 19.2 / 16.0 / 12.8 / 9.6**，也就是说**暗区的门槛是亮区的整两倍**，暗场景本来就该漏检。

> ⚠️ 第一版我按 `mag = 20Δ` 算成 "192 → 9.6"，被自己写的 `tools/check_thr_consistency.py` 抓出来（它比对 RTL 参数与黄金模型）。**结论方向没变**（暗区门槛仍是亮区 2 倍），但所有 Δmin 数值都错了一倍。教训：这类"常数折算"必须写脚本交叉验算，不能心算。

### 为什么测试一直没发现

原有仿真只有两个场景：A = 亮区锯齿 + 暗区（**对比度 0**）+ 高亮段；B = 亮背景 120 + 台阶 14。
**「暗背景 + 小台阶」一次都没测过** —— 恰好是用户抱怨的那一类。所以 v4 这个失衡的工作点能一路跑到上板。

### 改了什么（只动常量，结构零改动）

`edge_adaptive_96.v` 参数化，四档地板改为 **144 / 132 / 116 / 96**：

```verilog
parameter [10:0] THR_FLOOR    = 11'd96,
parameter [9:0]  THR_ADD_D0   = 10'd48,   // 暗区 → 144
parameter [9:0]  THR_ADD_D1   = 10'd36,   // 次暗 → 132
parameter [9:0]  THR_ADD_D2   = 10'd20,   // 中   → 116
parameter [9:0]  THR_ADD_D3   = 10'd0,    // 亮区 → 96
```

`thr_calc` 的四个分支改为引用参数，可一键退回/退档。黄金模型 `section_floor()` 同步；新增 `tools/check_thr_consistency.py` 做 RTL↔模型常驻比对（不一致退出码 1）。

### 深度调研结论（对话中输出，验证后再落盘）

v5 上板的两个问题本质是同一个根因：**固定分段地板无法区分"噪声（高频）"和"模糊边缘（低频）"**。

统一解法候选 = **Sauvola 局部自适应阈值**（thr = FLOOR_min + k*dev，dev=局部平均绝对偏差）：
- 噪声区 dev 大 → 阈值自动抬高 → 压噪
- 模糊区 dev 小 → 阈值自动降低 → 检出模糊边
- 硬件复用现有 5×5 窗口，约 +300~500 LUT、0 DSP
