## 一、本阶段目标与结论

**目标**：把自研算法 `edge_adaptive_96`（96bit 全分辨率自适应阈值边缘检测）接入官方 SC520 摄像头 → HDMI 通路，生成可上板验证的位流。

**结论**：✅ 完成。算法仿真逐像素 0 误差；综合 ripple>0（未被优化删除）；P&R 时序 0 违规；bit 已生成并归档。

## 三、关键技术数据（答辩可引用）

**仿真**：128×8 图案（强边缘 127/40、40/200 + 弱边缘 121/124），与已验证逐像素版**逐像素完全一致（628 像素 0 误差）**。

**综合实测**（`gate.area`）：
| 模块 | LUT | ripple | seq | ERAM | DSP |
|---|---|---|---|---|---|
| `u_edge_adaptive_96` | 1134 | **148** | 305 | 11 | 0 |
| 全设计 | 10548 | — | 13990 | 50 | 8 |

**时序**（`final_timing.rpt`，Confidence: Routed）：SWNS +0.464ns / HWNS +0.020ns / **0 违例**；最紧域 = DDR `usr_clk` 133M（官方通路本征，与算法无关）。

**与官方的差异**（赛题红线对应）：
| 维度 | 官方 lab_ex2 | 我们 |
|---|---|---|
| 分辨率 | 降采样到 640 | 全 1280 |
| 阈值 | 固定 80 | 自适应（FLOOR + mean9×K/32） |
| 后处理 | 无 | 因果双阈值迟滞 |
| 显示 | 只有边缘图 | 四态可切（接口已留） |

## 四、踩坑与沉淀（细节见 MEMORY 坑 33–39）

1. 并行流水线行缓存地址必须逐拍推演（坑 33）
2. Verilog 拼接最左是 MSB（坑 34，`upleft` 方向反了是"每行多一对误检"的种子）
3. 验证方法要可靠：按像素编号对齐，别猜偏移（坑 35）
4. 对应模块自身带 +4 标注延迟，对比前量化（坑 36）
5. 行首跨行拍（坑 37）
6. **TD GUI 开工程持锁，外部改 `.al` 被回滚**（坑 38，本次最坑：改完必须关 TD / 等锁释放 / 复查留存）
7. patch 脚本要幂等自包含全部动作（坑 39）
8. 综合期 gate.qor 负 WNS 是布局前悲观值，以 Routed 报告为准（坑 28 补充）

## 五、上板验收清单（板子已到手，立即执行）

### 验收 A3（摄像头版）—— 烧 `bitbank\OUR_a3_camera_pending.bit`

| 步骤 | 操作 | 预期 |
|---|---|---|
| 0 | **插好 SC520 摄像头**（⚠️ MIPI 恢复时钟是整条通路心跳，不插=黑屏）、HDMI 接显示器 | — |
| 1 | 烧录 `OUR_a3_camera_pending.bit` | 烧写成功 |
| 2 | 上电/复位 | 屏幕显示**黑白边缘图**，对着景物有实时轮廓（`I_mode`/`I_k` 固定 2'd2 = 我们的判决、灵敏度 2） |
| 3 | 晃动摄像头前的手/物体 | 边缘随景物实时变化 → **算法在真实通路上工作** ✅ |
| 异常 A | 黑屏 | ① 摄像头排线重插 ② 换 HDMI 线/接口 ③ 确认烧的是 A3 的 bit |
| 异常 B | 彩色原图 | 不可能发生为佳（综合已确认 ripple=148）；若发生 → 记录，我查 |

**验收通过标准**：见到"随景物实时变化的黑白边缘图"。
