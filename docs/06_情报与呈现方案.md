# 06 · 重新对齐：我们到底要做什么、怎么呈现

> 触发：用户提出"对要做的功能不清楚、不知道在干的事起什么作用、最终作品以什么形式呈现"。  
> 情报来源：① GitHub 检索（8 个 FPGA 图像处理项目）② 高云赛道国一演示视频（BV15rKP6pEwi）③ 安路赛道国一选手的参赛经验 PPT + 2025 赛题解析 PPT。

## 〇、先纠正两个认知（很重要）

| 认知                | 事实                                                                                                  |
| ----------------- | --------------------------------------------------------------------------------------------------- |
| "国一作品做了 15 种图像处理" | 那是 **2025 年安路赛题二（以太网数据传输系统，HX4S20C 平台）** 的国一作品。**赛题与平台都已换代**，其**架构不可照搬**，但其**方法论与评分规律完全适用**         |
| "官方例程是用来改的"       | 更准确：**官方例程 = 硬件驱动库 + 及格线答案**。硬件层（MIPI/ISP/DDR/HDMI/PLL）必须复用；算法层必须自研（红线）；我们做的是"**复用它修好的路，在上面跑自己的车**" |

## 一、从国一选手 PPT 里拿到的 5 条"评分真相"

1. **"基础与扩展做满方能进入线下（决赛）"**（他与决赛选手交流所得）→ 扩展项不是"选做"，是**进决赛门票**。
2. **"一个优质的展示视频基本占晋级概率的 70%"**（评委原话）→ 视频的质量权重远超我们的想象，必须早规划。
3. **"多展示数值性的东西，不要只停留在完成功能"**——突出资源占用、传输速率等硬指标。
4. **"多思考视觉效果较强的技术，比如图像处理中的热力图、Sobel 边缘提取"**→ 我们选的边缘检测/卡通化方向正是"视觉效果强"的富矿。
5. **"如果创新性不强，可以着重介绍工作量，评委也认可"**→ **算法数量本身就是分数**（他们做了 15 种）。

配套方法论：三人分工（队长做 infra、A 做图像算法尽可能多、B 刷 Verilog 题+非图像 idea）；每周组会；**视频 > 技术报告**；每个功能展示前用文字介绍；国赛有 Verilog 上机测评 + 现场答辩（会被专家拷打 30 分钟、随时打断）。

## 二、从高云国一演示视频里拿到的"呈现公式"

```
【大字幕标题】"XX 功能展示"
      ↓
【实拍操作】手拧旋钮/按键 → 屏幕与仪器实时响应
      ↓
【口播指标】"支持……、可调……、最高 100MHz 采样、近百种协议"
```

特点：**功能切片**（8 个功能 = 8 段）、**指标先行**（全程报数字）、**专业仪器背书**（示波器/逻辑分析仪验证自己的输出）。

## 四、作品呈现形式（最终交付什么样）

### 作品定位一句话

> **"基于安路 PH1P35 的实时视觉增强平台"**——摄像头进、算法管道处理、HDMI 出，多模式实时切换，资源占用与延时全部量化。

### 三个交付物

| 交付物                 | 形式                           | 关键要求（来自国一经验）                  |
| ------------------- | ---------------------------- | ----------------------------- |
| **演示视频**（权重最高，~70%） | 一镜到底 + 功能切片 + 字幕标题 + 手操作实拍   | 每个功能前加文字介绍；全程报数值；展示鲁棒性测试      |
| **技术报告**（说明书式）      | 系统架构 / 算法原理 / 资源与时序数据 / 测试记录 | 提前 1~2 周开始写；一人专责格式；互相检查后给指导老师 |
| **答辩 PPT**          | 问题→方案→架构→算法→数据→创新点           | 准备被专家打断的问答；多做模拟演练             |

### 视频脚本骨架（按高云国一的形式，逐段）

```
0:00 片头：板卡 + 显示器 + 摄像头实拍，一句话讲清作品做什么
0:10 【MIPI 采集功能展示】字幕 + 实拍：画面实时跟随
0:40 【边缘检测功能展示】字幕 + 按键切阈值：黑白边缘图 + 指标（延时/资源）
1:10 【卡通化功能展示】字幕 + 效果对比
1:40 【目标检测展示】字幕 + 拿红色物体在镜头前移动，框跟随
2:10 【多算法切换展示】连续按键，6~8 种效果轮播（最抓眼球的一段）
2:40 【OSD 展示】安路 Logo + 状态信息叠加
3:00 【性能数据】资源占用表 + 帧率 + 端到端延时 + 连续运行稳定性
3:20 结尾：GitHub 开源地址 + 复现说明
```

## 五、这条情报对我们行动计划的修正

| 原计划        | 修正后                                                     |
| ---------- | ------------------------------------------------------- |
| 扩展只做 1~2 个 | ⚠️ **必须做满扩展**（国一证实是决赛门槛）→ 算法模块做成"可插拔"，每种算法一个模块，方便快速增加数量 |
| 视频最后一周再拍   | 提前规划：**从现在起每完成一个功能就录一段素材**（避免最后赶工）                      |
| 注重算法正确性    | 正确性 + **数值指标**并重（资源占用、帧率、延时都要能上屏/进报告）                   |
| 单一边缘检测     | **算法数量当卖点**：边缘/卡通/浮雕/马赛克/热力图/运动检测…越多越好（复杂度可控优先）         |
