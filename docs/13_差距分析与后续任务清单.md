## 三、关键发现：官方 OSD 是"现成"的，B4 从 2 天缩到半天

我把官方资料包里的 `lab_ex3_osd` 拆开看了，结论很实在：

**官方的 `hdmi_mixer.v` 里已经内置完整 OSD**，而且**端口/参数与我们工程里的 `hdmi_mixer.v` 完全一致**（`I_clk/I_rst_n/I_video_*/I_debug_status[3:0]/O_video_rd_en/I_video_rd_data/O_hdmi_*`，参数 `H_OFFSET/V_OFFSET/IMG_WIDTH/IMG_HEIGHT/DEBUG_MODE`）→ **技术上可以直接替换、顶层不用改一行**。

> ⚠️ 但"技术上能换"不等于"应该交这个"。下面是参照物的清单，**用它当调试基准，不当交付物**（原因见本节的"三重问题"）。

它里面有什么：
- `anlogic_logo_rom u_anlogic_logo_rom`：**160×160 的"安路"标识位图 ROM**（官方 Logo，正好满足 B4 的"包含安路标识 Logo"）；
- 5×7 点阵字模：A/N/L/U、C/N/T、0-9、`:`、a-f（十六进制）；
- 一块动态文字区 `DYN_OSD`（位置 375,120，尺寸 200×24），官方用来显示 `CNT: 1234` 计数器；
- 混合方式：命中即整像素替换（无 alpha）。

**资源账（实测，不是估算）**：

| 版本 | LUT6 | Slice | ERAM |
|---|---|---|---|
| lab_ex1（P0 基线，无 OSD） | 10002 (47.14%) | 12390 (58.40%) | 39 |
| lab_ex3（带 OSD） | **12669 (59.71%)** | **14852 (70.00%)** | 40 |
| 差值 ≈ OSD 成本 | **+2667** | +2462 | +1 |
| 其中 `u_hdmi_mixer`（官方带 OSD 版） | **2313 logic LUT / 85 ripple / 210 seq** | | |

**⚠️ 重要：别把这个当"白送"，要区分"借用"和"交付"**

官方 lab_ex3 的 OSD 是**参照物**，不是交付物。整段搬过来有三重问题：①赛题总则要求"作品必须原创"（见 `docs/11` §0）；②lab_ex3 的 OSD 只有"整像素替换 + 写死位置 + 一个 CNT 计数器"，搬了等于这项零工作量，评分拿不到；③所有用这块板的队伍都会长一个样，视频里一眼看出。

**正确切法（三档，按顺序用）**：

| 档 | 做法 | 用途 | 耗时 |
|---|---|---|---|
| **① 借用骨架（内部用）** | 把官方 `hdmi_mixer.v` + `anlogic_logo_rom.v` 拷进工程跑一遍，**只为拿到一个可对照的基准**（确认 Logo ROM 可用、OSD 混合点在像素域是对的） | 调试参照，**不进交付** | 0.5 天 |
| **② 自研叠加（交付用，推荐）** | 自写 `osd_overlay.v`：掩膜 + 描边 + 可选半透明 + 坐标可配 + 多区域（Logo / 状态 / 检测框）；**Logo 像素数据沿用官方 ROM**（主办方标识，重画反而失真），文字点阵可用官方字模，但**排版与渲染逻辑自写** | 正式 B4 + 后面所有指标上屏 | +1 天 |
| **③ 兜底（来不及才用）** | 整段复用官方 mixer + ROM，报告如实声明"OSD 采用官方 lab_ex3 参考实现，我们在其基础上扩展了 XX" | 只保住基础分，扩④/进③几乎拿不到 | — |

> 报告里统一写这句话：**"Logo 图形数据取自官方例程 ROM（主办方标识）；叠加与渲染逻辑为自研——官方为整像素硬替换、位置写死、仅显示计数器；我们为掩膜+描边+半透明、坐标可配、多区域，并动态显示模式名/帧率/端到端延迟。"** 这样既诚实又有说服力。

**资源估算（按 ② 自研版）**：Logo 掩膜存 1bit（160×160 = 25600 bit ≈ 1~2 块 ERAM，或缩到 96×32 只需 3072 bit）+ 5×7 字模 + 比较/混合逻辑，**预计 +400~900 LUT**，比整段搬官方的 +2667 LUT 省一半以上，对只剩 +0.376ns 的时序更友好。

**这带来的连锁收益**：Logo + 动态文字区一旦通了，后面**帧率/延迟/模式名/目标坐标全都往这块区域里塞**——扩④、进③、进①的"状态显示"一次全解决。
