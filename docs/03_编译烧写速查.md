## 二、GUI 编译（日常方式，最稳）

打开 `.al` 后，流程面板从上到下依次点，等每个变绿：

```
Read Design → Optimize RTL → Optimize Gate → Optimize Placement → Optimize Routing → Generate Bitstream
```

- 只改了**约束/逻辑**都必须重新跑到 Generate Bitstream（引脚位置是烧进 bit 的）
- 报错就把 log 贴出来（`...\td_project\log\` 下最新 .log）

## 三、命令行编译（AI 可自动执行，2026-10-14 打通）

工具：`E:\app\Software\work\td\bin\td_commands_prompt.exe`（TCL 接口）

脚本示例（现留档在 `archive\old_logs\rebuild_v3b.tcl`）：
```tcl
open_project OUR_p1_colorbar.al
launch_runs syn_1
wait_run syn_1
launch_runs phy_1
wait_run phy_1
exit
```

**三个必踩的坑（务必记住）**：

| # | 坑 | 正确做法 |
|---|---|---|
| 1 | 相对路径以**当前工作目录**为基准，不是工程目录 | 启动前必须 `cd` 到 `td_project`，否则报 `PRJ-9210 XML 不存在` |
| 2 | `launch_runs` 是**异步**的，脚本 `exit` 会掐断正在跑的 run | 用独立进程 + `Start-Process -RedirectStandardInput` 让 TD 一直活着 |
| 3 | `wait_run` 会卡在 `Waiting for run ... to finish`（但不影响 run 执行） | 从**外部轮询产物文件**判断完成（如 `phy_1\OUR_p1_colorbar.bit` 时间戳更新） |

**另一个重要经验**：TD 认为 run「已完成」时会**跳过重新综合**（`launch_runs` 直接返回）→ 改了 RTL 后必须先 `reset_runs syn_1 -f` 强制重跑，否则 bit 里还是旧逻辑。

## 五、验收对照（P1 v3 版本）

| 操作 | 屏幕 | LED 指示 |
|---|---|---|
| 上电 | 八色彩条（白黄青绿品红红蓝黑）+ 底部绿带（PLL 锁） | LED3/4 都灭 |
| 按 **KEY1**(D5) | 棋盘格 → 渐变 → 灰阶 → 彩条（循环） | LED1 闪 0.2s；LED3/4 显示图案编号 |
| 按 **KEY2**(A9) | 立即回彩条 | LED2 闪 0.2s |
| 底部状态带 | 上半段=当前图案指示色，下半段=绿（PLL 锁定） | — |

图案编号读法（LED3 为高位 / LED4 为低位）：`00`=彩条 · `01`=棋盘 · `10`=渐变 · `11`=灰阶

## 六、排错速查

| 现象 | 原因 | 处理 |
|---|---|---|
| `Bitgen is prohibited` | 有顶层端口没配 LOCATION | 检查 `.adc` 是否覆盖全部端口 |
| `USR-8409 DRIVESTRENGTH is not supported ... in INPUT direction` | `input` 脚带了 `DRIVESTRENGTH` | 删掉该属性（官方 `inout` 才允许） |
| `PRJ-9210 XML 文件不存在` | 命令行工作目录不对 | 先 `cd` 到 `td_project` |
| 改了代码但 bit 没变 | TD 跳过了重新综合 | `reset_runs syn_1 -f` 后重跑 |
| 按键无反应 | ①按错位置 ②消抖计数器位宽不足 | 见 [`09_问题总结_按键无响应.md`](./09_问题总结_按键无响应.md) |
| 画面无输出 | 显示器没插好 / HDMI 线 / 12V 未上电 | 先查硬件，再看 TD 是否烧写成功 |
