## 四、"必须用官方的东西"——边界与实测

### 4.1 官方三类文件的改动情况（`git log --follow` 可查）

| 类别 | 文件 | 提交次数 | 判定 |
|---|---|---|---|
| 加密网表 | `hdmi_1_4b_transmitter_core_wrapper.enc.v`、`mipi_dphy_rx/*.enc.v/.enc.sv` | **1（仅初始提交）** | ✅ 从未改动 |
| IP 生成 | `pll_hdmi.v`、`ph1p35_ddr/**`、`ph1p_ddrmc_wrapper_*.v` | **1** | ✅ 从未改动 |
| 官方 ISP | `awb.v`、`csi_unpacket*`、`raw10_unpacket*`、`uics520_cfg/*` | **1** | ✅ 从未改动 |
| 官方 OSD | `anlogic_logo_rom.v`、`osd_char_lib.v` | **1** | ✅ 原样使用（团队自律） |
| | `hdmi_mixer.v` | **2** | ⚠️ 见下方备注：是"换成另一份官方版本"，不是我们自己改逻辑 |
| 官方顶层 | `design_top_wrapper.v` | 3 | ⚠️ 当自己顶层在用：只改连线/参数/`ifdef` |
| **官方 ISP 连接板** | `isp_top.v` | **3** | ⚠️ **加例化 + 连线**，专项说明见下 |

> **`hdmi_mixer.v` 的 2 次提交是怎么回事**（别被数字吓到）：初始提交里那份是 **182 行、无 Logo** 的简化版（1600×900，只有窗口 mux）；2026-10-18 的 B4 提交把它换成了 **909 行的完整 OSD 版**（Logo ROM + 字符库 + 动态数字渲染）。也就是说这 2 次的方向是**从"官方无 OSD 版"换成"官方完整 OSD 版"**，替换后再没动过。
> 诚实说明：本仓库没有留存官方 lab_ex3 原始包，**无法逐字节比对**，能确认的是"该文件的 OSD 逻辑（`S_logo_pixel`、`S_char_bits`、`S_dyn_dec_digit`、`DEBUG_MODE=4` 诊断码）与官方 `osd_char_lib.v` 的接口一一对应"，且我们自研的 `osd_overlay.v` 是另起文件、未合入此文件。

### 4.2 `isp_top.v` 的专项说明（答辩口径）

`isp_top.v` 是**明文 Verilog**，不是加密件、不是 IP 生成物。我们只做了四件事：

1. 加两个输入端口 `I_mode[1:0]` / `I_k[1:0]`（透传，不改内部逻辑）；
2. 在 `awb` 与 `data_96bit_to_128bit` 之间**例化** `edge_adaptive_96`；
3. 把 `tready` 串进算法模块（握手链路必须改）；
4. 加一级 mux 让 `I_mode==0` 可取 awb 原数据。

**插入位置与握手方式对齐官方 `lab_ex2`**（官方边缘检测例程在同一个位置例化 `edge_detect_96`）。
**没有任何一行被修改的官方算法逻辑。** 详见 `docs/17` L1.5 节（该节已于 2026-10-18 更正，上一版把 `isp_top` 误列为"物理不可改"）。

### 4.3 仍然存在的一处功能缺口（不是合规问题，是功能问题）

| 项 | 现状 | 影响 |
|---|---|---|
| 按键 | `pin.adc` 里 `I_button[0..1]` = **N2 / J14（扩展口）**，而板载 KEY1/KEY2 = **D5 / A9**（`src/p1_colorbar/constraints/colorbar_top.adc`） | **板载按键按不到** |
| `I_mode` | 顶层写死 `2'd2`（`design_top_wrapper.v:720`），`I_k` 写死 `2'd2` | 四态切换无法现场演示 |

对基础 4 条**没有影响**（基础不要求按键）；但**高阶挑战(1)「多算法切换」必须依赖它**。
两条路：① 改 `pin.adc` 为 D5/A9 并重编（要重跑一次 syn+phy，约 10 分钟）；② 用扩展口外接按键。
**注意：改 `pin.adc` 必须重新构建，现有位流不能用。**

## 五、硬红线：原创性与第三方代码许可

《选题指南》第六条（P35）：**参赛作品必须为原创**。逐项核对：

| 检查 | 结果 |
|---|---|
| 自研 RTL 是否有整段拷贝痕迹 | ✅ 无。`rtl/*.v` 九个文件均为自研接口（96bit / 4 像素拍）重写，文件头注明借鉴的是**思路** |
| 是否使用了官方 OSD 模块 | ✅ 是，但那是**主办方自己的素材与实现**，赛规未禁止；已在 `docs/17` L2 声明 |
| Logo 位图来源 | ✅ 官方 `lab_ex3` 的安路标识素材，赛题要求就是要显示它 |
| **第三方开源代码是否原文件入库** | ⚠️ **有一处**：`docs/research/R3_参考源码/` 里放了 `conv2d.sv`、`sobel_convolution.v` 两个**第三方源文件原文** |

**关于这两个文件**：`docs/research/R3_参考源码/README.md` 写的是"只借鉴思路、不复制代码"，这个声明是诚实的（我们的 `edge_adaptive_96.v` 确实没抄）。但**把别人的源文件原文放进提交仓库，属于再分发**，而这两个文件**都没有 License 头**（默认保留所有权利）。

**建议（二选一）**：

- **A（推荐，零风险）**：删掉这两个 `.sv/.v` 文件，`README.md` 里保留仓库链接 + "借鉴了什么"的分析表。溯源照样能做，答辩时讲"看了哪个仓库的哪个思路"即可。
- **B**：保留，但在 README 里明确写"仅作学习分析、不参与编译、不用于交付成果"，并接受潜在的许可争议。

> 已核对：这两个文件**不在 `.al` 工程的文件清单里**，不参与综合，删掉不影响任何功能。

### 6.2 时序

| 指标 | 值 | 判定 |
|---|---|---|
| 布线后 Setup WNS（SWNS） | **+0.101 ns** | ✅ 0 违例端点 |
| 布线后 Hold WNS（HWNS） | **+0.020 ns** | ✅ 0 违例端点 |
| 综合阶段 SWNS | **−2.478 ns** | ⚠️ 官方 OSD Logo 乘法路径，靠 P&R 拉回正 |
| STA coverage | **42.96%** | ⚠️ 见下 |

**两条必须知道的**：

1. **综合阶段是负的（−2.478ns），P&R 后才 +0.101ns。** 余量很薄，换 seed / 改逻辑都可能翻负。**出正式片前跑 `MultiSeed.tcl` 多试几组。**
2. **STA coverage 只有 42.96%**，意思是约 57% 的路径不在约束覆盖范围内、未被分析。原因是我们的 SDC 只约束了 `sys_clk_50m` 与 PLL 派生时钟；DDR2（`usr_clk`/`ctl_clk`/`ddr_clk`）与 MIPI 恢复时钟由官方 IP/原语自带约束产生，不在这个文件里。**这不等于有 bug，但"0 违例"的适用范围要如实说成"已约束路径 0 违例"。**
