# 24 · 逐层架构体检：重大失误与可替代的更优方案

> 方法：用「七层框架（L0 物理硬件 → L6 呈现交互 + 贯穿层）」当体检表，逐层对照**你们的硬件（PH1P35MDG324）**与**当前进度（@20037f6）**，找「重大失误」与「有更好的替代」。
> 日期：2026-10-19 · 配套：`docs/23_外部评审_问题清单与16天实施方案.md`

## 〇、体检总览

| 层 | 判定 | 一句话 |
|---|---|---|
| L0 物理硬件 | 达标 | 链路扎实；**片内 RISC-V MCU 硬核、第二路 MIPI 完全闲置** |
| L1 传输接口 | 达标（有隐患） | 96bit 打包、DDR 四缓冲都对；**检测坐标与显示帧跨 DDR 未做帧对齐** |
| L2 图像形成 | 可优化 | 只有 demosaic+awb；**无统一 HSV 转换、无去噪、无暗区增益限幅** |
| L3 像素处理 | 可优化 | v5 算法成立，但**均值滤波与边缘检测目标相悖、分段地板治标不治本** |
| L4 区域分析 | **缺失** | 无任何区域聚合；**计划中的「行列投影」在多目标下失效** |
| L5 目标识别 | **缺失** | 无分类判据、无帧间跟踪、无输出去抖 |
| L6 呈现交互 | 可优化 | 官方 OSD 未换；**缺统一数值通道**；外部控制仅蜂鸣器 |
| 贯穿层 | 可优化 | STA 覆盖 21%；**无帧率/丢帧/错误计数器**；自检标志未接 |

## 一、三个重大失误（按严重度）

### 失误 1（架构级）：检测坐标与显示画面跨 DDR 未做帧对齐 🔴

**现象**：算法在 103.52 MHz 检测域产出坐标，OSD 在 74.25 MHz 显示域画框，中间隔着 DDR 四缓冲帧缓存（引入 1~2 帧延迟）。直接把坐标送去做叠加，**框会稳定落后画面 1~2 帧**——慢速移动不明显，快速移动时框明显"追不上"，演示现场会很致命。

**为什么现在就要处理**：这是**架构问题，不是调参问题**。等阶段 2 把检测做完再发现，返工的是整个数据通路。你们 mode 4 踩过的"3 拍延迟对齐"是同一问题的微缩版，跨 DDR 是帧级的更大版本。

**三种解法（按推荐度）**

| 方案 | 做法 | 成本 | 适用 |
|---|---|---|---|
| ① 帧号随行（推荐） | 坐标打上帧号，与帧数据一起过缓存；OSD 侧比较帧号一致才用 | 需占用 128bit 空余位或一条同步小 FIFO | 彻底、通用 |
| ② vsync 同步延迟链（最省） | 显示域用 k 级寄存器（k = 缓存帧数）把坐标延后 k 帧，与画面同一 vsync 释放 | 几十个 FF | 延迟固定时最省 |
| ③ 检测放在显示域之前 | 把检测挪到 DDR 之后、OSD 之前（像素域） | 改动大、且检测要重跑一遍像素流 | 不推荐 |

**验收**：目标做匀速左右摆动，框与物体边缘的偏移量应 ≤2 像素且不随速度增大；若框随速度增大而落后 → 说明没对齐。

---

### 失误 2：L4 区域层缺失，且「行列投影」多目标失效 🔴

**问题**：需求文档 §8.2 阶段 2 定的"行列投影求包围盒"，原理是对整帧做行/列方向命中计数后取非零范围——**只能给出全局包围盒**。两个同类物体分列画面两侧时，会输出一个横跨全屏的大框。

**三档替代**

| 方案 | 做法 | 成本 | 判定 |
|---|---|---|---|
| **A 网格化投影**（推荐） | 画面分 8×8 或 16×16 格，每格独立统计命中数与局部质心；相邻命中格合并成区域 | ~300–400 LUT + 极少存储（计数可放寄存器或 1 块 ERAM） | **16 天内性价比最高**，可区分多目标 |
| **B 单遍连通域 CCL** | 游程法 + 等价标签表，扫描中同时累积面积/质心/包围盒/几何矩 | ~800–1200 LUT + 1–2 ERAM | 正解，任意形状；有余力再做 |
| C 保持行列投影 | 只演示单目标，报告如实声明限制 | 0 | 兜底；分低、风险高 |

**建议**：阶段 2 直接上 **A**；若 10/26 前有余力再升级 B（B 与 A 的特征输出接口可以设计成一致，升级不改上层）。

---

### 失误 3：残雪的处置层级错了 🔴

**问题**：一直在 **L3 的结果端调阈值地板**（v5 把暗区地板 192→144，反而低于真实噪声梯度 → 上板雪花回潮）。而根因在两个更上游的位置：

- **L2**：噪声从这里进入，且 awb 增益把暗场噪声放大
- **L3**：用 5×5 均值滤波去噪——**均值滤波在平滑噪声的同时模糊边缘，与边缘检测的目标自相矛盾**

**正确的三层处置**

| 层 | 改法 | 成本 |
|---|---|---|
| L2 | **暗区增益限幅**：暗像素不放大增益，直接掐断噪声被放大的路径 | ~100 LUT |
| L3 | **5×5 均值 → 3×3 中值**：保边去噪，对脉冲噪声（雪花正是脉冲型）是正规军，成本与均值相近 | 复用现有行缓存 |
| L3 | **分段 FLOOR → 局部均值归一化**：`阈值 = base + k×(局部均值 − 全局均值)`，或 `梯度/局部均值` 归一化。**复用已经算出来的 5×5 均值窗口，零额外 ERAM** | 几乎 0 |

**判定**：继续调分段地板已被 v5 证伪，应停止。Sauvola（局部方差）理论更对，但 16 天内实现+验证+时序收敛成本过高，**列为有余力项**。现场补光是零成本兜底。

## 二、逐层改进方案（含更优替代）

### L0 物理与硬件层

| 项 | 现状 | 更优替代 | 价值 |
|---|---|---|---|
| **片内 RISC-V MCU 硬核** | **完全闲置** | 用它做：参数标定（阈值/灵敏度）、外设联动（蜂鸣器/数码管扫描）、UART 协议解析、模式菜单 | **最大价值：现场改阈值不用重编译**。16 天冲刺里每次编译约 10 分钟、还要重新上板，改成 MCU 侧可调能省下大量往返 |
| 第二路 MIPI D-PHY | 闲置 | 双摄（立体/双视角） | ❌ 时间不够，明确不做 |
| 补光 | 无 | 台灯/柔光罩 | **物理层解决噪声，成本 0，对残雪最直接** |
| SW5/SW6 | 未确认 | 演示前确认拨对（蜂鸣器/数码管选择） | 避免现场"外设没反应" |

### L1 传输与接口层

| 项 | 更优替代 | 说明 |
|---|---|---|
| 帧对齐 | 见失误 1 | 必做 |
| **千兆以太网（YT8511）** | 板载 PHY 闲置；`assets/ref_docs/guoyi_repo` 里**已有 UDP 上位机参考**（lab_ex4） | 这才是扩③「结合移动平台实现外部控制」的正解——PC/手机远程看坐标，比蜂鸣器有说服力得多 |
| UART（J1/H1） | 最低成本的坐标外传 | 半天可做，作为以太网的降级方案 |
| 96bit→128bit 打包 | 保持 | 设计正确，别动 |

### L2 图像形成层

| 项 | 更优替代 | 成本 |
|---|---|---|
| **统一 HSV 转换** | 在 L2 输出侧提供 HSV（或至少在检测算法前统一转换一次），避免卡通化/目标检测各转一次 | ~300 LUT，省下重复开销 |
| **3×3 中值去噪** | 作为**公共预处理**放在 ISP 之后（现在被塞进卡通化里是错位的） | 复用行缓存 |
| 暗区增益限幅 | 见失误 3 | ~100 LUT |

### L3 像素级处理层

| 项 | 更优替代 | 说明 |
|---|---|---|
| 5×5 均值 → **3×3 中值** | 保边去噪 | 成本相近 |
| 分段 FLOOR → **局部均值归一化** | 复用已有均值窗口 | 零额外 ERAM |
| **闲置的 31 个 DSP 要用起来** | HSV 的 max/min 与除法、质心除法、坐标缩放、幅值 sqrt | 与你们"缺 slice 不缺 DSP"的判断一致——**用 DSP 换紧缺的 slice** 是正确方向，要落实到具体算子 |
| 保持无反压 | 维持固定延迟 | 96bit 通路 `O_tready` 直通，绝不能引入不确定停顿 |

### L4 区域级分析层（从无到有）

推荐 **网格化投影**，输出统一特征接口（便于后续升级 CCL）：
```
每帧输出：区域数 + 每区域的 { 包围盒 x0,y0,x1,y1 / 面积 / 质心 cx,cy / 平均色相 }
```
质心除法**直接用 DSP**（有 31 个闲置），不必做"半数法"近似，精度更高、LUT 更省。

### L5 目标级识别层（从无到有）

| 能力 | 做法 |
|---|---|
| 分类 | 平均色相 + 填充率（面积/包围盒面积）+ 长宽比；先用规则判据，不急于上分类器 |
| 跟踪 | 质心一阶 IIR 平滑 + 最近邻关联 + 丢帧保持 N 帧 |
| 去抖 | 连续 3 帧命中才确认输出，避免单帧噪声产生"幽灵目标" |

### L6 呈现与交互层

| 项 | 更优替代 |
|---|---|
| **统一数值通道** | OSD 做一个通用"数值渲染区"，帧率/延迟/坐标/计数都通过同一接口写入——现在加一个指标不用改结构 |
| 自研 OSD | 已有掩膜+描边+半透明，优于官方整像素替换，**尽快切换** |
| 外部控制 | 以太网/串口（远程）+ 蜂鸣器/数码管（本地）双保险 |
| Logo | 位置参数化，便于缩到 96×32 应急 |

### 贯穿层

| 项 | 说明 |
|---|---|
| 补 `<SDC_FILE>` | STA 覆盖 21% → ~43% |
| **帧率/丢帧/错误计数器提前做** | 别等阶段 3——稳定性测试（评分第 4 条）就要用它，且是答辩唯一可信的量化证据 |
| 恢复上电自检 4 标志 | P1 时代已有，摄像头版未接；对"系统稳定性"评分点有直接帮助 |
| MultiSeed | 出正式片前跑 |

## 三、与 16 天排期的合并建议

| 阶段 | 加入的改进项 |
|---|---|
| 阶段 0（10/19–20） | 换自研 OSD + 补 SDC + **加帧率/丢帧计数器** + push |
| 阶段 1（10/21–22） | 卡通化时**顺手把 3×3 中值提到 L2**、加暗区增益限幅（一并治残雪） |
| 阶段 2（10/23–26） | 检测改用**网格化投影**；同步做**帧对齐**；质心除法用 DSP |
| 阶段 3（10/27–28） | 指标上屏（复用统一数值通道）+ IIR 跟踪与去抖 |
| 阶段 4（10/29–31） | 稳定性三项测试 + MultiSeed；有余力再上以太网或 MCU 硬核调参 |
| 明确不做 | 双摄、CNN/NPU、全中文 OSD 字库、1080p、Sauvola（除非提前完成） |

## 四、一句话总结

**你们的短板不在"做不出来"，而在两处结构性缺口**：L4/L5 两层整体缺失（导致扩展分拿不到），以及检测与显示之间缺一条帧对齐的链路（导致做出来也不好用）。前者的最优解是网格化投影，后者的最优解是 vsync 同步延迟链——**两者加起来不到 500 LUT，但决定了扩展分能不能拿到、演示能不能看**。
