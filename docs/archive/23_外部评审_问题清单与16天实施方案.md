## 三、最需要警惕的一点：Sobel 红线

赛题红线：**作品的图像处理算法不得与参考例程相同**。

- 官方 `lab_ex2` = 灰度化 → **Sobel**（\|Gx\|+\|Gy\|）→ 固定阈值 80 → 多数表决
- 你们 = 灰度化 → **梯度** → 自适应阈值 + 分段 FLOOR + 因果迟滞

**风险在哪**：梯度算子这一层与官方是同一类（甚至 mode 1「官方判决」还显式复用同一套前端）。评委追问"你们的算子是不是 Sobel"时，只答"阈值机制是我们自研的"是不够稳的——**算子相同 + 判决不同，属于灰色地带**。

**三条应对（按成本排序）**：

1. **口径统一 + 提前准备话术**（零成本，今天就做）
   把算法描述统一为"**均值梯度（非标准 Sobel 卷积核）**"，核心创新点表述为"**亮度自适应的分段地板阈值 + 因果双阈值迟滞**"。报告里画一张"官方 vs 我们"的差异表，把差异落在**判决体系**上，而不是声称算子不同（声称了容易被拆穿）。
2. **尽快上两种与 Sobel 完全无关的算法**（这是最有效的稀释）
   卡通化（颜色量化 + 边缘压黑）与颜色目标检测（HSV 判色 + 投影定位）**都不含梯度算子**。当作品里有 3 种算法、其中 2 种与梯度无关时，"算法雷同"的质疑自然消解。
3. **准备一页对比实验**（已有素材）
   "官方固定阈值对弱边缘漏检 352/352、我们漏检 0"——这是差异化最硬的证据，务必进报告和视频。

## 六、答辩口径与材料要点

**必须出现的数字**：实测帧率、端到端延迟 ms、LUT/Slice/ERAM/DSP、算法模式数、弱边缘漏检率对比、连续运行时长。

**三段必背话术**：
1. "与官方例程的差异？" → 均值梯度 + **亮度自适应分段地板 + 因果双阈值迟滞**；官方是固定阈值 80；弱边缘官方漏检 352/352，我们漏检 0。
2. "哪些是复用的？" → 加密 IP/PLL/DDR/官方 ISP 原样未改（`git log --follow` 可查，1 次提交）；**Logo 位图数据取自官方 ROM（主办方标识），叠加渲染逻辑自研**；OSD 已换自研版。
3. "残雪？" → 如实说：传感器暗场噪声经 AWB 增益放大，边缘检测使其显性化；已用中值前置 + 迟滞收紧缓解；**根因解法是 AE/AG 闭环，列为后续工作**（诚实比遮掩得分高）。

**视频 3 分钟脚本**沿用 `docs/13` §六，但把"卡通化"和"目标检测"两段提前——它们是视觉冲击力最强、也最能证明"算法不止一种"的素材。
