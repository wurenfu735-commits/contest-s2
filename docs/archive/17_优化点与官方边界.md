## 一、官方边界：三层分清楚再动手

先把"哪些能改"钉死，避免后面白干或者踩红线。

### L1 物理上不可改（加密 / 原语 / IP 生成）

| 文件 | 性质 | 为什么不能改 |
|---|---|---|
| `hdmi_1_4b_transmitter_core_wrapper.enc.v` | **加密 Verilog** | 综合器只能读、不能解；改一个字符整个文件失效 |
| `mipi_dphy_rx/` | 器件物理层原语 | 对应芯片内部专用硬核，改了综合不过 |
| `pll_hdmi.v` | TD IP 生成 | 由 IP 配置器产出，要改只能在 IP 界面改参数 |
| `ph1p35_ddr_wrapper` | TD IP 生成 | 同上 |
| `csi_unpacket` / `raw10_unpacket` / `awb` / `uics520_cfg` | 厂商 ISP 链路 | 摄像头寄存器时序与内部格式强耦合，改了出不来图 |

**处置：只用不改。** 这些不是"官方要求你不要改"，是"改了根本跑不起来"，反而不用纠结。

### L1.5 `isp_top.v` —— 唯一允许"动"的官方文件，但只许加例化

> **⚠️ 2026-10-18 更正**：上一版把 `isp_top` 也列进了 L1"物理不可改"，**这是错的**，与我们实际做法矛盾（我们改了它 3 次）。更正如下。

`isp_top.v` 是**明文 Verilog**，不是加密网表，也不是 IP 生成物，综合器能正常读改。它在本设计里扮演的是"ISP 链路的连接板"：`raw10_unpacket → demosaic → awb → data_96bit_to_128bit` 这条链的例化都写在这一个文件里。

**边界应该是：不许改官方模块内部逻辑，但可以在官方给定的插入点加自己的例化。** 依据是官方自己的 `lab_ex2`（边缘检测例程）就在**同一位置**例化了它的 `edge_detect_96`——插在 `awb` 与 `data_96bit_to_128bit` 之间。我们照这个位置插，位置、握手方式、数据宽度都一致。

**我们实际改了什么**（`git log` 可查，共 3 次提交）：

| 改动 | 性质 |
|---|---|
| 新增 `I_mode[1:0]` / `I_k[1:0]` 两个输入端口 | 纯端口透传，不改任何内部逻辑 |
| 例化 `edge_adaptive_96`，接在 `awb` 与 `data_96bit_to_128bit` 之间 | 官方同位置的插入点 |
| `tready` 从 `awb_O_tready = O_tready` 改为经过算法模块串起来 | 握手链路，必须改 |
| 加一级 mux：`I_mode==0` 取 awb 原数据，否则取算法输出 | 便于对比与排障 |
| `data_96bit_to_128bit` 的三个输入改接到 mux 输出 | 连线 |

**一句话口径（答辩就这么说）**：`isp_top` 里我们只做了"例化 + 连线"，没有任何一行被修改的官方算法逻辑；位置与握手方式对齐官方 `lab_ex2`。

> 真正的加密件只有 `hdmi_1_4b_transmitter_core_wrapper.enc.v` 和 `mipi_dphy_rx/*.enc.*`，这两个文件在全部 30 多个提交里**只出现过 1 次（初始提交），之后从未被改动**——这一点可以直接用 `git log --follow` 现场证明。

## 二、资源硬账：先看清缺什么

`syn.log` 实测（PH1P35MDG324，Speed 3）：

| 资源 | 已用 | 总量 | 占用率 | 判断 |
|---|---|---|---|---|
| **Slice** | 16,454（综合）/ **16,710（P&R）** | 21,216 | 77.55% / **78.76%** | ⚠️ **唯一瓶颈** |
| LUT | 20,156 | — | — | 其中 lut6 有 8,402 个 |
| Slice Reg | 14,454 | 42,432 | 34.06% | ✅ 富余 |
| **ERAM（20Kb/块）** | 63 | **108** | 58.33% | ✅ 还剩 **45 块** |
| **DSP** | 9 | **40** | 22.50% | ✅ **剩 31 个** |
| 分布式 RAM 占用 | `dram lut 296` + `shifter lut 112` | — | — | 可迁移项 |

### 三条推论（第二条最重要）

**推论 1：78.76% 已经贴着布线拥塞线。**
TD 官方建议资源不要超过 80%，超过后布线拥塞会导致时序反复不收敛。我们现在 Setup 只有 **+0.005 ns**——等于零余量。任何"再加一点逻辑"的改动都可能直接不收敛。这不是估算，是已经发生的事实（对比 v4 无 OSD 版还有 +0.376 ns）。

**推论 2：我们缺 LUT，DSP 反而闲着 31 个——所以开源社区那套"Sobel 用移位加法做到 0 DSP"的经验，对我们**是负优化**。**
`LewisLiuLiuLiu/logikbench` 的 `sobel3x3`、`nk12U/Sobel-Filter-FPGA` 都在强调"kernel folds to shifts/adds, 0 DSP"。这个优化在 DSP 紧张的小器件（Cyclone IV / Artix-35T）上是对的；在我们这儿 DSP 只用了 22.5%，把 `×2` 展开成 `a<<1` 会**多占 LUT 和进位链**，恰好打在唯一短缺的资源上。

> 这条反直觉，但账很清楚：DSP 剩 31 个 ≈ 免费；LUT 已经 77.55% ≈ 最贵。**能塞进 DSP 的就塞 DSP，别为了"零 DSP"好看去烧 LUT。**

**推论 3：45 块空 ERAM = 900 Kbit，足够吃下任何 ROM/行缓存。**
所以"要不要把常量表放 BRAM"这个问题，答案永远是"放得下，问题是能不能被推断出来"。

## 三、官方 OSD 那 2,753 LUT 到底花在哪

`docs/15` 记录的实测分层面积（`u_hdmi_mixer`）：

| 项 | 官方版 | 自研版 | 倍数 |
|---|---|---|---|
| LUT | 2,753 | 593 | 4.6× |
| ripple | 85 | — | — |
| 寄存器 | 229 | — | — |
| DSP | 1 | 0 | — |
| 全片 slice 增量 | **+2,533**（69.07% → 78.76%） | +477 | — |

### 成因一：位图 ROM 的数据位宽差了 12.5 倍（主因）

两份 ROM 的**条目数完全一样**，都是 6,388 条：

| | 官方 `anlogic_logo_rom.v` | 自研 `osd_logo_rom.v` |
|---|---|---|
| 条目数 | 6,388 | 6,388 |
| 每条位宽 | **25 bit**（24bit 彩色 + 1bit 透明） | **2 bit**（透明/深蓝/红） |
| 数据总量 | **159,700 bit** | **12,776 bit** |
| 读方式 | `always @(*)` 组合 | `always @(*)` 组合 |
| 映射结果 | LUT 拼的巨型优先级选择器 | 小 LUT 阵列 |

159,700 bit ÷ 64（一个 LUT6）= **约 2,500 个 LUT**，跟实测 2,753 基本对得上。**这就是全部成因。**

### 成因二：一条组合乘法

```verilog
// hdmi_mixer.v:619
S_logo_addr = S_logo_y * LOGO_W + S_logo_x;
```

`LOGO_W = 160` 是常量，但写成 `*` 后综合器会用 DSP 或组合乘法树实现，正好解释那 **1 DSP + 85 ripple**。自研版是手写成移位加法：

```verilog
// osd_overlay.v:457-458
wire [13:0] S_logo_y = (S_ly14 << 7) + (S_ly14 << 5);   // ly*128 + ly*32
wire [13:0] S_logo_addr = S_logo_y + S_lx14;            // ly*160 + lx
```

> 按推论 2，这条**在官方版里其实是"正确的"**——用 DSP 换 LUT 正是我们想要的方向。所以不必把它当缺陷看。

### 关键结论：这份 ROM 结构上就进不了 BRAM

`always @(*)` 是**异步读**。异步读在任何 FPGA 上都无法推断成块 RAM——BRAM/ERAM 只支持同步读（读数据必须打一拍）。

所以官方 ROM 那 159,700 bit **注定摊在 LUT 上**，不是"参数没调好"，是写法决定的。想让它进 ERAM，只能改文件（违反 L2）——因此唯一合规的出路是**整条换掉**。

## 四、优化项（按性价比排序）

### O1 ★★★★★ 脱离官方 OSD 通路，一次性回收 ≈2,000 LUT

> **⚠️⚠️ 2026-10-19 重大更正：原来写的"定义 `OSD_SELF_DEV` 就能回收 2,533 slice" 现在是错的，照做会翻车。**
>
> **原因**：`hdmi_mixer.v` 在 B4 被换成了官方 909 行带 OSD 版（`git log` 只有两条：
> 初始 182 行**无 Logo** → B4 909 行**官方 OSD**）。而 `design_top_wrapper.v` 里的
> `` `ifdef OSD_SELF_DEV `` 只在**第 901 行**，`u_hdmi_mixer` 是在**第 875 行无条件例化**的。
>
> 所以现在的语义变成了：
>
> | 编译选项 | 实际结果 | 资源 |
> |---|---|---|
> | 不定义（现行） | 官方 Logo 自带叠加 | 16,616（78.32%）✅ 正确 |
> | **定义 `OSD_SELF_DEV`** | **官方 Logo + 自研 OSD 同时叠加（双 Logo）** | **≈17,093（80.6%）❌ 反而更贵** |
>
> 也就是说这个开关**从"二选一"退化成了"只能加不能换"**。B4 之前 `hdmi_mixer` 是 182 行无 OSD 版，
> 那时"定义 = 用自研 OSD / 不定义 = 没 OSD"是成立的；B4 之后语义就变了，**但文档没跟着改**。

#### ★ 实测：Logo 位图到底占多少（2026-10-19 跑出来的，不是估算）

**实验方法**：把 `anlogic_logo_rom.v` 临时替换成 `O_pixel = 25'd0`（端口类型不变），完整跑 syn+phy，
再逐字节还原（还原后 `sha256 09b288fa…`、`git hash-object 5d99c37a…`、6400 行、`git diff` 为空，四项都核过）。
构建日志：`sim/build_syn.log` / `sim/build_phy.log`。

| 指标 | v5 基线（有 Logo） | Logo 桩（无位图） | **差值** |
|---|---|---|---|
| `#lut6`（P&R） | 14,534 | **11,757** | **−2,777** |
| **`#slice`（P&R）** | **16,616（78.32%）** | **14,291（67.36%）** | **−2,325** |
| `#eram` | 60 | 60 | 0 |
| `#dsp` | 9 | 8 | **−1** |
| SWNS（Setup） | +0.101 ns | **+0.655 ns** | **+0.554 ns** |
| HWNS（Hold） | +0.020 ns | +0.021 ns | — |
| `u_hdmi_mixer` 分层 LUT | 2,551 | **211** | −2,340 |

**三条硬结论：**
1. **一块 Logo 位图 = 2,325 slice = 全片的 10.96%**，还白吃 1 个 DSP，并把 Setup 余量从 0.655 ns 压到 0.101 ns。
2. 官方 `hdmi_mixer` 的 2,551 LUT 里，**2,340 是位图，只有 211 是文字/面板/mux 逻辑** —— 也就是说
   `hdmi_mixer` 这个"模块"几乎就等于"那块 ROM"。
3. 位图是 **160×160、只存 6,387 个不透明像素**（填充率 24.9%），格式 `{1'b1, R[7:0], G[7:0], B[7:0]}`，
   共 **159,675 bit，纯组合 `case`，0 ERAM**。理论下限 159,675 ÷ 64（LUT6）= 2,495，实测 2,340 —— 对上了。

#### 优化方向：把 25 bit/px 降到调色板索引（不是删 Logo）

官方 2.3(4) 明确要求**必须包含"安路"标识 Logo**，所以 Logo 不能删。
但这张图只有 **579 种颜色，且前 2 色（安路深蓝 `#1C2D4E` 3,003 px + 安路红 `#ED1C24` 785 px）就占 59.3%**
—— 剩下的都是抗锯齿过渡色，完全可以量化。

按 k-means 量化实测（对比图见 `src/p1_colorbar/tools/logo_palette_cmp.png`，从左到右：原图 / 16 色 / 8 色 / 4 色）：

| 编码 | 色数 | 平均每通道误差 | 视觉 | ROM 数据量 | 估算 LUT |
|---|---|---|---|---|---|
| 25 bit（现行） | 579 | 0 | — | 159,675 bit | **2,340**（实测） |
| **4 bit** | **16** | **1.43/255 = 0.56%** | **肉眼无法区分** | 25,548 bit | **≈400** |
| 3 bit | 8 | 2.42/255 = 0.95% | 几乎无差别 | 19,161 bit | ≈300 |
| 2 bit | 4 | 5.76/255 = 2.26% | 内边缘略生硬 | 12,774 bit | ≈200 |

→ **选 4 bit / 16 色**：省掉 ≈1,940 LUT，而画质损失低于 JPEG 压缩的一个量化档。
2 bit 只再省 200 LUT 但画质肉眼可辨，不划算。

#### 两条实现路线

| | 做法 | 合规 | 省多少 | 连带价值 |
|---|---|---|---|---|
| **A（已采用，已出位流）** | 写 `rtl/mixer_lite.v` + 复用 `rtl/osd_logo_rom.v`（2 色 + 透明，2bit/像素），**顶层不例化官方 `hdmi_mixer`**（文件保留不删） | ✅ L3 顶层连线，不动官方文件 | **实测 −2,069 slice（78.32% → 68.57%）** | **顺带拿到 OSD 控制权**——高阶(1) 模式名、高阶(2) 坐标、高阶(3) 延迟 ms 都要往屏上写，官方 mixer 的文字是写死的，本来就得自己接管 |
| B | 直接把 `anlogic_logo_rom.v` 的内容换成 16 色版（输出仍是 25 bit 格式） | ❌ 改了官方明文文件，破坏"L2 原样用"自律 | ≈同样多 | 无 |

**为什么 A 不是"额外成本"**：官方 `hdmi_mixer` 的 OSD 文字（"安路 CNT:" + 固定计数器）写死在 909 行里，
我们**无论如何**都要有自己的 OSD 才能在屏幕上显示当前算法名/坐标/延迟。所以 `mixer_lite` 是扩展功能的
**必需品**，省资源只是顺带的收益。

**这 2,426 slice 就是 `docs/18` 里 7 项扩展的本钱。不做这一步，一项都放不进去。**

- **合规口径**：不修改官方文件（`hdmi_mixer.v` 文件保留在工程里，只是顶层不再例化它）；
  位图**数据**沿用官方 `anlogic_logo_rom.v` 同一份素材，只做**主色归纳**（深蓝 `#1C2D4E` + 安路红 `#ED1C24` + 透明）

  6,387 支的纯组合多路选择树本身就是一条长关键路径；它消失后关键路径退回 DDR `usr_clk` 133M 域。



### O2 ☆ 自研 ROM 改同步读到 ERAM —— 别做

自研 ROM 只有 12,776 bit ≈ 200 个 LUT，改成同步读进 ERAM 最多省一百多个 LUT，但要给 `osd_overlay.v` 的整条流水线补一拍对齐，改动风险和收益完全不成比例。**明确不做。**

### O3 ★★★ 把 408 个"伪装成 LUT 的存储"迁到 ERAM

`syn.log` 里有两条容易忽略的：

```
| dff(single fanout)->dram  |  129 |
#used ram  408
  #dram lut   296
  #shifter lut 112
```

- `dram lut 296`：296 个 LUT 被当成分布式 RAM 用（小数组没推断成 ERAM）
- `shifter lut 112`：112 个 LUT 被当成移位寄存器用
- `dff(single fanout)->dram 129`：129 个单扇出触发器被工具改成了分布式 RAM

这些是**因为容量太小没被推断成 ERAM** 的存储。把它们合并成大一点的数组（或直接调 TD 的 BRAM IP）能释放几百个 LUT。收益中等，但改动局部、风险低。

### O4 ★★★ 邻域窗口：把 6 路灰度串成流式级联

我们当前 v4 是 **6 块灰度 + 1 块判决行缓存、窗口 10×7**，占 `u_edge_adaptive_96` 主要面积。

`LewisLiuLiuLiu/logikbench` 的 `sobel3x3` / `median3x3` / `conv2d` 三个滤波器用的是**完全相同的流式接口**（`in_valid` / `in_sof` / `in_pix` → `out_valid` / `out_sof` / `out_pix`，同尺寸零填充边框），所以可以**直接串成链**，一个滤波器的输出直接喂下一个，不重复过 DDR、不重复开窗。

对我们的意义：如果后面要加多个风格化滤镜（卡通化 = 高斯 + 阈值、浮雕 = 单向差分、素描 = 反色 + 高斯），不需要每个滤镜各开一套行缓存，**共用一套窗口生成器 + 级联的算子链**，面积近似只增算子本身。这条直接决定了 `docs/16` 路线 B 能不能塞得下。

### O5 ★★ 定点化与免除法

- 统一 **Q 格式定点**（`zmohammed5/fpga_image_processor` 用 Q8.8，`tharunreddy1801/...Dehazing` 用 Q0.16），避免任何 `real` 或宽位浮点。
- **除法一律不要**：用倒数查表（`tharunreddy1801` 的做法）或 CORDIC。硬件除法的面积和延迟都不可接受。
- 位宽逐级收敛：中间结果不要一律给 32 位，按动态范围逐级截位（这是省 LUT 最快的一招）。

### O6 ★★ 时序收敛手法

当前 Setup +0.005 ns，属于"随便动一下就掉"的状态。切到自研 OSD 后有 782 ps 余量，但加算法前仍要准备好这几手：

| 手法 | 用法 |
|---|---|
| `(* max_fanout = N *)` | 对高扇出控制信号（复位、使能、模式选择）触发寄存器复制 |
| 复位信号走 BUFG | 避免复位网络占用普通布线资源、拖慢扇出 |
| 用 `case` 替代深 `if/else` 链 | 展平优先级逻辑，减少级联 LUT 深度 |
| `(* keep *)` | 防止关键中间信号被优化掉（调试期用，出片前清掉） |
| 跑 `MultiSeed.tcl` | 正式出片前必跑，找一版时序更好的种子 |
| 分层综合 | 给 `u_edge_adaptive_96` 单独加约束，避免全局优化把它拆散 |

### O7 ★★★ 反向利用富余的 DSP

既然 DSP 剩 31 个（22.5%），可以把 LUT 重的运算主动搬到 DSP：

- 颜色空间转换（RGB→YCbCr）的 3×3 矩阵 → 3 个 DSP，替掉一堆加法器
- 高斯模糊的 `×16 / ×6 / ×1` 权重（本来要移位加法）→ 直接 DSP 乘
- 任何"系数固定但位宽宽"的乘加 → DSP

这是**用富余资源换短缺资源**，比省 DSP 划算得多。
