## 二、上板要准备什么

| 硬件 | 要点 |
|---|---|
| HX1P35A 开发板 | 主芯片 PH1P35MDG324 |
| **SC520 MIPI 摄像头** | 接板上 MIPI_CSI（42pin FPC）。⚠️ **不插摄像头 = 黑屏**：MIPI 恢复时钟是整条通路的心跳 |
| HDMI 显示器 + HDMI 线 | 1280×720@60 |
| Type-C 数据线 | ⚠️ 必须能传数据。**这一根线同时供电 + 当 JTAG**（板载 USB-JTAG） |
| 12V DC 电源 | 板上另有 12VDC 座；两种供电方式都行，别同时乱插 |

接线顺序（**全程断电操作**，官方板卡手册明确要求）：
1. 关电源开关 → 2. 插 HDMI → 3. 插摄像头 FPC（注意金手指方向）→ 4. 插 Type-C → 5. 上电

## 三、JTAG 驱动：第一次必做

> **先对一下型号**：赛题二用的是 **HX1P35A 板（PH1P35MDG324）**，板上自带 **USB-JTAG**（Type-C 一根线，同时供电）。
> 官方资料里 `1_安路工具和软件\新版TD驱动PH1P35使用方法\` 这个文件夹**就是配套你这块板子的**，不是别的赛题的。
> 不需要外置下载器；如果你手上有 AL-LINK / AL-LINK-FT 外置狗，同样是装 WinUSB，PID 也是 6042。

### 3.0 先判断：是"没装"还是"没插好"（30 秒）

> **懒人版（推荐先跑这个）**：插好 Type-C 后，直接双击 `tools\check_jtag.bat`。
> 它会按 **USB 层 → 驱动层 → 工具链层** 三层依次报结果，最后一行出现 `count: 1` 就是全通；
> 如果 `count: 0`，它会告诉你卡在哪一层。不用开设备管理器，也不用开 TD。

插好 Type-C、板上电，打开**设备管理器**（Win+X → 设备管理器），找 `通用串行总线控制器` / `其他设备`：

| 你看到的 | 含义 | 怎么办 |
|---|---|---|
| `USB Serial Converter A`，**带黄色感叹号** | 设备认到了，**驱动没装** | 走 **3.1** |
| `USB Serial Converter A` 正常，但属性→驱动程序→"驱动程序提供程序"写的是 **FTDI** | 装的是 FTDI 串口驱动，**TD 认不到** | 走 **3.1**（改成 WinUSB） |
| `USB Serial Converter A`，提供程序写的是 **WinUSB** | ✅ **已经装好了** | 直接跳到 3.2 验证，再进第五节烧写 |
| 什么都没有，插拔也无反应 | 线是充电线 / 没上电 / 口坏 | 换一根**能传数据**的线，换 USB 口，确认电源开关 |

> 本机因为是远程会话，**读不到你的 USB 设备列表**，这一步只能你自己看一眼。

**本机实测（2026-10-17 23:52，用系统自带命令读出来的，不是猜的）**

```bat
pnputil /enum-devices /instanceid "USB\VID_0403&PID_6042&MI_00\7&c92b2b2&0&0000"
```

输出里能直接读到：

| 字段 | 值 | 含义 |
|---|---|---|
| 设备描述 | `USB-JTAG Cable` | 安路定义的设备名 |
| 类名 / 类 GUID | `USBDevice` / `{88bae032-…}` | WinUSB 设备类 |
| 制造商名称 | **`WinUSB (Powered by UsbDriverTool)`** | ✅ 确认是 `UsbDriverTool` 装的 WinUSB |
| 驱动程序名称 | `oem213.inf` | 第三方驱动包，已入驱动库 |
| **状态** | **已断开连接** | ← 问题只在这里：**线没插** |

同一块板子的第二接口 `MI_01` = `USB-JTAG Cable (Libusb - WinUSB)`，类 `libusb (WinUSB) devices`，也是 `oem213.inf`；
父设备 `USB\VID_0403&PID_6042\123456789`，硬件 ID `VID_0403&PID_6042&REV_0700`（REV_0700 = **FT2232H**）。

**结论：驱动早就装好了，连 PID 都已经刷成 6042（说明 `FT_PROG` 那步也做过）。现在"认不到"是板子没连上，不是驱动问题 —— 不要再重装驱动。**

> ⚠️ **更正**：本文档 23:45 那一版在这里写的是"这台机器确实没装过 JTAG 驱动"，那是**只看 `DriverStore\FileRepository` 里有没有 `ftdibus.inf` 得出的错判**。安路走的是 WinUSB 通用驱动 + 自定义 inf（`oem213.inf`），本来就**不会**有 FTDI 驱动包，所以"没找到 FTDIBUS"这个现象是**正常的**，不能作为没装的证据。

### 3.4 装不上的三种情况

| 现象 | 原因 | 处理 |
|---|---|---|
| 列表里根本没有设备 | 线只能充电 / 板子没上电 | 换数据线；确认电源开关在 ON；换 USB 口（避开前置面板/扩展坞） |

| 装完 TD 仍认不到、BitWriter 报 `PRG-9511` | 设备被别的程序占用 / 装成了 FTDI 而非 WinUSB | 关掉另一个 TD / bw.exe / 串口助手；回 3.1 重装 WinUSB |

## 四、怎么生成位流（两条路，都实测过）

### 4.1 图形界面（日常用，最稳）

打开 `td_project\OUR_p1_colorbar.al`，左侧 Flow 面板从上往下依次跑到全绿：

```
Read Design → Optimize RTL → Optimize Gate → Optimize Placement → Optimize Routing → Generate Bitstream
```

改了 RTL 后**必须**跑到底（引脚位置是编进 bit 的）；TD 认为 run 已完成时会跳过重跑，先 `reset_runs` 或右键 Reset。

### 4.2 命令行（这次就是用这个跑出 bit 的）

TD 的 GUI 编译本质是执行 `doc\scripts\DefaultFlow.tcl`，它读**当前目录**的 `settings.cfg`。所以可以完全脱离 GUI：

```bash
cd td_project\OUR_p1_colorbar_Runs\syn_1
C:\anlogic\TD_6.2.1_Engineer_6.2.168.116\bin\td_commands_prompt.exe run_syn.tcl < /dev/null
cd ..\phy_1
...\td_commands_prompt.exe run_phy.tcl < /dev/null
```

`settings.cfg` 关键项（syn / phy 的差别只在 `start_step`/`end_step`/`parent`）：

```tcl
set device_name ph1_35p.db          # 必须先绑定芯片，否则 elaborate 直接断言
set package_name PH1P35MDG324
set speed 3
set prj_name {OUR_p1_colorbar}
set start_step read_design          # phy: opt_place
set end_step   opt_gate             # phy: bitgen
set parent     ../syn_1             # 只有 phy 有
```

三个实操要点（本次踩过）：
1. **`import_device` 必须最先执行**——这正是"断言报错"的根因（见第七节）。
2. 脚本末尾要 `exit`，否则 `td_commands_prompt` 跑完会停在交互提示符 `td >` 一直挂着。
3. run 目录里的 `.prj` 路径比 `.al` 深一级，**本次直接写成绝对路径**（64 条全部校验存在），彻底避免相对路径算错。

### 5.1 第一次：把下载器连上（只做一次）

点右上角 **`Debug Server: AL-LINK-FT (Local Host)`** → 弹出 `Debug Server Setting`：

### 5.2 每次烧写：四步

| 步 | 点哪里 | 做什么 |
|---|---|---|
| ① | 顶部 **`Refresh`** | 左边应出现 **`0:PH1P35MDG324`**。出现即说明链路通；没有就先回 5.1 |
| ② | 左列 **`Add`**（橙色加号） | 选 `.bit` 文件（可粘贴绝对路径） |
| ③ | 表格 **`Mode`** 下拉 | 选 **`PROGRAM_SRAM`**，Speed 保持 5MHz |
| ④ | 左列 **`Run`**（绿色三角） | 开始烧写；进度走完屏幕应出画面 |

烧写时 `Stop` 可中止。日志区会依次打印擦除 / 编程 / 校验，最后 `Program success` 之类字样。

### 5.3 模式对照

| 模式 | 用途 | 掉电 |
|---|---|---|
| **PROGRAM_SRAM** | 下到配置 RAM。**调试阶段就选这个**，一次十几秒 | ❌ 丢失，每次上电重烧 |
| **PROGRAM_FLASH** | 烧到板载 SPI Flash（N25Q128）固化 | ✅ 保存，上电自启动 |
| Verify SRAM / Verify Flash | 回读校验 | — |
| Erase Flash | 整片擦除 | — |
| 左列 `Create Flash File` | 把 `.bit` 转成 Flash 镜像（固化用） | — |
| 左列 `Encrypt` / `Merge Dualboot Bit` | 加密 / 双启动合并，本项目用不到 | — |

> 线下答辩/演示前用 **PROGRAM_FLASH** 固化一次，现场只带板 + 摄像头 + 电源 + HDMI，上电即出画面，不依赖电脑。

## 七、"现在这个报错"是什么意思

你如果看到的是下面某一条，对照看：

### 7.1 `Assertion failed: GlobalDesign.chip() != nullptr (macrolib.cpp:1283)`

**含义**：TD 的 TCL 引擎在执行 `elaborate`（展开设计）时，发现这个设计**还没绑定任何芯片**，于是内部断言失败退出。

**不是代码问题**——我拿一个 4 位计数器都能复现。

**根因**：命令行直接 `open_project` + `elaborate` 时，没有先 `import_device ph1_35p.db -package PH1P35MDG324`。工程里虽然写了 `<Device>PH1P35MDG324</Device>`，但那是"工程属性"，不触发芯片库加载。

**解决**：走 `DefaultFlow.tcl + settings.cfg`（第四节那条路），它在第一步就 `import_device`，之后 `elaborate` 1.7 秒正常完成。GUI 里点按钮不受影响，所以"用 TD 图形界面跑"永远是对的。

### 7.2 `HDL-8007 ERROR: xxx is a black box`

**含义**：代码里 `例化` 了这个模块，但**找不到它的定义**（黑盒）。综合会因此报错停下。

**本次真实遇到两次，原因都不是 RTL 写错**：
1. `osd_overlay` / `edge_adaptive_96` 黑盒 → run 目录里的 `.prj` 相对路径少了一级（`.al` 里写 `../user_source`，run 目录要 `../../../user_source`；而 `../../../rtl/...` 要再深一级）。改成绝对路径后消失。
2. `divider` 黑盒 → `divider.ipc` 丢了（见第九节），恢复后消失。

**排查口诀**：报黑盒 → 先确认这个 `.v` 在不在工程文件列表里 → 再确认列表里的**路径能不能真的打开**（TD 不会替你报"文件不存在"，只报黑盒）。

### 7.3 `HDL-5007 WARNING: literal value ... truncated to fit in N bits`

**含义**：字面量位宽不够，**高位被静默截断**。这正是本次 OSD 字模那个真 bug：`9'hXXX` 装不下 `'A'=0x41`，字符码被砍掉，仿真因为黄金模型同样截断而"看起来是对的"。已修（键加宽到 `10'h`）。

**教训**：这类 WARNING 必须当 ERROR 看，尤其涉及 `case` 键、常量索引。

### 7.4 下载阶段的报错（还没到这一步的话先记着）

| 报错 | 含义 | 处理 |
|---|---|---|
| `PRG-9511` 打开下载器失败 | 下载器没连上 / 被别的程序占用 | 换 USB 口、关掉另一个开着 BitWriter 的窗口 |
| BitWriter 报 `PRG-9505 : USB device open error` | 进程权限不够（安路的 WinUSB 接口默认只放行管理员），或驱动被别的程序占用 | **右键 `bw.exe` → 以管理员身份运行**；先把其他 TD / bw / 串口助手关干净 （2026-10-18 实测：非管理员命令行必报此错） |
| `PRG-9505` 打开 USB 失败 | 驱动不对 | 按第三节装 WinUSB |
| `PRG-9000` 没有读到正确的器件 ID | 器件不支持或下载器接错 | 确认 `Device` 是 PH1P35MDG324、线序正确 |
| `PRG-9513` Flash 一直 busy | Flash 状态位不对 | 重新上电再试 |
| `PRG-9520` 其他功能正在使用下载器 | 两个进程抢下载器 | 别同时开两个 TD / bw.exe |
| `Bitgen is prohibited`（编译期） | 有顶层端口没配 LOCATION | 查 `constraints_source\pin.adc` |

### 7.5 `HDL-5317 / HDL-5323 WARNING: port ... not connected`

只是"某端口没接"，**不是错误**，可以上板。本次综合共 110 条 WARNING，全部属于这类历史遗留（`demosaic`、`divider_gate.v` 门级网表里未使用的 DSP 端口等），OSD 两个新文件**自身 0 条**。

### 8.3 时序（`route.qor`）

| 指标 | 官方 OSD 版 | 自研 OSD 版 | 判定 |
|---|---|---|---|
| Setup WNS | **+0.005 ns**（TNS 0，0 违规） | +0.787 ns（0 违规） | ✅ 都满足，但官方版仅剩 5 ps |
| Hold WNS | **+0.020 ns**（TNS 0，0 违规） | +0.020 ns（0 违规） | ⚠️ 刚好过 |

**官方版 5 ps 的成因已经定位清楚**：`hdmi_mixer.v:619` 用 `S_logo_y * LOGO_W`（DSP 乘法器）**组合地**算 ROM 地址，再直接进输出 mux，像素域 13.33 ns 预算里实际走 15.7 ns（16 级逻辑 + 424 扇出）。

- 综合阶段这条路径是 **-2.475 ns（24 条违例）**，靠布局布线拉到 +0.005；
- **官方 lab_ex3 自己也是这个套路**：综合 -1.296 ns → 布完 +0.103 ns。所以"综合负、布线正"在这块设计上是正常现象，不要被综合报告的负值吓到；
- 想拿回余量：把那一行换成移位 `({3'b0,S_logo_y}<<7) + ({3'b0,S_logo_y}<<5) + S_logo_x`，可去掉 DSPMULT 与两级 ADDER，行为不变（自研版就是这么做的，+0.787 ns）。

Hold 20 ps 是**官方通路本征值**（DDR `usr_clk` 133M 域），三个版本一模一样，与 OSD 无关。正式出片前建议 GUI 里跑一次 `MultiSeed.tcl`，或留着 `drHoldFix` 别关。
