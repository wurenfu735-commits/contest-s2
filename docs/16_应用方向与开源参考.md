# 16 · 应用方向与开源参考（2026-10-18）

> 触发问题：**"基础部分跑通了，但不知道这套系统该拿来做什么、怎么应用。"**
> 本文做三件事：① 盘清我们的硬约束 ② 列出真正能借鉴的开源工程 ③ 给出三条可落地的应用路线并排序。
> 前置阅读：`06_情报与呈现方案.md`（功能清单与评分规律）、`05_开源调研.md`（P1 阶段调研）。

## 一、先说约束：资源已经很紧了

这不是"想做什么就能做什么"的阶段。布局布线后的实测数据：

| 项 | 官方 OSD 版（现行） | 自研 OSD 版（备选） |
|---|---|---|
| Slice 占用 | 16,710（**78.76%**） | 14,654（69.07%） |
| LUT | 2,753（含官方 mixer+ROM） | 593 |
| DSP | 1（mixer 里 `S_logo_y * LOGO_W`） | 0 |
| Setup Slack | +0.005 ns | +0.787 ns |

**结论**：官方 OSD 一口气吃掉约 2,100 slice 和几乎全部时序余量。

- 想再加算法，**第一件事是把 OSD 换回自研版**（省 ~2,000 slice、时序余量从 5 ps 回到 787 ps）
- 否则每加一个 3×3 窗口模块（约 300–600 LUT）都要重新谈时序
- 720p60 @ 74.25 MHz、每拍 4 像素（96 bit）——**吞吐不是瓶颈，面积和时序才是**

> 一句话：**接下来拼的不是"能加多少算法"，而是"每 slice 出多少视觉效果"。**

| [delhatch/Red_Tracker](https://github.com/delhatch/Red_Tracker) | 纯 Verilog 红色物体检测 + 最大连通块质心 + 十字准星叠加，DE2-115 | **最大色块质心**的求法（行/列投影 + 峰值）、准星叠加时序 | 颜色目标检测（扩展②）的标准实现，`06` 里已列为借鉴对象 |

### 2.2 有参考价值但不必陷进去的

| 项目 | 判断 |
|---|---|
| [nk12U/Sobel-Filter-FPGA](https://github.com/nk12U/Sobel-Filter-FPGA)、[SanjayKrishna2005/SobelEdgeDetector](https://github.com/SanjayKrishna2005/SobelEdgeDetector) | 经典 3×3 流水线 + line buffer，**我们已经有更好的自适应阈值**，只用于对照"别人怎么切流水线" |
| [YenLaurent/image-process-on-fpga](https://github.com/YenLaurent/ImageProcessBasedOnFPGA) | 中科大项目：灰度→中值→Sobel→UDP 只传 **1 bit 二值图**，带宽降到 1/24。**思路可借**（"边缘图本身就是压缩"），但我们没有以太网出口，只能写进答辩展望 |
| [ykpgrr/Lane-Detection-with-Implementation-on-FPGA](https://github.com/ykpgrr/Lane-Detection-with-Implementation-on-FPGA) | 车道线检测，但主体在 ARM 上跑 C++/OpenCV，FPGA 只做预处理 —— **我们没有 CPU**，整条算法都得用 RTL 写，参考价值有限 |
| [EtienneIMT/Gesture_FPGA](https://github.com/EtienneIMT/Gesture_FPGA) | CNN + hls4ml 路线，Zynq 平台。**我们无 PS、无 HLS、无 NPU**，不适用；但"QAT 量化到 6bit"可作为答辩时的技术视野 |

### 2.3 红线提醒

以上全部**只借鉴架构思路与工程技巧**，落地代码必须按我们自己的 96 bit / 4 像素接口、自己的时序约束重写。
`05` 里定的铁律不变：算法核心判决逻辑自研，不复制任何仓库的 RTL 源码。

## 三、三条应用路线（按"性价比"排序）

### 路线 A：视觉交互（推荐 ★★★）

**不是做滤镜，而是做"能被看见的闭环"**：摄像头看到 → 算法判决 → 画面/外设响应。

| 阶段 | 做什么 | 成本 | 效果 |
|---|---|---|---|
| A1 | 颜色块检测 + 十字准星跟随（`Red_Tracker` 思路） | 低：行/列投影即可，无需连通域标记 | 拿个红球晃，准星咬住 —— 一眼就懂 |
| A2 | 运动方向判决（`x-hao-v` 思路） | 中：帧间质心差分 + 状态机 | 上下左右挥动 → 驱动 OSD 菜单光标 |
| A3 | **OSD 菜单被手势控制**（L 型闭环） | 中高：复用已有 OSD + 光标状态机 | 不用按键，隔空翻页 —— 答辩现场最有记忆点 |

**为什么推荐**：① 复用现有 OSD 框架，不额外吃资源 ② 演示效果强于任何滤镜 ③ 与"实时"主题天然契合（延迟可量化）。

### 路线 B：风格化滤镜组（稳妥 ★★☆）

对标 `06` 的扩展①和冲刺档 9。一个"可插拔"框架 + N 个算法模块：

```
灰阶 → 中值(3×3) → [边缘/阈值] ─┐
                              ├→ 融合 → HDMI
      → [颜色量化/双边] ────────┘
```

| 滤镜 | 实现要点 | 资源估算 |
|---|---|---|
| 卡通化 | 边缘掩膜 AND 量化色块（`cartoonize_rcd` 范式） | 中（中值 3×3 ≈ 400 LUT） |
| 浮雕 | 对角差分 + 128 偏移 | 极低（复用 3×3 窗口） |
| 马赛克 | 块内取左上像素（坐标右移截断） | 极低（纯组合） |
| 反色 / 阈值 | 逐位取反 / 比较 | 可忽略 |
| 热力图 | 灰度→伪彩 LUT（`gray_to_color`） | 低（一块 ROM） |
| 素描 | 灰度反相 + 高斯模糊 + 颜色减淡混合 | 中（要两路模糊） |

**注意**：多个滤镜**共用同一个 3×3 窗口生成器**，靠模式选择切换后级 —— 这是"堆数量不爆面积"的关键。

### 路线 C：检测与测量（有深度但慢 ★☆☆）

- 缺陷/异物检测（边缘 + 形态学开闭运算 + 面积阈值）
- 尺寸测量（边缘对间距 → 像素→毫米标定）
- 帧差运动检测（框出变化区域，最简单，可作为 C 的入门）

优点是有"工业感"、能报数值；缺点是需要标定和稳定光照，现场演示容易翻车。

## 四、建议的组合

```
必做：A1（颜色检测+准星） → B 的卡通化 + 2~3 个低成本滤镜 → 多模式按键切换
选做：A2/A3（手势控制 OSD 菜单）—— 这是拉开差距的一项
收尾：性能可视化（资源/帧率/延迟上屏），把数字做进画面
```

对应 `06` 的档位：**保底 4 项已全绿**（B1–B4），扩展做 A1 与卡通化两项，冲刺挑 2 个滤镜 + 延时可视化。

**先做的技术准备**：把 OSD 切回自研版（`OSD_SELF_DEV`），腾出 ~2,000 slice —— 否则后面每加一个模块都在赌时序。
