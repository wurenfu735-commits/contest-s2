# 10 · 协作规范

> 仓库：<https://github.com/wurenfu735-commits/contest-s2>（**私有**）
> 本文讲"多人/多机怎么改同一个工程而不打架"。怎么干工程见 [`07_执行路线图.md`](./07_执行路线图.md)。

## 一、核心约定：改完即拉

这个工程**同时有多台机器、多个 AI 会话在改**。Git 不会自动同步——**你不拉，别人就看不到你的改动；别人不推，你也看不到他的**。

所以只有一条铁律：

> **动手改之前先拉，改完立刻推。**

```bash
git pull --rebase        # 动手前
# ...改代码、写文档...
git add -A
git commit -m "说明"
git push                 # 改完立刻
```

`--rebase` 而不是默认 merge：让历史保持一条直线，评审时看得清。

## 二、Windows 上的两个坑（本机已踩过）

### 坑 1：git 推送报 TLS 错误

症状：

```
schannel: next InitializeSecurityContext failed:
CRYPT_E_NO_REVOCATION_CHECK (0x80092012)
```

原因：本机网络无法完成 TLS **吊销列表**检查（不是证书无效）。**本地已修好**，但要注意用哪套 git：

```powershell
# ✅ 用这套（本机已验证可用）
& "E:\app\Software\ai agent\git\Git\cmd\git.exe" -C "E:\fpga\contest_s2" push origin main

# ❌ 不要用 ops_bash / dsh-ops 自带的 git（会撞上面那个 TLS 报错）
```

### 坑 2：行尾（CRLF / LF）

`.gitattributes` 已统一：**仓库内一律 LF**，`.bat`/`.ps1` 用 CRLF，位流与图片按二进制处理。

不要改这两条设置，否则会出现"整个文件每一行都变了"的假 diff：

```bash
git config core.autocrlf false        # 保持默认即可
git config core.safecrlf warn
```

## 三、一键同步脚本（本机）

不想记命令的话，本机有脚本，**拉取 → 自动提交 → 推送 → 复核** 四步一次做完，最后会核对远端真实 commit 而不是只看命令退出码：

```powershell
# 只看看现在什么状态（不动仓库）
powershell -NoProfile -ExecutionPolicy Bypass -File "E:\fpga\tools\sync-contest_s2.ps1" -StatusOnly

# 自动提交并同步（提交信息自动带时间戳）
powershell -NoProfile -ExecutionPolicy Bypass -File "E:\fpga\tools\sync-contest_s2.ps1"

# 用自己写的提交信息
powershell -NoProfile -ExecutionPolicy Bypass -File "E:\fpga\tools\sync-contest_s2.ps1" "修好 HDMI 时序"

# 只同步已有提交，不自动提交工作区
powershell -NoProfile -ExecutionPolicy Bypass -File "E:\fpga\tools\sync-contest_s2.ps1" -NoCommit
```

也可以直接双击 `E:\fpga\tools\sync-contest_s2.cmd`。

日志在 `E:\fpga\dsh-ops-migration\git-sync.log`（只在本机，不入库）。

> **注意**：该脚本是**本机专用**，不在仓库里（依赖本机 git 路径与 TLS 配置）。别的机器请按第一、二节手工操作。

## 四、什么进仓库、什么不进

| 进 | 不进 |
|---|---|
| RTL 源码 `.v` / `.sv` / `.vhd` | 仿真波形 `*.wlf`（单个可达 **26 GB**）、`wlft*` |
| 约束 `.f` / `.tdf` / `.sdc` | 综合产物 `db/` `*_Runs/` `output_files/` `*.qdb/qpg/qtl/qor/timing` |
| 测试平台 `tb/` | **位流 `*.bit`**（走 Releases 附件，见下） |
| 文档 `.md` | 第三方参考资料副本（`assets/ref_docs/guoyi_repo*`） |
| 脚本 `.py` / `.tcl` / `.do` | 日志 `*.log` `*.logw` |

`.gitignore` 已经配好。**不要为了让某个产物进仓库而删规则**——本工程工作区约 27 GB，但入库只需约 40 MB；放开一条规则就可能让 push 直接失败。

### 位流怎么给队友

位流是"发布产物"，用 GitHub Releases：

```bash
git tag v0.2-p2-edge            # 打标签
git push origin v0.2-p2-edge    # 推标签
```

然后在仓库网页 Releases 页面新建 Release、上传 `.bit` 作为附件。队友在 Release 页直接下载烧写。

已发布：**v0.1-p1-colorbar**（P1 colorbar 通路 + 按键消抖修复）

## 五、提交信息怎么写

方便靠 `git log` 看出进度，建议：

```
<阶段> <做了什么>

P2 自适应阈值边缘检测：完成行缓冲与阈值计算
- 新增 rtl/edge_adaptive.v（Sobel 近似，移位代替除法）
- sim/golden/edge_adaptive.py 输出与 RTL 逐像素比对一致
- 资源：LUT6 +312（占余量 3.7%），时序仍 0 违规
```

**进度写进 `memory/PROGRESS.md`**，按阶段追加实测数据（注明日期）。这样任何人——包括不看代码的队友——都能一眼看出"做到哪、下一步、卡在哪"。

## 六、答辩相关（重要）

赛题规则：**官方例程的算法禁止照抄，必须自研**。

因此提交时请留意：

- 引用/借鉴了外部开源，在 `docs/05_开源调研.md` 里记清楚**来源链接 + 差异在哪**（答辩要讲这个）
- 不要把第三方作品整包提交进仓库（既有许可问题，也说不清原创性）
- 自己的算法改动，提交信息里写清"与参考例程的实现差异"
