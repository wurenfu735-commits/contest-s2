# P2 算法规格 · 自适应阈值边缘检测 + 双阈值迟滞

> 这份规格是**黄金模型、RTL、仿真、比对**四者的共同基准。改动前先改这份文档。

## 0. 与官方算法对比（红线合规说明）

| 环节 | 官方 lab_ex2（`edge_detect_96.v`） | 我们 | 是否构成"不同算法" |
|---|---|---|---|
| 灰度化 | `R/4 + G/2 + B/4`（移位近似） | 相同 | 灰度是通用前处理，不算核心 |
| 降采样 | 每 4 像素合 2 对（**水平减半**，仅 640 样本） | **不做降采样，全分辨率 1280** | ✅ 不同 |
| 梯度 | Sobel `\|Gx\|+\|Gy\|` | 相同（3×3 Sobel 是教科书标准） | 梯度算子相同，但… |
| **阈值判决** | **固定阈值 80**（全图一个值） | **自适应阈值**（随局部亮度动态计算） | ✅ **核心差异** |
| **后处理** | 无 | **双阈值迟滞**（弱边缘需与强边缘连通才保留） | ✅ **核心差异** |
| 输出 | 二值（边缘白/非边缘黑） | 相同格式（便于与官方对比截图） | — |

**结论**：判决逻辑（阈值机制 + 后处理）与分辨率处理均与官方不同 → 满足"算法不得与参考例程相同"。

## 1. 算法定义（流式、因果，可被 RTL 实现）

> 关键设计原则：**算法必须"因果流式"**——每个输出像素只依赖"当前像素 + 已流过的邻域"，不能依赖未来像素。这样黄金模型与 RTL 才能**逐像素完全一致**。

### 1.1 灰度化（与 RTL 位运算逐位一致）
```
gray = (R >> 2) + (G >> 1) + (B >> 2)      // 范围 0..253，无溢出
```
（R/G/B 各 8bit；该近似与官方相同，硬件成本为零）

### 1.2 3×3 Sobel 梯度
窗口（3 行 × 3 列，取自 lx 邻域）：
```
p00 p01 p02
p10 p11 p12
p20 p21 p22
```
```
Gx = -p00 + p02 - 2*p10 + 2*p12 - p20 + p22
Gy =  p00 + 2*p01 + p02 - p20 - 2*p21 - p22
mag = |Gx| + |Gy|        // 范围 0..2040 → 11 bit（取 13 bit 留余量，与官方一致）
```

### 1.3 自适应阈值（核心差异点 1）
用 3×3 邻域均值近似"局部亮度"：
```
sum9 = p00+p01+p02 + p10+p11+p12 + p20+p21+p22     // ≤ 9*253 = 2277 → 12 bit
mean9 = sum9 >> 3                                   // 除以 8 近似（省除法器）
thr   = THR_FLOOR + ((mean9 * K) >> 5)              // K = 灵敏度系数（可按键调）
```
语义：**画面越亮，阈值越高**（亮区噪声大，需抑制）；**画面越暗，阈值越低**（暗区梯度小，避免漏检）。

| 参数 | 范围 | 默认 | 作用 |
|---|---|---|---|
| THR_FLOOR | 4 档：8 / 16 / 24 / 32 | 16 | 阈值下限，防止暗区过度敏感 |
| K | 4 档：0 / 1 / 2 / 3 | 2 | 亮度对阈值的贡献强度（K=0 退化为近固定阈值） |

### 1.4 双阈值迟滞（核心差异点 2）
```
thr_high = thr
thr_low  = thr >> 1                                  // 默认高:低 = 2:1

if      mag >= thr_high : out = 白（强边缘）
elif    mag >= thr_low  : 若左邻或上邻或左上邻已被判为边缘 → out = 白，否则 out = 黑   // 弱边缘靠连通性
else                    : out = 黑
```
**因果实现**：弱边缘只看**已经处理过的 3 个邻居**（左、上、左上）——这正是流式扫描的自然顺序，硬件零额外成本（只需记住上一行的判决位）。

效果：**孤立噪点消失**（噪点四周无强边缘支撑），**细边缘更连贯**（弱边缘被强边缘"带出来"）。

### 1.5 输出
```
边缘 → 24'hFFFFFF（白）；非边缘 → 24'h000000（黑）
```
与官方输出格式一致，便于做"官方 vs 我们"的对比截图（答辩素材）。

## 2. 位宽与资源预算

| 项 | 位宽 | 说明 |
|---|---|---|
| 灰度 | 8 | 0..253 |
| 行缓存 | **3 行 × 1280 × 8bit = 30.7 Kbit** | 全分辨率；官方是 2 行 × 640 × 16bit（降采样） |
| 梯度 mag | 13（有效 11） | ≤ 2040 |
| 局部和 sum9 | 12 | ≤ 2277 |
| 阈值 thr | 12 | |
| 判决位 | 1 × 1280（上一行） | 迟滞用 |

**资源占用预估**：ERAM 约 +3~4 块（我们余量 103 块）；LUT 增量预计 < 800（官方整个 edge_detect 含降采样逻辑用了 ~2500 LUT，我们不含 ISP）。

## 3. 时序与延迟

| 项 | 值 | 说明 |
|---|---|---|
| 流水线级数 | 约 5 级 | 行缓存写入 1 + 窗口成形 1 + Sobel 1~2 + 阈值/迟滞 1 |
| 单像素延迟 | 5 / 74.25MHz ≈ **67 ns** | 可忽略 |
| 帧延迟 | 2 行 ≈ 2×1650/74.25M ≈ **44 µs** | 远小于 16.7ms 帧周期 ✓ |
| 关键路径 | 需保持 ≥74.25MHz | 乘法用移位实现（无 DSP），时序无压力 |

## 4. 接口（与官方 ISP 链一致，即插即用）

```
module edge_adaptive_96 #(
    parameter IMG_WIDTH  = 1280,
    parameter IMG_HEIGHT = 720,
    parameter THR_FLOOR  = 11'd16,
    parameter K_SHIFT    = 2'd5        // 灵敏度（可运行时改）
)(
    input               I_clk, I_rst_n,
    input               I_tlast, I_tuser,
    input      [95:0]   I_tdata,       // 4 像素 RGB888（与官方同格式）
    input               I_tvalid, I_tready,
    output reg          O_tlast, O_tuser,
    output reg [95:0]   O_tdata,
    output reg          O_tvalid,
    output              O_tready       // 直通 I_tready（同官方，无反压）
);
```
**插入位置**：`isp_top.v` 中 `awb` 与 `data_96bit_to_128bit` 之间（接官方留好的算法插槽）。

## 6. 边界处理（与官方一致）

- 有效区前 2 行、每行第 1 个像素：无完整 3×3 窗口 → 输出黑（官方用 `window_valid` 同样处理）
- 行首/行尾由行缓存按行独立处理（写指针在 tuser/行末复位）
- 复位时**不清行缓存**（清空会把 BRAM 退化成寄存器，官方踩过这个坑并留了注释）
