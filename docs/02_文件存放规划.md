> 原则：**官方资料只读不动；我们的产物独立分层；每阶段打快照可回溯。**

## 二、每目录放什么

| 目录          | 放什么                            | 示例                                                       |
| ----------- | ------------------------------ | -------------------------------------------------------- |
| `docs\`     | 解读、路线图、需求指标、模块设计、技术笔记、每阶段"注意点" | `01_赛题解读与4周冲刺路线图.md`、`02_文件存放规划.md`                      |

| `memory\`   | 错误记录、关键决策、已踩坑清单                | `MEMORY.md`、`PROGRESS.md`                                |

## 三、最终提交物放哪（delivery\）

对应官方提交要求，建议结构化：

```
delivery\
├── 01_设计报告\           (含系统架构、算法说明、资源与时序数据、测试报告)
├── 02_源码工程\           (TD 6.2.1 工程 .al + 全部 RTL + 约束 + 编译说明)
├── 03_演示视频\           (上板实拍，展示基础功能+扩展功能)
├── 04_答辩PPT\            (含创新点、量化指标)
├── 05_复现说明\           (别人照做能跑起来的步骤)
└── 06_补充材料\           (引脚表、采购信息、自检报告等)
```

## 四、命名规范（快照）

- 每阶段结束，工程打一个快照点（zip），便于回退：
  - `v{阶段}_{日期}_{简述}`，例：`vP3_20261115_adaptive_edge`
- 源码工程子目录名用阶段前缀，例：`p0_baseline`、`p2_algo_sim`。

## 五、迁移说明

- **不迁移**既有产物（`E:\workbuddy\fpga\` 文档、`E:\fpga\anlu_project\` 工程、资料包内 `.workbuddy\memory\`），它们作为**历史快照**保留原位，避免破坏。
- 从现在起，**新产物一律进 `E:\fpga\contest_s2\`**。
- 官方资料包 `HX1P35A_Contest_202606` 内**只读**，我们的任何编辑都不放进去（记忆文件已独立到 `contest_s2\memory\`）。

## 六、为什么这样分

1. **提交时只打包 `delivery\` + `src\` 即可**，不用在官方资料包里翻找。
2. **源码/仿真/文档分离**，三个人各管一块互不覆盖。
3. **memory 独立**，随阶段滚动更新，是"我们踩过的坑"的唯一权威来源。
