# 02 · 文件存放规划

> 目的：把「官方资料 / 阶段性产物 / 最终提交物」三者分开，避免混在一起找不到、避免误改官方文件。
> 原则：**官方资料只读不动；我们的产物独立分层；每阶段打快照可回溯。**
>
> ⚠️ 本文档分两部分：**第一节是仓库当前的真实结构**（照它找文件）；
> **第四节写"规划中但还没建"的目录**，那些路径现在**不存在**，别照着找。

## 二、位流与快照命名（**实际在用的**）

### 位流（`bitbank\`）

```
OUR_<阶段>_<功能>_<状态>.bit      状态 = verified（已上板验证）/ pending（待验证）
```

例：`OUR_p1_colorbar_verified.bit`、`OUR_a3_camera_v4_pending.bit`

**判断"哪个是现行版"看 [`bitbank\位流台账.md`](../src/p1_colorbar/bitbank/位流台账.md) 的「★ 现行版本」行，不要看文件名**——
同阶段的位流字节数几乎完全相同（1,789,533 / 1,789,539 B），只看名字极易烧错。

历史版本移入 `archive\old_bit\`；位流本身走 GitHub Releases 分发（见 `docs\10_协作规范.md`）。

## 五、为什么这样分

1. **提交时只打包 `delivery\` + `src\` 即可**，不用在官方资料包里翻找。
2. **源码 / 仿真 / 文档分离**，三个人各管一块互不覆盖。
3. **memory 独立**，随阶段滚动更新，是"我们踩过的坑"的唯一权威来源。
4. **官方资料包只读**，我们的任何编辑都不放进去（记忆文件已独立到 `contest_s2\memory\`）。
