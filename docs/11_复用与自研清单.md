# 复用与自研清单（答辩用）

> 用途：明确区分「安路官方提供的技术支持」与「我们自研的部分」。既保证学术诚信，也便于答辩时讲清工作量分配。

## 〇、复用边界怎么判（按官方原文，不按感觉）

**官方原句（必须记住两条）**：

1. 《选题指南》**六、其它**（P35）：**"参赛作品必须为原创，不得抄袭、盗用他人作品，且版权未移交他人。"** → 这条对**所有选题**有效，是唯一的"硬红线"。
2. 《选题指南》**选题一 1.3**（P14）："参赛作品中所展示的**所有算法、控制逻辑及数据处理流程应在 FPGA 中自主编程实现**……" → ⚠️ **这句原文在选题一里，选题二没有同款句子**。但它的立法意图（算法与控制逻辑要自己写）同样适用于选题二，因为 2.6 评分标准的扩展/高阶项全部围绕"算法设计与系统优化"。

> 团队旧文档里写的"官方例程的算法禁止照抄"属于**合理解读**，不是选题二的直接引文。答辩时别说"规则写了不许抄算法"，要说"总则要求原创，且例程算法本身就是官方已实现的东西，照搬等于没做工作"——后者站得住。

**四层判定表（照这个切，别整块儿想）**：

| 层 | 典型内容 | 能不能复用 | 依据 / 理由 |
|---|---|---|---|
| ① 器件与 IP 驱动层 | MIPI D-PHY、DDR 控制器、HDMI 加密核（`.enc.v`）、PLL、SC520 I2C 配置 | ✅ **可以、且应该复用** | 加密 IP 本就不可改；指南明确把这些列为"技术支持 / 接口例程" |
| ② 参考架构与连线 | `design_top_wrapper` 的模块划分、96/128bit 数据流、时钟域划分 | ✅ 可参考 | 赛题本就是"在官方平台上开发"，平台骨架不算作品 |
| ③ **赛题要求的处理算法** | 边缘检测、卡通化、目标检测、运动检测、AE/AWB 策略 | ❌ **必须自研** | 官方 lab_ex2 已有固定阈值 Sobel；照搬 = 该项零工作量，且与"原创"冲突 |
| ④ 交互与呈现层 | OSD、按键、状态显示、指标面板 | ⚠️ **边界层**：**叠加/渲染逻辑必须自己写**；**图形素材（"安路"Logo 位图）可用官方** | 官方 lab_ex3 已有整套 OSD；整段搬 = 该项零工作量，且视频里会和别的队长得一模一样 |

> **现状（2026-10-17 23:41）**：按"官方有的都要用官方"的要求，交付默认已改为**官方实现**（官方 `hdmi_mixer.v` + `anlogic_logo_rom.v` + `osd_char_lib.v` 原样），自研 `osd_overlay.v` 保留为 `OSD_SELF_DEV` 分支。两条路的资源/时序/画面差异见 [`14_B4_OSD更新说明.md`](./14_B4_OSD更新说明.md) 第九节。**下表与"答辩一句话"描述的是自研分支的做法**，若最终交官方版，答辩口径要改成"基础部分用官方例程打底，自研工作在 A2/A3 算法与后续扩展"。

**第 ④ 层为什么这么切**：
- "安路"Logo 是**主办方要求你展示的标识**，图形数据取官方 ROM 是最合理、最不会出错的做法（自己重画一个 Logo 反而有失真风险）；
- 但"叠加"这件事本身是赛题基础要求（B4）的**实现工作**，必须是你的：坐标/尺寸参数化、混合方式（描边、半透明）、多区域布局、动态内容（模式名/帧率/延迟/坐标）。官方 lab_ex3 只有"整像素替换 + 左下角黄字 CNT"，这些差异就是你干的活。

**OSD 的合规做法（推荐）**：

| 维度 | 官方 lab_ex3 | 我们（交付版） |
|---|---|---|
| Logo 图形 | 160×160 ROM | **沿用官方 ROM 的像素数据**（并在报告注明来源） |
| 叠加方式 | 命中即整像素替换 | **自研**：1bit 掩膜 + 描边（黑/白自适应背景）+ 可选半透明 |
| 位置/尺寸 | `localparam` 写死 (0,0) | **自研**：可配置坐标，多区域（Logo 区 / 状态区 / 检测框区） |
| 动态内容 | 只有 `CNT: 1234` | **自研**：算法模式名、阈值档、帧率、延迟 ms、目标坐标 |
| 文字字模 | 官方 5×7 表 | 可复用字符点阵数据，但**排版/取模/渲染逻辑自写** |

**答辩一句话**（被问到 OSD 是不是抄的）：
> "Logo 的图形数据取自官方例程的 ROM——因为那是主办方的标识，重画反而不准；但叠加逻辑是我们自己写的：官方是整像素硬替换、位置写死、只有计数器；我们是掩膜+描边+半透明、坐标可配、多区域，并且动态显示模式名/帧率/端到端延迟。这一块的差异在报告第 4 节有对照表。"

## 三、一句话说明（答辩话术）

> 硬件通路层（MIPI/DDR/HDMI 及芯片专用加密 IP）复用了安路官方参考设计——这些涉及器件物理层资源与加密 IP，属于厂商技术支持；**算法与应用层全部自研**：**5×5 均值去噪 + 均值梯度 + 分段自适应阈值 + 因果双阈值迟滞**的 RTL 实现、Python 黄金模型与逐像素验证体系、四态切换、上板自检可视化。
>
> 其中**算法与官方参考例程的判决机制完全不同**：官方是固定阈值 80、无后处理、水平降采样至 640；我们是**5×5 均值去噪 + 分段自适应阈值（暗192/中160/中高128/亮96 + 亮度项）+ 因果双阈值迟滞**、**全分辨率 1280**、**移位/加法实现不占 DSP**。早期（v2/v3 逐像素版）对比实验显示：对低对比度弱边缘，官方固定阈值 100% 漏检、我们全部检出；⚠️ v4 的官方对比态 `OFFICIAL_THR` 尚未按新 mag 量级重标定，该数字不能直接挪用到 v4（如实口径）。
