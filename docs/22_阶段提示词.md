## 三、⚠️ 开工前必须先对账的两处估算（我核对需求文档时发现的）

### 3.1 阶段 3 帧差运动检测的 ERAM 预算写少了约 23 倍

需求文档 §8.2 写「~800 LUT / **1 ERAM** / 0 DSP」，但按 1/4 降采样实算：

| 降采样解释 | 网格 | 前帧灰度 8bit | 折合 ERAM20K 块 |
|---|---|---|---|
| 每 4 像素取 1 | 320×180 = 57,600 px | 460,800 bit | **22.5 → 23 块** |
| 行列各 1/2（面积 1/4） | 640×360 = 230,400 px | 1,843,200 bit | **90 块（超预算，直接爆）** |

> 每块 ERAM20K = 20 Kbit = 20,480 bit；剩余 48 块。

**结论**：23 块不是不能做，但会吃掉剩余 ERAM 的一半，且 §8.3 的总账（"+2350 LUT ≈ +11%"）只算了 LUT 没算这一笔。

**处置（阶段 3 开工第一件事，先算再写）**，候选：

| 方案 | 网格 | ERAM | 代价 |
|---|---|---|---|
| A 前帧存 DDR 复用 | 320×180 | 0 | 要占 DDR 带宽，需与现有 4 缓冲读写仲裁 |
| B 降到 1/8 网格 | 160×90 | ~6 块 | 每格 8×8，挥手/人体运动完全够用 |
| C 网格 + 4bit 灰度 | 160×90 | ~3 块 | 量化到 16 级，帧差阈值要相应放宽 |
| D 1/16 网格 | 80×45 | ~2 块 | 每格 16×16，只适合大范围运动 |

建议 **B**（6 块，视觉够用，余量健康）。这条要写进阶段 3 提示词的第一条任务。

### 3.2 阶段 1/2 的「0 ERAM」依赖共享窗口，独立实现各需 +1 块

- **卡通化**：3×3 中值需要 3 行灰度窗口（y-2/y-1/y）。若 tap 进 `edge_adaptive_96` 已有的行缓存链 → 0 ERAM；独立实现 → 32bit×1280 打包 4 行/块，2 行只需 **1 块**。
- **检测**：二值形态学开运算需要 3 行二值窗口，1bit×1280×3 = 3,840 bit → 打包后 **1 块**足够（不写 0 也行，但用 ERAM 比 1280 级移位寄存器省 LUT）。

两者都在 48 块余量内，**不阻塞**，但需求文档 §8.3 的总账应补上这 1~2 块。

## 五、阶段 1 提示词 —— 卡通化（2 天）

```text
【阶段 1 · 目标】扩①风格化：卡通效果 = 颜色量化（色块平滑）+ 边缘压黑（勾线）。
预算 ~500 LUT / 0~1 ERAM / 0 DSP。

────────────────────────────────────────────
T1 · 先做架构决策（先算账，再写代码）

卡通化需要 3×3 中值（或均值）平滑，也就是需要 3 行灰度窗口。
两个候选，写个对比表（LUT/ERAM/实现难度/对现有模块侵入性）给我选：

  方案 A · 共享窗口：把卡通化做成 edge_adaptive_96 内部的一个输出分支，
     直接复用它已有的行缓存链和 5×5 窗口。0 ERAM，但要改已验证模块（有回归风险）。
  方案 B · 独立模块：新模块插在同一个位置（awb → 卡通化 → data96_128），
     自带 2 行缓存（1 块 ERAM）。不碰已验证代码，代价 +1 ERAM。

倾向：A 省资源且不额外占 ERAM；但 B 更安全。你来给结论并说明理由。

────────────────────────────────────────────
T2 · 颜色量化（这一级应该做到接近 0 LUT）

原理：量化 = 取高位 + 位复制回填，纯连线，不用乘法不用比较器。
  8bit → 3bit：out = {r[7:5], r[7:5], r[7:6]}   （左移 5 + 左移 2 + 右移 1）
  若色块太硬（台阶感明显）就上 4bit：out = {r[7:4], r[7:4]}
三个通道各做一次，共 24 × 4 = 96 根线，**全部是 wire assign，0 LUT**。

做：先写参数化 Verilog（QUANT_BITS 可配 3 或 4），再用黄金模型扫一遍
    "原始 vs 量化"的色彩误差，确认没有通道溢出/截断 bug。

────────────────────────────────────────────
T3 · 3×3 中值滤波（降噪去纹理，让色块干净）

原理：9 个元素取中值，用排序网络（Batcher's odd-even mergesort 或简化版
      "三行各排序 → 三列各排序 → 对角线"），约 19 个 8bit 比较器 ≈ 150~300 LUT。
      注意：中值保边缘，比均值更适合卡通化（均值会把勾线糊掉）。

做：RTL 里 3 行窗口必须**同拍对齐**（MEMORY 第 15/16 条：地址与数据成对打拍，
    多链相位显式对齐——这是踩过 140/560 误差的老坑）。

────────────────────────────────────────────
T4 · 边缘压黑（勾线）

原理：直接复用 edge_adaptive_96 已算好的判决位 e（1bit/像素），
      e=1 → 输出黑（24'h000000），e=0 → 输出量化后的色块。
      就是一个 24bit 2:1 mux × 4 像素 = 96 个 mux ≈ 48 LUT。

关键（最容易错的一处）：判决位 e 比原图晚 3 拍，量化+中值又有自己的延迟。
  先把三条路径的延迟列成表（原图 / 量化+中值 / 边缘判决），
  再用移位寄存器把快的那条补到和最慢的一条同拍，最后才做 mux。
  **没对齐就 mux = 勾线和色块错位几列**，肉眼能看出来。

────────────────────────────────────────────
T5 · 模式接入

mode_ctl 现在是 5 态（0..4）。卡通化作为新的一态（mode 5）加入，
O_mode 位宽从 [2:0] 扩到 [3:0]（或重排态序），同步改：
  - mode_ctl.v 的 O_mode 位宽与循环上限
  - cdc_mode_sync.v 的 I_mode/O_mode 位宽与独热码编码
  - isp_top.v 的 I_mode 位宽与例化
  - design_top_wrapper.v 的 mode 连线
  - OSD 的模式名显示
改完跑一遍 mode 全态回归（每个态都上板看一眼）。

────────────────────────────────────────────
【验证要求（按 MEMORY 第 36-40 条）】
- 黄金模型与 RTL **严格同序**：RTL 是因果流式，模型窗口垂直顺序必须是 {y-2, y-1, y}
  （顶部补 2 行，不是 np.pad 对称补 0），边界屏蔽与 RTL 的 win_valid 逐字对齐
- 测试图四件套：彩条 + 棋盘 + 渐变 + 灰阶
- 图案必须含四类区域：强边缘 / 弱边缘 / 叠加高斯或椒盐噪声的平坦区 / 低对比度纹理

- 验证脚本不许吞编译错误：vlog 输出里出现 "Error" 必须判失败

【验收】
  □ 仿真逐像素 0 误差（4 张图）
```

```text
T1 · 判色：RGB → HSV，但**不要写除法器**

原理：HSV 的 H 需要分段比较、S 需要 (max-min)/max —— 除法在 FPGA 上很贵。
两条路，选一条并说明理由：
  路 1 · 归一化色度判据（推荐，零除法）：
     先算 sum = R+G+B（两级加法），再判 R > TH1*sum（TH1 取 2 的幂次倒数 → 移位）
     等价于"红色占比足够高"，对纯色球/色块非常好用，~30 LUT
  路 2 · 完整 HSV：H 用比较器树分段 + 移位近似除法，S/V 直接用 max/min
     更通用（能判任意色相区间），~150~250 LUT
注意：亮度鲁棒性——暗处 sum 小，"占比"判据仍然成立（这是选它的理由之一），
      但要加一个 sum 下限（太黑不判），否则暗部噪声全被判成目标。

做：先写黄金模型，用几张不同亮度下的目标图统计"命中率 / 虚警率"，
    把阈值定下来再写 RTL。

────────────────────────────────────────────
T2 · 形态学开运算去噪（先腐蚀后膨胀，3×3）

原理：腐蚀滤掉孤立噪点，膨胀把目标涨回原尺寸。
**二值形态学可分离**（关键技巧，省一半逻辑）：
  3×3 腐蚀 = 水平 1×3 取 min → 垂直 3×1 取 min
  3×3 膨胀 = 水平 1×3 取 max → 垂直 3×1 取 max
  开运算 = 腐蚀两趟 + 膨胀两趟，共 4 趟，每趟只需 1 行缓存
窗口：3 行 × 1bit × 1280 = 3,840 bit → 1 块 ERAM 打包足够

做：同上，三条链（前/中/后行）必须同拍对齐；行首延后放行（等链填满）。

────────────────────────────────────────────
T3 · 质心：行列投影 + 半数法（零除法）

原理：
  列投影：每列统计命中像素数 cx[i]，累加得 sum_x = Σ i*cx[i]、sum_w = Σ cx[i]
  行投影：同理得 sum_y
  质心 = sum_x / sum_w
半数法：不除，扫描累加 cx[i]，当累加值首次达到 sum_w/2 时，当前 i 即为质心。

⚠️ 一个必须提前认清的偏差（别等上板才发现）：
  **半数法给的是中位数，不是加权平均质心**。
  单目标（一个连通 blob）时两者几乎重合，完全够用；
  多个分散目标时，中位数会落在中间某个位置，看起来"框飘了"。
  处置：先用半数法；若多目标漂移明显，改用「sum_w 取最高位 + 移位」的近似除法
  （约 50 LUT），或先做连通域标记（贵，不推荐）。
  写进文档：本设计定位为**单目标跟踪**。

────────────────────────────────────────────
T4 · 叠加：准星 + 外接框

原理：质心坐标 (cx, cy) 从 csi 域（~103.52MHz）跨到 HDMI 像素域（74.25MHz），
  用 cdc_mode_sync 同款手法：格雷码或独热码 + 帧锁存（一帧只更新一次，
  避免画面撕裂/闪烁）。
  画框：在 HDMI 像素域用 hcnt/vcnt 判断是否落在框线上，落在则替换像素。
  注意坐标要换成**画面坐标**（MEMORY 第 12 条：hcnt 从 260、vcnt 从 25 开始）。

────────────────────────────────────────────
T5 · OSD 报坐标

在自研 osd_overlay 上加一行，显示 "X:#### Y:####" 与命中像素数。
```

```text
原理：
```
