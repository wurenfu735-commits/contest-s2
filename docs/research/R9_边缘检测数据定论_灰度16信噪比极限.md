# 边缘检测最终诊断（for2.csv 数据定论）

> 数据：`td_project/data/for2.csv`（mode2 调试模式，经 HDMI 视频流带出内部数值）
> 日期：2026-10-20 18:18

---

## 一、抓取方式（已成功）
mode2 临时改成调试模式，4 lane 经 HDMI 输出内部数值，抓 `S_hdmi_out_data[23:0]`：
- lane0 = {4'h0, thr0[7:0], mag_r[0][11:0]}
- lane1 = {4'h1, mag_max_line[11:0], 8'h00}
- lane2/3 = 拉伸后灰度 gray[15:0]/[31:16]

高 4 位分布 {0:260, 1:255, 2:255, 3:254}，4 lane 均衡，抓取成功。

## 二、三个决定性数据

### 1. Sobel 梯度 mag（lane0 低 12 位）
- **中位数 6，p90=14，p99=22，最大 28**
- 直方图：mag 0~3 占 50%，4~7 占 37%，≥8 仅 13%
- → 真实边缘梯度极低，阈值压到下限 8 也只能过 ~一半，大量边缘 mag 只有 2~6。

### 2. 拉伸后灰度 gray（lane2/3）
- **中位数 26，p90=34，最大 42**
- → 我加的 `(in-8)<<1` 拉伸后灰度仍只有 18~42，说明**输入(AWB 输出)本身就极暗（~17~29）**。

### 3. 阈值 thr0 恒 78（对应 mag_max_line=314）
- thr0 = max(8, 314>>2=78)，被上一行峰值 314 顶到 78。
- **78 >> 梯度中位 6**：阈值是边缘梯度的 13 倍，边缘被全部吃掉。

## 三、根因链（完整、有数据支撑）
```
传感器满曝光+16×增益（ae_set.v 已确认）
  → 但 AWB 只做白平衡、G 通道零增益（awb.v L340 G_new=G）
  → AWB 输出灰度锁死在极低段（实时画面实测 17~29，白纸 45）
  → 我的 (in-8)<<1 拉伸只把 17~29 拉到 18~42（输入就暗，拉伸无能为力）
  → Sobel 梯度中位 6、最大 28
  → 阈值 78（被 mag_max_line=314 顶高）是梯度的 13 倍
  → 边缘全部被阈值吃掉 → 输出 99.4% 纯白
```

## 四、最终结论
**病根不在边缘检测算法，也不在阈值，而在 ISP 上游：AWB 之后缺少"亮度增益"级，导致灰度只有 17~42。**
- 我之前的所有阈值/自适应/拉伸调整，都是在"输入动态范围只有 25 级（17~42）"的沙地上建楼，必然塌。
- 必须先解决"灰度被压暗"这一环，边缘检测才有意义。

## 五、修复方案（按优先级，这次有数据）

### 方案 A（治本，强烈推荐）：在 AWB 输出加"亮度增益"
`awb.v` L340 `G_new_r1 <= rgb888_g_d1` 改为乘一个亮度增益：
```verilog
// G 通道加亮度增益（如 4×），R/B 保持白平衡增益
G_new_r1 <= rgb888_g_d1 << 2;   // 4×，17~29 -> 68~116
```
或统一给 R/G/B 都加亮度增益，把灰度从 17~29 抬到 100+。

### 方案 B（治本，更好）：加"帧 min/max 自适应拉伸"
在 AWB 后统计一帧的灰度 min/max，做线性拉伸：`out = (in - min) * 255/(max-min)`。
把 17~42 动态范围拉伸到 0~255，梯度放大 6~10 倍。
资源：2 个帧累加统计 + 每像素一次乘加，可控。

### 方案 C（配合）：阈值改为"固定低值 + 峰值缩放"
即便亮度修好，阈值也不该用 mag_max_line>>2（会被少数强边顶到 78）。
改为 `thr = max(8, mag_max_line >> 4)` 或固定值，让阈值贴近梯度中位。

## 六、下一步
1. **先做方案 B（帧自适应拉伸）或 A（G 通道亮度增益）**，把灰度从 17~42 拉到 0~200+。
2. 灰度拉开后，Sobel 梯度同步放大到几十~几百，现有自适应阈值立即能工作。
3. 撤掉 mode2 调试模式，恢复边缘(强阈)。
