# 边缘检测"全白/检测缺失"根因诊断（for1.csv 后终版）

> 数据：`td_project/data/for1.csv`（mode3 自适应阈值版，17:36 抓取）
> 结论日期：2026-10-20

---

## 一、现象（for1.csv 实测）
- 输出 **99.4% 纯白**（1018 白 / 仅 6 黑），黑段只有 [5,1] 两处。
- 用户描述：书面内容展示 / 手部 / 脸部三部分，**背景白底过亮、实际物品检测差**。

## 二、逐级排查（这次不再盲调阈值，查到了上游）

### 1) 自适应阈值本身没坏（仿真已证）
- 仿真里"弱边灰阶差 20"能正确检出（tb_edge PASS）。
- 但真实输入边缘梯度**远小于 20** → 阈值下限 8 仍高于梯度 → 全白。

### 2) 真实灰度被压缩在极低段（铁证）
- 之前 19 份 `median_window/gray` 抓取：白纸 mean **45**（跨度 14~31）、人像 mean 90、全暗 mean 15。
- **整幅灰阶只用到了 0~110 这一小段**，动态范围严重不足。

### 3) 曝光/增益已最大化，但亮度仍不足（决定性发现）
`uiisp_beta/ae_set.v`（有人已改过，注释为中文）：
```
r_ae_set = 1991   // 曝光 = 最大安全曝光（720p60 VTS=1000，最大 2*VTS-9=1991）
r_ag_set = 144    // 增益 = 16 倍模拟增益 + 1 倍数字增益
```
→ **传感器已经满曝光 + 16 倍增益**，硬件采光已到极限。

### 4) ISP 缺"亮度/对比度增强"这一级（根因）
`awb.v` L339-341 的增益应用：
```verilog
R_new = (in_r_r1 * R) >> 16   // R 通道：白平衡增益
G_new = G                      // G 通道：原样透传，零增益！
B_new = (in_b_r1 * B) >> 16   // B 通道：白平衡增益
```
- **AWB 只做白平衡（R/B 相对 G），完全不提升亮度**；G 通道零增益。
- 整个链路 `demosaic → awb → image_modes4` **没有任何"亮度拉伸/直方图均衡/对比度增强"环节**。
- 结果：暗场景 AWB 输出灰阶被锁死在 0~110，边缘梯度天然极小（个位数~十几）。

## 三、根因结论
**不是边缘检测算法的问题，也不是阈值问题，而是 ISP 上游缺一级"亮度/对比度增强"**。
- 传感器已满曝光+16×增益，但 AWB 只做白平衡不提升亮度；
- 导致进入边缘检测的灰度动态范围只有 ~110 级（且集中在低段）；
- Sobel 对这么弱的对比度只能输出个位数梯度，任何阈值（含自适应）都会判为"无边缘"→ 全白。

## 四、修复方案（按优先级）

### 方案 A（首选，治本）：在 AWB 之后、image_modes4 之前加一级"亮度+对比度拉伸"
```verilog
// 线性拉伸：out = clamp((in - 黑电平) * scale)
// 把 [black..white] 映射到 [0..255]，scale 由场景动态范围决定
```
- 简单实现：`out = min(255, (in - 8) << 1)` 即可把 0~110 拉到 0~220，动态范围翻倍。
- 更稳：统计帧内 min/max 做自适应拉伸（类似直方图均衡，资源极小）。
- 这一级加完，边缘梯度同步放大，现有自适应阈值立即生效。

### 方案 B（次选，快速验证）：把 AWB 的 G 通道也加亮度增益
在 `awb.v` 给 G 通道乘一个固定亮度增益（如 1.5×），或把 `GAIN_MAX` 逻辑改成"亮度增益"而非"白平衡上限"。

### 方案 C（补充，治标）：边缘检测前做局部对比度归一化
在 Sobel 前对 3×3 窗做局部 min/max 归一化（拉平局部对比度），但资源比 A 多。

### 方案 D（兜底）：直接调低曝光/增益的映射，或补光
物理补光让白纸达到 160~200 灰阶，是最直接但依赖环境的方式。

## 五、建议执行顺序
1. **先做方案 A 的极简版**：在 `image_modes4` 输入端加一行 `gray = min(255, (luma - 8) << 1)`（亮度翻倍拉伸），重出 bit 看边缘是否出现。
2. 若边缘出现 → 证明根因正确，再把拉伸改成自适应（帧 min/max）。
3. 若仍无改善 → 回到曝光/补光（方案 D）。

---

## 附：为什么之前的"自适应阈值"方向是对的、但没解决
- 自适应阈值解决的是"不同场景对比度差异"，**前提是场景本身有足够对比度**。
- 但当输入灰度动态范围只有 110 级、且边缘梯度只有个位数时，任何阈值都"巧妇难为无米之炊"。
- 真正的病根在**亮度/对比度没有被拉伸**，必须先补这一级。
