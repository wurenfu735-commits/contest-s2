## A. RTL 编码红线（可综合规范，7 条）

| #  | 规则                                                                 | 为什么                                |
| -- | ------------------------------------------------------------------ | ---------------------------------- |
| A1 | **组合逻辑用 `always @*`**，且**每条路径对每个输出都赋值**（或先给默认值）                    | 漏赋值 → 综合出 **Latch**（仿真未必报错，综合后才暴露） |
| A2 | **时序块用 `<=`，组合块用 `=`**；同一信号绝不混用两种                                  | 混用会出现仿真/综合行为不一致（经典陷阱）              |
| A3 | **每个寄存器只有一个驱动者**，需要时给**确定复位值**                                     | 未复位寄存器：仿真起始为 X，硬件是不定值              |
| A4 | **每个时钟域只用一种复位惯例**（本项目统一：低有效异步复位 `negedge I_rst_n`）                 | 混用会引入额外逻辑、破坏资源推断                   |
| A5 | **每个 `case` 都要有 `default`**；不用 `full_case`/`parallel_case`/`casex` | pragma 只对综合工具有效，会让仿真与硬件不一致         |
| A6 | 可综合代码中**没有 `initial`、`#延迟`、`$display`、`===`、`real`**               | 这些只属于仿真平台                          |
| A7 | **位宽写明确**，中间结果**先算好再截断**                                           | 无声溢出是错误诊断的温床（我们已踩过位宽的坑）            |

**结合我们历史的补充**：

- **A8：计数器位宽必须装得下目标值**（`SAMPLE_MAX-1` vs `2^W-1`）—— 2026-10-14 按键 bug 的根因
- **A9：不要用"清零行缓存"做复位**（会把 BRAM 退化成寄存器，官方源码里专门留了注释警告）
- **A10：关键路径上的中间信号主动加 `(* keep = "true" *)`** —— TD 会把“看似不影响输出”的逻辑整片**常量传播**删掉。
  **判据：综合后某模块 `ripple = 0` 就是被优化掉了**（2026-10-16 实测：算法 49 LUT / 0 ripple / 37 seq → 加 keep 后 **356 LUT / 39 ripple / 161 seq / 3 块 ERAM**）

## B. 图像处理设计的专用注意（本项目重点）

| #  | 注意点                                                                         | 我们的做法                       |
| -- | --------------------------------------------------------------------------- | --------------------------- |
| B1 | **行缓存要让综合器推断成块 RAM**：用"写地址/读地址分离 + 同步读"的写法；必要时加 `(* ram_style = "block" *)` | 3 行 × 1280 × 8bit，目标用 ERAM  |
| B2 | **行缓存的写指针要在行末（tuser/tlast）复位**，否则行会"错位"                                     | 每行独立处理                      |
| B3 | **流水线要"延迟匹配"**：数据、valid、tlast、tuser 必须**同拍推进**（每级一起打拍）                      | 5 级流水，控制信号与数据同步延时           |
| B4 | **警惕"因果性"**：输出像素只能依赖"当前 + 已流过"的像素（NMS 之所以不做就是这个原因）                          | 迟滞只看左/上/左上                  |
| B5 | **边界处理要显式**：有效区前 2 行、每行第 1 列没有完整 3×3 窗口 → 输出黑（与官方一致）                        | 用 `window_valid` 标志         |
| B6 | **别盲目堆并行度**：并行 ↑ ⇒ 资源 ↑、布线压力 ↑、功耗 ↑，时序还可能变差                                 | 4 像素/拍（跟着官方 96bit 接口走），不再加宽 |
| B7 | 乘法/除法尽量换成**移位与加法**（省 DSP、缩逻辑级数）                                             | 阈值计算全用 `>>3`、`>>5`          |
| B8 | **块 RAM 只用工程 `.al` 里已注册的 IP**（如 `blk_mem_gen_zhenghe`），HDL 里裸例化它的模块名即可 | ⚠️ **裸例化 arch 库的 `PH1P_LOGIC_ERAM` 无效**（该原语是空壳，TD 只在 IP 流程里才映射成物理块 RAM）；reg 数组会被推断成 `LOGIC_RAMFIFO` 且深度推错（1024 vs 实际 1280） |
| B9 | **4 像素/拍做 3×3（或 5×5）窗口，必须加"跨拍像素拼接寄存器"** | 每拍第 1 个像素的**左邻**是**上一拍第 4 个像素**，不在本拍的 96bit 里。少这个 8bit 寄存器，窗口会整体右移 1 像素 → 卡通化出竖条纹、形态学边界错位。**这是一类"仿真看着对、上板才发现"的隐性错位**，2026-10-19 加（详见 `R4` 三.3） |

## C. 时序与资源（来自避坑指南）

| #  | 原则                                                              | 落到我们项目                                              |
| -- | --------------------------------------------------------------- | --------------------------------------------------- |
| C1 | **时序不只看 WNS**，还要看 **WHS（Hold）**、**WPWS（脉宽）**                    | TD 报告里三个都要看（P1 v3：Setup 14.07ns / Hold 23ps / 0 违规） |
| C2 | **关键路径长就加 Pipeline，别指望工具变魔术**；Latency 与 Throughput 是两回事         | 我们允许 +1~2 拍延迟换取 Fmax 余量（16.7ms 帧预算根本用不完）            |
| C3 | **`if/else if` 串会形成优先级 MUX 链**，`case` 更接近并行选择                   | 判决逻辑用 `case`；真需要优先级的才用 if 链                         |
| C4 | **资源利用率 ≠ 可布线性**：50% 从容，80% 危险                                  | 我们 LUT 4.4%、ERAM 5%，非常从容（约 +800 LUT 后仍是 8% 左右）      |
| C5 | **不要把 Timing Exception 当遮羞布**：false_path / multicycle 必须有真实硬件依据 | 我们只对异步跨域做必要的处理，不用它们掩盖问题                             |
| C6 | **动态功耗来自"无效翻转"**：能用 Clock Enable / valid 门控就别让它空转               | 用 tvalid 门控流水线更新                                    |

## D. 仿真与验证（我们的经验 + 规范）

| #  | 规则                                              | 教训来源                                 |
| -- | ----------------------------------------------- | ------------------------------------ |
| D1 | **必须用真实参数跑一遍**（小参数会掩盖位宽/时序问题）                   | 按键 bug：TB 用 1kHz 掩盖了 74.25MHz 下的位宽溢出 |
| D2 | **必须有"总量校验"**：比对像素总数、误差数，不能只看"没报错"              | 历史坑：设计完全不动也会误报 PASSED                |
| D3 | **逐像素比对要有可定位的错误报告**（第一个误差的坐标 + 总数）              | 便于分类定位（行首→边界；某几行→行缓存）                |
| D4 | **X 传播检查**：设计中出现的 X 要能解释，不能靠"仿真恰好没影响"           | 规范里的"不要依赖 x 乐观假设"                    |
| D5 | **模型与 RTL 同序**：黄金模型严格按 RTL 的扫描顺序与邻域依赖实现，才能 0 误差 | 已在 R1 规格中定死                          |

## E. 本项目专用检查表（写 `edge_adaptive_96.v` 时逐条打勾）

**写之前**

- [ ] 明确这段代码**综合后要变成什么电路**（3 行 ERAM + 移位加法网络 + 判决逻辑）
- [ ] 接口与官方 96bit 流一致，插在 `isp_top` 的 awb 与 `data_96bit_to_128bit` 之间

**写之中**

- [ ] 组合块 `always @*` + 所有输出全路径赋值（防 Latch）
- [ ] 时序块 `<=`；数据/valid/tlast/tuser **同拍推进**
- [ ] 行缓存按"同步读 + 读写地址分离"写，行末复位写指针
- [ ] 所有计数器位宽够用（sum9 12bit、mag 13bit、thr 12bit、行缓存地址 11bit）
- [ ] 阈值计算只用移位与加法；无乘法器/除法器/DSP
- [ ] 迟滞判决只依赖左/上/左上（因果）
- [ ] 边界（前 2 行、行首）显式输出黑
- [ ] **不复位行缓存**

**写之后**

- [ ] ModelSim 用**真实参数**（1280×720、74.25MHz）跑 4 种测试图
- [ ] 与黄金模型 `.raw` **逐像素比对 = 0 误差**，并打印第一个误差坐标
- [ ] TD 综合报告：ERAM 增量 ≤ +4 块、LUT ≤ +800、**DSP = 0**
- [ ] **核对资源增量是否符合事前预估**（写代码时就在文件头写下预期值：LUT / FF / ERAM / DSP）
      - **`ripple` 必须 > 0** —— 有进位链才说明加法器真的进了网表；`ripple = 0` 而代码里有加法/比较，就是被优化了
      - 顶层 `#eram` / `#lut6` / `#reg` 的增量要与预估对得上（本次实测：`#eram` 5→8、`#luts` 1169→1522、`#registers` 1384→1519）
- [ ] 时序三件套（Setup WNS / Hold WNS / 脉宽）全为正
- [ ] 上板：彩条→清晰竖线；渐变→无虚假边缘；按键切换正常；状态带正常

## F. 厂商工具行为必查项（安路 TD 专有 —— 2026-10-16 排查一整天换来）

| #  | 坑                                                           | 表现                                                         | 对策                                                     |
| -- | ------------------------------------------------------------ | ------------------------------------------------------------ | -------------------------------------------------------- |
| F1 | **逻辑被常量传播整片删除**                                   | 某模块资源异常小、**`ripple = 0`**                          | 给关键中间信号加 `(* keep = "true" *)`                   |
| F2 | **裸例化 arch 原语无效**                                     | `elaborate` 能找到模块、参数也对，但 `#eram` 不增加          | 只用 `.al` 的 `<IP_FILE>` 段注册过的 IP                  |
| F3 | reg 数组被推成 `LOGIC_RAMFIFO` 且**深度推错**                | 日志出现 `PH1P_LOGIC_RAMFIFO(ADDR_WIDTH=10)`，而数组需 1280 深 | 同样改用已注册的 IP                                    |
| F4 | **官方源码里的保留标记就是坑位地图**                         | 官方写 `(* keep = "true" *)`、`//synthesis keep`、`AutoExcluded` | **看到就追问“官方为什么这么写”**                |

**排查铁律**：面对多种可能原因，**先做那个"一次实验就能切开一半假设空间"的**（如本次的 `keep`，一次编译即可区分"逻辑被删"还是"RAM 没落地"），而不是先做自己最熟悉的方向。

**通用检索习惯**：开工前不要只查“某某编码规范”，要查“**<工具名> <现象> 坑**”；遇到异常先搜“是不是工具已知行为”，再怀疑自己的代码。
