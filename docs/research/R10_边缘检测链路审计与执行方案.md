## 一、先对齐事实：本工程只有 4 个模式

KEY1(D5) 输出 **Gray 码**，`k1_mode.v` 循环 `0→1→3→2`，顶层 `camera_mode={mode[1], mode[1]^mode[0]}` 转二进制 → 实际模式**只有 0~3**：

| camera_mode | 含义 | 实现 |
|---|---|---|
| 0 | 原图（经链路延时） | `final_side`（emeta 透传 RGB） |
| 1 | 灰度 | `final_side[32+i*8]` |
| 2 | LPR 二值 | 中值 → 固定阈值 → 3×3 开运算 |
| 3 | **边缘** | 中值 → 3×3 窗 → Sobel → 阈值 → 白底黑边 |

> ⚠️ 记忆里的「mode4 卡通 / mode5 形态学梯度」在本工程**不存在**，`I_mode` 只有 2 bit，无法到 4/5。不要再按 5 模式排查。

## 二、目标工作流 vs 现状（逐级对照）

目标：**灰度 → 3×3 高斯平滑 → Sobel → 阈值二值化 → 边缘输出（+可选开运算）**

| 级 | 目标做法 | 当前实现（mode 3） | 结论 |
|---|---|---|---|
| ① 灰度 | BT.601 加权 | `luma = (77R+150G+29B+128)>>8` | ✅ 已实现，正确 |
| ② 前置平滑 | **3×3 高斯（1,2,1/2,4,2/1,2,1 ÷16）** | **3×3 中值**（`median_window` + 9 级比较交换排序网络） | ❌ **不符**：用的是中值不是高斯；排序网络 LUT 开销极大 |
| ③ 梯度 | Sobel `|Gx|+|Gy|`，**独立 3×3 窗** | `edge_window` 取 3×3 → `magnitude()`：`Gx=右列(1,2,1)−左列`、`Gy=下行−上行`，`|Gx|+|Gy|` | ✅ Sobel 本身正确，且**确实有独立窗口** |
| ④ 阈值 | 平滑后按噪声水平定阈，稳健 | `threshold = (中心灰>>3) + 14`（约 19~39） | ⚠️ **偏低且用中心自身亮度**：边缘处中心忽明忽暗，阈值不稳 |
| ⑤ 输出 | 白底黑边 | `(egood && mag>=thr) ? 黑 : 白` | ✅ 方向对 |
| ⑥ 可选开运算 | 去孤立边缘点 | **没有** | ❌ 缺失（可选） |
| 同步 | hs/vs/de 随像素流对齐 | 用 AXI-stream（`tvalid/tuser/tlast`），各窗内部 `ov/os/ol` 同步寄存 | ✅ 机制正确，但**新增算术级必须显式补延时**（见第四节） |
| 存储 | 优先 EDA 推断 | `line_ram4` **直接例化 `PH1P_LOGIC_ERAM`** | ⚠️ 与“优先推断”要求不符，建议改推断式 + 综合属性 |

**一句话结论：Sobel 本身是对的；缺的是「前置高斯平滑」这一级，且前置级误用了最耗 LUT 的中值排序网络，阈值也偏弱。** 这正是你列出的噪点原因 1、2 的代码证据。

## 三、差距定位（改哪里）

| # | 问题 | 位置 | 改法 |
|---|---|---|---|
| 1 | 前置平滑不是高斯 | `image_modes4.v` L33-36 `median_window` + L38-493 九级排序 | **删除排序网络**，改为 `gauss_window`(独立窗) + 可分离高斯求和 |
| 2 | 中值排序巨耗 LUT | L38-493（`sorted[0..8]`、`bounds/meta` 9 级） | 随 #1 一并删除（这是最大的 LUT 释放点） |
| 3 | 阈值偏低/不稳 | L611 `threshold<=ew[..39-:5]+14` | 改为 `T = base + (高斯中心>>k)`，`base` 由 `I_k` 选档（建议 32/48/64/80） |
| 4 | 无边缘后处理 | 输出段 L621-625 | 可选：对二值边缘做一次 3×3 开运算（默认关闭，省资源） |
| 5 | 显式厂商 RAM | `window4.v` L30-32/L62-78 `PH1P_LOGIC_ERAM` | 改 `reg [31:0] mem[0:511]` + 同步读 + 综合属性，让 TD 推断 ERAM |
| 6 | 算术级未补延时 | 新高斯加法（组合→1 拍寄存） | 把 `tvalid/tuser/tlast` 同步打 1 拍，与像素同延迟 |

> 注：#5 是“尽量”级别；若推断后资源/时序不理想，可保留显式 ERAM（安路原语），不影响功能。

## 四、执行方案（推荐 Plan A，可直接落地）

### 数据通路（每像素 4 lane 并行，与现结构一致）

```
gray(4 lane) ──► [窗#1 gauss_window 3×3] ──► 高斯加权和(÷16) ──reg 1拍──► smooth
                     │(独立3×3行缓存)                                        │
                     └──────── tvalid/tuser/tlast 同步+1拍 ──────────────────┤
                                                                             ▼
smooth ──► [窗#2 sobel_window 3×3] ──► Sobel |Gx|+|Gy| ──reg 1拍──► mag
                     │(独立3×3行缓存)                                        │
                     └──── tvalid/tuser/tlast 同步+1拍 ─────────────────────┤
                                                                             ▼
                     (可选)[窗#3 open_window] ──► 开运算 ──► 二值 0/FFFFFF
```

### 高斯（可分离，最省加法器）
```verilog
// 行内：a + 2b + c  →  行间：top + 2*mid + bot ，最后 >>4
wire [11:0] top = w0 + {w1,1'b0} + w2;
wire [11:0] mid = w3 + {w4,1'b0} + w5;
wire [11:0] bot = w6 + {w7,1'b0} + w8;
wire [12:0] gsum = top + {mid,1'b0} + bot;    // ≤ 16*255 = 4080
wire [7:0]  gauss = gsum[11:4];               // ÷16
```
- 每 lane ≈ 6 个 12bit 加法器 + 移位；4 lane 共 ~24 个。**远比 9 级比较交换排序小**。

### Sobel（保持现有 `magnitude()`，方向已正确）
```verilog
Gx = 右列(1,2,1) − 左列(1,2,1);
Gy = 下行(1,2,1) − 上行(1,2,1);
mag = |Gx| + |Gy|;
```

### 阈值（平滑之后再定，可显著提高）
```verilog
wire [7:0] thr_base = 8'd32 + {I_k,4'b0000};   // 32/48/64/80
wire [7:0] thr = thr_base + smooth_center[7:3]; // 平滑后中心>>3，随亮度慢变
edge_px = mag >= {1'b0,thr};
```

### 延时对齐（关键，防错位）
- `window4` 内部已对 `tvalid/tuser/tlast` 各打 1 拍（`ov/os/ol`）；
- 高斯加权是**组合逻辑**，必须在其后**补 1 拍寄存**，并把 `valid/sof/eol` 同步打 1 拍；
- Sobel 的 `magnitude` 同理补 1 拍；
- 三处延时数必须完全一致，否则边缘会相对原图错位 1~2 像素（尤其会破坏 left-2-col 的边界判定）。

### 存储改为推断式（可选但推荐）
```verilog
(* ram_style = "block" *) reg [31:0] mem [0:511];
always @(posedge clk) begin
  if (we) mem[addr_w] <= din;
  q <= mem[addr_r];          // 同步读，1 拍
end
```
同时保留“三 bank 轮转”避免读写同址；上行两行、左两列依旧标记无效。

## 五、资源与验证

- **LUT**：删掉 9 级排序网络（`sorted[0..8]` 全宽 288bit）→ 释放大量比较器；新高斯 ~24 加法器。**净 LUT 预计明显下降**（这是本次改动最大收益）。
- **ERAM**：仍为 2 个窗 × 3 bank = **6 块**（与现状持平）；若加可选开运算再 +3 块。
- **仿真**：扩展 `_syntaxcheck/tb_image_modes4.v`
  - 合成台阶边缘 → 高斯输出应为**平滑过渡**（中间灰）；
  - Sobel 应在台阶处出**单峰**、平坦区≈0；
  - 验证 `tuser/tlast` 与边缘位置对齐（无 1~2 像素偏移）；
  - 噪声场景：加入 ±10 随机噪声，验证高斯后 Sobel 不再满屏噪点。
- **上板**：KEY1 切到 mode3，观察边缘是否连续、噪声点是否显著减少。

## 六、执行顺序与回退

1. 备份当前 `rtl/image_modes4.v` → `image_modes4_v3_median.bak`。
2. 删除中值排序网络，按上表新增 `gauss_window` + 高斯求和 + 延时对齐。
3. 阈值改为 `32+I_k*16 + (smooth_center>>3)`。
4. ModelSim 自测（台阶+Sobel 单峰+对齐）。
5. TD 综合评估 LUT/ERAM → 出 bit → KEY1 看 mode3 效果。
6. 若效果仍差：**Plan B（重来）** —— 只保留「灰度→高斯→Sobel→全局阈值」最小链路，去掉 LPR 与所有形态学，先把干净边缘跑出来，再逐级加回。
