# research\ —— 调研分区导读

## 这个目录是什么

每个阶段 / 扩展项**动工前**的可行性调研都落在这里（模板见 `docs\07_执行路线图.md` 第四部分）。
调研的目的是**减少实施中的错误**，不是走流程；调研结论一旦过时，以现行规格（`docs\08`）与实现为准。

| 文件 / 目录 | 讲什么 | 状态 |

## 怎么用

1. 新扩展项动工前：按 `docs\07` 第四部分模板新建 `Rn_<项目名>.md`（编号顺延），全队看过再动手。
2. **只借鉴思路、绝不照搬源码**（调研边界铁律，MEMORY 八节第 4 条）：借鉴的粒度是架构模式与工程技巧，落地代码结合我们的接口（96bit、4 像素/拍）自己写；参考仓库的**源码原文不进本仓库**（无 License = 保留所有权利，入库即再分发），只留链接与分析。
3. 调研文档是**过程记录**，不随实现回头重写；方案升级（如 v2→v4）时在文档头部加一行"现行以 docs\08 为准"的标注即可。
