## 二、核心结论（务必先理解这几点）

### 1. 一切问题的根因：灰度只有 1~6（信噪比物理极限）

上板抓取的 CSV 数据（`bla 1.csv` = 灰度，`whi 1.csv` = mode3 边缘）显示：

- 灰度值只有 `00000001`~`00000110`（即 1~6），这就是"灰度化基本全黑"的直接原因。
- **根因链**：暗光 → AWB 灰世界白平衡**只增益 R/B、G 通道零增益透传**（`awb.v` 中 `G_new_x1 = G_new_r1 = rgb888_g_d1[0]`）→ G 是亮度主分量，被锁死在个位数。
- **信噪比极限**：灰度 1~6 时，车牌字符边缘梯度（~5）≈ 椒盐噪声梯度（~5），后处理无法区分。手部纹理梯度（1~2）≈ 噪声，被中值+软腐蚀当噪声压掉 → 只剩大轮廓。

### 2. "边缘 vs 噪点跷跷板"是信噪比不足的必然结果

今天最终观察（换高分辨率屏后确认）：**边缘检测好时噪点明显，噪点少时边缘就差**。

这不是阈值没调对，而是信号和噪声在数值上"混在一起"，任何单一固定阈值都无法分开。**换屏只改变显示，不改变进光量，所以跷跷板仍在。**

### 3. 自适应二值化（mag >= 中心灰度）是错误方向（已回退）

上一轮曾把阈值改成 `mag >= 中心灰度`（借鉴易灵思项目）。今天用 Python 实测证明这是错的：

- 无拉伸时也会漏检：暗区 30vs50 梯度20 < 中心30；亮区 200vs220 梯度20 < 中心200。
- 易灵思 `Gmax >= matrix_p22_dly` 能 work，是因为他们用 **8 方向取最大 Gmax**（梯度幅值大）+ **正常光照**（对比度大），不是通用规律。
- **Sobel 梯度本质是"绝对灰度差"，与绝对灰度值无正比关系，不应与中心灰度比较。**
- 已回退为**固定阈值**（I_k 选档 12/16/20/24，默认 20）。

### 4. 治本只有一条路：补光

信噪比无法靠后处理提升。灰度 1~6 的根因是暗光 + AWB 不提升 G 亮度。**唯一治本是补光**，把灰度拉到 60~120，届时字符梯度（~50）>> 噪声梯度（个位数），一切迎刃而解。

## 四、核心改动文件 `image_modes4.v` 详细说明

### 当前完整链路

```
灰度化 luma（加权和 77R+150G+29B）
  → stretch（gamma 0.35 对比度拉伸，32 段分段线性）
  → 中值滤波（window4 + 9 级排序网络，3×3）
  → Sobel 梯度（|Gx|+|Gy|）
  → 固定阈值（I_k 选档，默认 20）
  → 3×3 软腐蚀（邻域边缘计数 ≥4 才保留）
  → 输出
```

### 四个模式的最终语义

| 模式 | 输出 |
|------|------|
| 0 | 原图 |
| 1 | 灰度（**已过 stretch 拉伸**）|
| 2 | 边缘强度灰度图（mag 缩放，绕开二值化阈值）|
| 3 | 边缘（固定阈值二值，黑边白底）|

### 本次新增的两个关键点

**① `stretch()` 对比度拉伸（gamma 0.35）**

```verilog
// 32 段分段线性近似 y=255*(x/255)^0.35，暗区陡峭增益
// 效果：灰度 1→10、6→57、16→97、32→123（暗区对比度放大 ~9 倍）
function [7:0] stretch; ... endfunction
```

- 目的：解决"灰度化全黑"。
- **重要副作用**：gamma 拉伸会破坏"梯度 ∝ 中心灰度"关系（拉伸后梯度/中心灰度比从 4.7 剧烈降到 0.04），所以**必须配固定阈值，不能用自适应阈值**。

**② 两级流水（修复时序违规）**

灰度化拆成两拍，避免 `awb乘法器 → luma(3乘法) → stretch(case+乘法)` 挤成 12 级长组合路径：

```verilog
// 第1拍：luma 加权和 -> luma_r
// 第2拍：stretch 查表 -> gray
// raw/valid/sof/eol 同步打一拍对齐
```
