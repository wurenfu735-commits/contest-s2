| 项      | 内容                                                           |

## 2. 算法原理（通俗）

```
灰度化 → 3×3 Sobel 求梯度 → 自适应阈值 → 双阈值迟滞 → 二值输出
 R/4+G/2+B/4    |Gx|+|Gy|      阈值随亮度走     弱边缘靠连通性
```

**两个差异点（与官方的本质不同）**：

1. **自适应阈值**：官方全图用一个固定阈值 80；我们**按局部亮度算阈值**  
   `thr = THR_FLOOR + ((mean9 × K) >> 5)`，`mean9` 是 3×3 邻域均值（`sum9 >> 3` 近似除 8）  
   → 亮区阈值抬高（抑制噪声）、暗区阈值降低（避免漏检）
2. **双阈值迟滞**：官方无后处理；我们设高低两个门限，弱边缘**只有与强边缘连通才保留**  
   → 孤立噪点消失、细边缘更连贯。**因果实现**：只看已扫描过的左/上/左上三个邻居（硬件零额外缓存）

全部用**移位与加法**实现，不引入乘法器/除法器/DSP。

### 3.2 ⚠️ 合规判断（重要）

- 上表中**除 medalotte 是 MIT**外，其余项目**均无 License**（= 默认保留所有权利）、或为 GPL-3.0（传染性）
- **结论：一律不复制任何代码**，只借鉴"模块划分、行缓存组织、验证方法"这类**公开的技术思路**
- 我们的 RTL 将**完全自写**，且算法核心（自适应阈值映射 + 因果迟滞判决）与上述任何实现都不同 → 同时满足赛题"算法不得与官方例程相同"与开源合规

### 3.3 一句话总结借鉴成果

> **学它们的"结构"，不学它们的"实现"**：灰度→梯度→判决的三段式划分、3 行缓存的容量组织、以及"用软件参考模型对拍"的验证习惯；而在算法核心上走自己的路——**自适应阈值 + 因果双阈值迟滞 + 全分辨率 + 零 DSP**。

## 4. 我们平台可行性

| 维度       | 评估                                                          | 依据                                                    |
| -------- | ----------------------------------------------------------- | ----------------------------------------------------- |
| **资源**   | ERAM 约 +3~4 块（余量 103 块）；LUT 增量 <800（当前已用 941/21216）         | 3 行 × 1280 × 8bit = 30.7 Kbit 行缓存 + 判决位 1×1280；无乘法器   |
| **时序**   | 目标 ≥74.25 MHz；当前余量 WNS 14.07 ns，压力极小                        | 全移位/加法实现，最长路径是 9 点求和与阈值比较                             |
| **接口**   | 与官方 ISP 链一致：96bit 流（4 像素 RGB888）+ tvalid/tlast/tuser/tready | 官方 `isp_top.v` 已留好算法插槽（awb 与 data_96bit_to_128bit 之间） |
| **延迟**   | 单像素约 5 拍 ≈ **67 ns**；帧延迟约 2 行 ≈ **44 µs**（远小于 16.7 ms 帧周期）  | 流水线级数：行缓存写 1 + 窗口成形 1 + Sobel 1~2 + 阈值/迟滞 1           |
| **实时性**  | 60 fps 无压力（每帧仅用约 0.3% 的时间预算处理）                              | 74.25 MHz 像素时钟，1280×720@60                            |
| **上板路径** | **先走短路**：`TPG(彩条) → 算法 → HDMI`（不经过 DDR）；摄像头链路后续接入           | P1 已有可用显示地基，按键可切换"原图/边缘图"                             |

## 6. 风险与退路

| 风险                                   | 可能性 | 退路                                                            |
| ------------------------------------ | --- | ------------------------------------------------------------- |
| 迟滞的**同拍依赖**（左邻居在同拍产生）导致建立时间紧张或需要额外寄存 | 中   | 让迟滞判决整体**延后一拍**（判决位随流水线一起走），代价是 +1 拍延迟，逻辑更干净                  |
| 逐像素比对不通过                             | 中   | 用**第一个误差像素的坐标**定位类型：集中在行首 → 边界处理；集中某几行 → 行缓存指针；散布 → 阈值位宽/移位方向 |
| 资源超预期（行缓存用 ERAM 不够）                  | 低   | 退路一：改用官方式**水平降采样**（4 像素合 2 对，行缓存减半）；退路二：灰度位宽降到 7bit           |
| 时序不收敛                                | 很低  | 在 9 点求和与阈值比较之间插流水线寄存器（当前余量 14 ns）                             |
| 上板效果不如仿真                             | 低   | 用彩条/渐变做"已知输入"复核；再用摄像头对比官方 lab_ex2 输出                          |
