# TD 综合提速方案（7 分钟 → 最快十几秒）

> 工程：`OUR_K1_4mode` ｜ 关键事实：综合 `optimize_rtl` 53s + `optimize_gate` + 布局布线（opt_place/opt_route）占大头。
> 日期：2026-10-20

---

## 一、先说清楚：7 分钟花在哪
从 `run.log` 实测：
- **综合（syn）**：`optimize_rtl` 就 53s，加上 `optimize_gate` ≈ 1.5 分钟。
- **布局布线（phy）**：`opt_place` + `opt_route` 是最大头（你的设计 70% slice、带 DDR + MIPI + HDMI，布线慢是正常的），约 4~5 分钟。
- 所以"每次 7 分钟" = 综合 + 布局布线 + 出 bit 全跑一遍。

## 二、提速方法（按"改动类型"分三种）

### 方法 1：只调参数/阈值 → 根本不用重新综合
你最近几次改动（阈值、拉伸倍数、I_k 档位）本质都是**改常量**。可以预先把这些做成**顶层可配**，烧录后按按键/拨码实时调，就不用重新出 bit：
- 阈值 `thr_base`、拉伸倍数、`I_k` 档位 → 接 `I_button` 或拨码，实时调节。
- **这是最划算的**：一次综合，无限次调参。

### 方法 2：只改 RTL 逻辑 → 用"增量综合 + 只跑 syn"
如果你只是改了 `image_modes4.v`（没动顶层端口、没动时钟/约束），可以：
1. 在 TD 里只点 **Synthesis**（`syn_1` 右键 Run），**不点** Physical Design。
2. 综合完看 `syn_1/OUR_K1_4mode_rtl.area` 确认资源，**不用布局布线**。
3. 只有确认逻辑正确、需要上板时才跑 phy 出 bit。
- 效果：7 分钟 → **~1.5 分钟**（只综合）。

### 方法 3：必须出 bit 上板 → 保底优化
布局布线不可避免，但可以：
1. **保留上次 run 结果，别 Reset**：TD 对未改动模块有增量能力，改动小的话 phy 会复用部分布局。
2. **降低布线 effort**（如果时序余量充足）：
   - 我们当前 slack +0.109ns，余量极小，**不建议**降 effort，否则可能出违例。
3. **关掉 ChipWatcher debug 采样**（如果不需要抓内部信号）：
   - `settings.cfg` 里有 `chipDebugger ../../chip_debugger` + 一堆 `mark_debug S_hdmi_out_data`。
   - **debug 采样会显著拖慢布局布线并增加资源**。如果当前阶段不需要抓内部信号，把 `mark_debug` 那行注释掉，能省不少时间。

## 三、针对你当前阶段的最优建议

你现在在**反复调边缘检测效果**，属于"改参数/小改逻辑"高频迭代期。推荐：

1. **立刻做"方法 1"**：把阈值/拉伸做成按键实时可调，一次综合后靠按键扫参数，彻底告别"改一个数等 7 分钟"。
2. **配合"方法 3 的关 debug"**：如果不再抓 `S_hdmi_out_data`，注释掉 `mark_debug`，布局布线能快 1~2 分钟。
3. **只用"方法 2"做语法/资源快速反馈**：改完 RTL 先只综合看资源，逻辑 OK 了再出 bit 上板。
