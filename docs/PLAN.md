每一层给出：**做什么 / 怎么干 / 怎么算干好 / 注意什么**。

| 层 | 内容 | 对应赛题条款 | 硬件成本 | 状态 |
|---|---|---|---|---|
| **T0** | 修 mode 4 + 补 sdc + 切自研 OSD + 加帧率/丢帧/错误计数器 + 按键改板载引脚 | 收尾 / 合规 | 省 ~2100 slice | ⏳ 做 |
| **T1** | 卡通化（颜色量化 + 边缘压黑） | 扩展① | ~500 LUT | ⬜ |
| **T2** | 颜色目标检测 + 质心跟踪 + 画框 + OSD 坐标 | 扩展② + 高阶② | ~850 LUT | ⬜ |
| **T3** | 指标上屏（帧率 / 延迟 / 模式名） | 扩展④ + 高阶①③ | ~200 LUT | ⬜ |
| **T4** | 帧差运动检测（区域框 + 计数） | 高阶④ | ~800 LUT + 1 ERAM | ⬜ |
| **T5** | 演示视频 + 技术报告 + 代码包 + 匿名检查 + 提交 | 材料 | — | ⬜ |

### 1.1 每条的四个要素

#### T0 · 收尾修复（1 天，硬前置）
- **做什么**：拿到"干净、合规、有余量"的基线。
- **怎么干**：① mode 4 拆独立模块 `edge_overlay`（原图延迟做成模块数据通路，不会被综合器优化），输出用**梯度幅值**而非纯二值；② `.al` 补 `<SDC_FILE>` 段引用 `OUR_p1_colorbar.sdc`；③ 顶层定义 `OSD_SELF_DEV` 切自研 OSD；④ 加帧率/丢帧/错误计数器；⑤ 按键从扩展口 `N2/J14` 改板载 `D5/A9/B9/C7`。
- **算干好**：mode 4 出"彩色原图 + 梯度灰阶边缘"；STA coverage 回到 ~43%；slice ~69%；Setup 余量 ≥ +600 ps；按键按得动。
- **注意**：改 `.al` 前**必须完全退出 td.exe**（含托盘）并确认 `.lock.f` 消失。

#### T1 · 卡通化（2 天）
- **做什么**：风格化/视觉增强。
- **怎么干**：复用现成边缘判决 + 3×3 中值 + RGB 量化（取高 3~4 bit）+ 边缘压黑。
- **算干好**：手绘动画风，色块平滑、边缘压黑，实时 60 fps。
- **注意**：量化位宽先在黄金模型上调好再进 RTL，别上板反复试。

#### T2 · 目标检测与跟踪（3 天，最大分值项）
- **做什么**：识别特定颜色目标、画框、OSD 报坐标、跨帧跟踪。
- **怎么干**：RGB→HSV 判色 → 形态学开运算去噪 → **网格化投影**（不是行列投影）求质心 → 画框 + 准星 + OSD 坐标。
- **算干好**：红球移动时准星咬住不飘；双目标不粘连；OSD 坐标与实际位置一致。
- **注意**：
  - ⚠️ **不要用行列投影**求质心 —— 多目标会粘连，这是已识别的重大失误。
  - ⚠️ **检测框必须与显示帧对齐** —— 检测结果要按 vsync 同步的 k 级寄存器延迟链搬到显示域（约几十个 FF），否则框会落后 1~2 帧，"跟随偏差"超标。
  - 质心用**半数法**求平均，零除法、零 DSP。

#### T3 · 指标上屏（1 天）
- **做什么**：性能可视化（帧率 / 处理延迟 / 当前算法名）。
- **怎么干**：在自研 OSD 上扩字符串区，计数器值来自 T0 加的计数器。
- **算干好**：数字稳定不跳；切换算法时数字随延迟变化。
- **注意**：延迟要真实测量（进算法到出算法的拍数 × 周期），不要写死常量。

#### T4 · 帧差运动检测（2 天，可选）
- **做什么**：硬件运动检测。
- **怎么干**：1/4 降采样 + 前帧存 1 块 ERAM + 区域框 + 计数。
- **算干好**：挥手出框并计数；静止时计数归零。
- **注意**：阈值要在黄金模型上先定，避免环境光缓慢变化导致全屏误判。

#### T5 · 材料与提交（7 天）
- 功能冻结 **10/31** → 演示视频 ≤3 min → 技术报告 ≤50 MB → 代码包 ≤100 MB → 匿名检查 → **11/3 前**提交留缓冲。

| 项目 | 数值 | 说明 |
|---|---|---|
| Slice（官方 OSD，P&R） | 16,616 / 21,216 = **78.32%** | 余 358，**做扩展前必须先切自研 OSD** |
| Slice（自研 OSD） | 14,654 = **69.07%** | 省 2,533 slice，Setup WNS 从 +0.005 ns 回到 **+0.787 ns** |
| 红线 | ≤ **82%** | 超过则不收敛风险陡增 |

| DSP | 9 / 40（剩 **31**） | 🟢 充裕，**不缺 DSP，缺 Slice** |

> **反直觉但必须记住**：网上 Sobel 工程那套"kernel 全展开成移位加法、做到 0 DSP"对我们是**负优化**——省下的 DSP 换更多 LUT，正好打在唯一短缺的 Slice 上。正确策略是**把 LUT 重的乘加往 DSP 搬**。

> ⚠️ **数据口径统一说明**：历史文档里出现过 78.76% / 78.57% / 78.32% / 77.55% 四个数字，

> 且引用时必须写明"官方 OSD / 自研 OSD"与"综合 / P&R"。

## 第二部分 · 技术路线五层（每层四要素）

### T1 通路层 —— 采集到显示的稳定链路

**要干什么**：B1 + B3。让画面稳定、连续、可测量。

**可以怎么干**：
- **保留现有**，不动结构：MIPI D-PHY → CSI 解包 → RAW10 → demosaic → awb → 算法插入点 → 96→128 → DDR 四缓冲 → hdmi_mixer → hdmi_tx
- 只补两件事：①**帧率 / 丢帧 / 错误计数器**（FIFO 溢出、MIPI 误码、坏帧回退各挂一个 32 位计数）②恢复上电自检标志

**怎么算干好**：
| 项 | 标准 |
|---|---|
| 帧率 | 60 s 计数 **3600 ± 2 帧** |
| 长稳 | 连续 30 min 无花屏、无撕裂、无卡死 |
| 光变 | 开灯/关灯/手电直照交替 **10 次**，画面不失控 |
| 拔插 | 断电拔插摄像头 3 次，均能恢复 |
| 时序 | WNS > 0 |

**注意什么**：绝不碰 DDR 133.33M 域（新逻辑只放 74.25M / 103.52M）；DDR 用长突发；MIPI 误码要有坏帧回退。

---

### T2 像素算法层 —— 自研算法 + 风格化

**要干什么**：B2（已有）+ **基础扩展① 风格化**。

**可以怎么干**：
1. **保留**：`edge_adaptive_96` 的判决体系（自适应阈值 + 因果迟滞）——这是差异化核心
2. **优化**：5×5 均值 → **3×3 中值**（保边去噪）；分段 FLOOR → **局部均值归一化** `阈值 = base + k×(局部均值 − 全局均值)`，**复用已算出的 5×5 均值窗口，零额外 ERAM**
3. **新增卡通化**：颜色量化（每通道保留高 4 bit）+ 边缘 3×3 膨胀 + 按位融合
4. **共用一套窗口生成器**：卡通化与检测都只需 3×3 邻域，共用行缓存是塞进预算的唯一办法

**怎么算干好**：
| 项 | 标准 |
|---|---|
| 卡通化 | 明显动画风：色块平滑 + 黑色描边，肉眼可辨 |
| 边缘 | 雪花肉眼减少（与 v5 位流并排对比拍照） |
| 仿真 | 与黄金模型逐像素 **0 误差** |
| 成本 | 卡通化 ≤450 slice；中值改造 ≤150 slice |

**注意什么**：不能照抄官方 Sobel（红线）；算法必须**固定延迟**（96bit 通路 `O_tready` 直通，无反压）；新逻辑只放 74.25M/103.52M 域。

---

### T3 检测识别层 —— 最大缺口，从零建

**要干什么**：**基础扩展②**（检测识别 + 叠加结果与文字）+ **高阶(2)**（跟踪 + 坐标叠加）。

**可以怎么干**（按顺序）：
1. **RGB→HSV 判色**（在 T2 侧统一转换一次，供所有算法共用）
2. **形态学开运算**去孤立噪点
3. **区域聚合：网格化投影**（8×8 或 16×16 格独立统计命中数与局部质心，相邻格合并）
   → **不要用整帧行列投影**：两个同类物体会被框成一个大框（见 `docs/24` 失误 2）
   → 有余力再升级为单遍连通域 CCL，两者特征输出接口设计成一致，升级不改上层
4. **质心 / 包围盒**：除法直接用 DSP（31 个闲置），不必做近似
5. **跟踪**：质心一阶 IIR + 最近邻 + 丢帧保持
6. **去抖**：连续 3 帧命中才确认输出
7. **★帧对齐**：检测在 103.52M 域、显示在 74.25M 域、中间隔 DDR（1~2 帧）→ 显示域用 **vsync 同步的 k 级寄存器延迟链**对齐（几十个 FF，最省）

**怎么算干好**：
| 项 | 标准 |
|---|---|
| 跟随 | 目标匀速摆动，框与边缘偏差 **≤2 px**，且不随速度增大（验证帧对齐生效） |
| 多目标 | 两个同类物体**分别成框**，不粘连 |
| 稳定 | 静止目标连续 300 帧，类别不跳变、坐标抖动峰峰 ≤2 px |
| 去抖 | 单帧噪声不产生"幽灵目标" |
| 实时 | 端到端延迟 ≤3 帧（50 ms） |
| 成本 | ≤850 slice + 2~3 ERAM |

## 一、三个重大失误（按严重度）

### 失误 1（架构级）：检测坐标与显示画面跨 DDR 未做帧对齐 🔴

**现象**：算法在 103.52 MHz 检测域产出坐标，OSD 在 74.25 MHz 显示域画框，中间隔着 DDR 四缓冲帧缓存（引入 1~2 帧延迟）。直接把坐标送去做叠加，**框会稳定落后画面 1~2 帧**——慢速移动不明显，快速移动时框明显"追不上"，演示现场会很致命。

**为什么现在就要处理**：这是**架构问题，不是调参问题**。等阶段 2 把检测做完再发现，返工的是整个数据通路。你们 mode 4 踩过的"3 拍延迟对齐"是同一问题的微缩版，跨 DDR 是帧级的更大版本。

**三种解法（按推荐度）**

| 方案 | 做法 | 成本 | 适用 |
|---|---|---|---|
| ① 帧号随行（推荐） | 坐标打上帧号，与帧数据一起过缓存；OSD 侧比较帧号一致才用 | 需占用 128bit 空余位或一条同步小 FIFO | 彻底、通用 |
| ② vsync 同步延迟链（最省） | 显示域用 k 级寄存器（k = 缓存帧数）把坐标延后 k 帧，与画面同一 vsync 释放 | 几十个 FF | 延迟固定时最省 |
| ③ 检测放在显示域之前 | 把检测挪到 DDR 之后、OSD 之前（像素域） | 改动大、且检测要重跑一遍像素流 | 不推荐 |

**验收**：目标做匀速左右摆动，框与物体边缘的偏移量应 ≤2 像素且不随速度增大；若框随速度增大而落后 → 说明没对齐。

---

### 失误 2：L4 区域层缺失，且「行列投影」多目标失效 🔴

**问题**：需求文档 §8.2 阶段 2 定的"行列投影求包围盒"，原理是对整帧做行/列方向命中计数后取非零范围——**只能给出全局包围盒**。两个同类物体分列画面两侧时，会输出一个横跨全屏的大框。

**三档替代**

| 方案 | 做法 | 成本 | 判定 |
|---|---|---|---|
| **A 网格化投影**（推荐） | 画面分 8×8 或 16×16 格，每格独立统计命中数与局部质心；相邻命中格合并成区域 | ~300–400 LUT + 极少存储（计数可放寄存器或 1 块 ERAM） | **16 天内性价比最高**，可区分多目标 |
| **B 单遍连通域 CCL** | 游程法 + 等价标签表，扫描中同时累积面积/质心/包围盒/几何矩 | ~800–1200 LUT + 1–2 ERAM | 正解，任意形状；有余力再做 |
| C 保持行列投影 | 只演示单目标，报告如实声明限制 | 0 | 兜底；分低、风险高 |

**建议**：阶段 2 直接上 **A**；若 10/26 前有余力再升级 B（B 与 A 的特征输出接口可以设计成一致，升级不改上层）。

---

### 失误 3：残雪的处置层级错了 🔴

**问题**：一直在 **L3 的结果端调阈值地板**（v5 把暗区地板 192→144，反而低于真实噪声梯度 → 上板雪花回潮）。而根因在两个更上游的位置：

- **L2**：噪声从这里进入，且 awb 增益把暗场噪声放大
- **L3**：用 5×5 均值滤波去噪——**均值滤波在平滑噪声的同时模糊边缘，与边缘检测的目标自相矛盾**

**正确的三层处置**

| 层 | 改法 | 成本 |
|---|---|---|
| L2 | **暗区增益限幅**：暗像素不放大增益，直接掐断噪声被放大的路径 | ~100 LUT |
| L3 | **5×5 均值 → 3×3 中值**：保边去噪，对脉冲噪声（雪花正是脉冲型）是正规军，成本与均值相近 | 复用现有行缓存 |
| L3 | **分段 FLOOR → 局部均值归一化**：`阈值 = base + k×(局部均值 − 全局均值)`，或 `梯度/局部均值` 归一化。**复用已经算出来的 5×5 均值窗口，零额外 ERAM** | 几乎 0 |

**判定**：继续调分段地板已被 v5 证伪，应停止。Sauvola（局部方差）理论更对，但 16 天内实现+验证+时序收敛成本过高，**列为有余力项**。现场补光是零成本兜底。

|---|---|---|
| 5×5 均值 → **3×3 中值** | 保边去噪 | 成本相近 |
| 分段 FLOOR → **局部均值归一化** | 复用已有均值窗口 | 零额外 ERAM |
| **闲置的 31 个 DSP 要用起来** | HSV 的 max/min 与除法、质心除法、坐标缩放、幅值 sqrt | 与你们"缺 slice 不缺 DSP"的判断一致——**用 DSP 换紧缺的 slice** 是正确方向，要落实到具体算子 |
| 保持无反压 | 维持固定延迟 | 96bit 通路 `O_tready` 直通，绝不能引入不确定停顿 |

### L4 区域级分析层（从无到有）

推荐 **网格化投影**，输出统一特征接口（便于后续升级 CCL）：
```
每帧输出：区域数 + 每区域的 { 包围盒 x0,y0,x1,y1 / 面积 / 质心 cx,cy / 平均色相 }
```
质心除法**直接用 DSP**（有 31 个闲置），不必做"半数法"近似，精度更高、LUT 更省。

### L5 目标级识别层（从无到有）

| 能力 | 做法 |
|---|---|
| 分类 | 平均色相 + 填充率（面积/包围盒面积）+ 长宽比；先用规则判据，不急于上分类器 |
| 跟踪 | 质心一阶 IIR 平滑 + 最近邻关联 + 丢帧保持 N 帧 |
| 去抖 | 连续 3 帧命中才确认输出，避免单帧噪声产生"幽灵目标" |

### L6 呈现与交互层

| 项 | 更优替代 |
|---|---|
| **统一数值通道** | OSD 做一个通用"数值渲染区"，帧率/延迟/坐标/计数都通过同一接口写入——现在加一个指标不用改结构 |
| 自研 OSD | 已有掩膜+描边+半透明，优于官方整像素替换，**尽快切换** |
| 外部控制 | 以太网/串口（远程）+ 蜂鸣器/数码管（本地）双保险 |
| Logo | 位置参数化，便于缩到 96×32 应急 |

### 贯穿层

| 项 | 说明 |
|---|---|
| 补 `<SDC_FILE>` | STA 覆盖 21% → ~43% |
| **帧率/丢帧/错误计数器提前做** | 别等阶段 3——稳定性测试（评分第 4 条）就要用它，且是答辩唯一可信的量化证据 |

## 三、最需要警惕的一点：Sobel 红线

赛题红线：**作品的图像处理算法不得与参考例程相同**。

- 官方 `lab_ex2` = 灰度化 → **Sobel**（\|Gx\|+\|Gy\|）→ 固定阈值 80 → 多数表决
- 你们 = 灰度化 → **梯度** → 自适应阈值 + 分段 FLOOR + 因果迟滞

**风险在哪**：梯度算子这一层与官方是同一类（甚至 mode 1「官方判决」还显式复用同一套前端）。评委追问"你们的算子是不是 Sobel"时，只答"阈值机制是我们自研的"是不够稳的——**算子相同 + 判决不同，属于灰色地带**。

**三条应对（按成本排序）**：

1. **口径统一 + 提前准备话术**（零成本，今天就做）
   把算法描述统一为"**均值梯度（非标准 Sobel 卷积核）**"，核心创新点表述为"**亮度自适应的分段地板阈值 + 因果双阈值迟滞**"。报告里画一张"官方 vs 我们"的差异表，把差异落在**判决体系**上，而不是声称算子不同（声称了容易被拆穿）。
2. **尽快上两种与 Sobel 完全无关的算法**（这是最有效的稀释）
   卡通化（颜色量化 + 边缘压黑）与颜色目标检测（HSV 判色 + 投影定位）**都不含梯度算子**。当作品里有 3 种算法、其中 2 种与梯度无关时，"算法雷同"的质疑自然消解。
3. **准备一页对比实验**（已有素材）
   "官方固定阈值对弱边缘漏检 352/352、我们漏检 0"——这是差异化最硬的证据，务必进报告和视频。
