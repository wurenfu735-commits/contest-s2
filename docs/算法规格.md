## 0. 现行规格速览（改算法前必读这一节）

### 0.1 算子真名（别再叫错）

```
S1 = sum25(x+1, r0..r4)      // 中心右移 1 列的 5×5 盒式均值（×25，未除）
S2 = sum25(x-1, r0..r4)      // 中心左移 1 列
S3 = sum25(x,   r0..r4)      // 中心（上 5 行）
S4 = sum25(x,   r2..r6)      // 中心（下 5 行）
mag = |S1 - S2| + |S3 - S4|
```

- 等效核：**Gx ≈ 5×7、Gy ≈ 7×5**（两个相距 2 像素的 5×5 盒式均值之差）
- 正式叫法：**"5×5 盒式平滑 + 基线 2 中心差分"的可分离平滑梯度**
- **不是 Sobel、不是 Roberts、不是 Scharr** —— 与官方例程的 3×3 Sobel **不同族**，红线无虞
- 判决锚像素 `(4n+i, y-3)`，**总延迟 3 拍**（官方 `edge_detect_96` 是 1 拍，因为官方降采样到 640）

### 0.2 阈值（v5 四段自适应地板）

```
mean25 = S3 >> 4
thr = FLOOR_分段(mean25) + ((mean25 * K) >> 5)

mean25 <  64（灰度 <41）    → FLOOR + 48   = 144
64 ≤ mean25 < 128（41~82）  → FLOOR + 36   = 132
128 ≤ mean25 < 192（82~123）→ FLOOR + 20   = 116
mean25 ≥ 192（≥123）        → FLOOR + 0    =  96
```
基准 `THR_FLOOR = 96`。四个偏移量已参数化（`THR_ADD_D0..D3`），回到 v4 行为改回 `96/64/32/0`。
改完**必须跑 `tools/check_thr_consistency.py`** 确认 RTL 与黄金模型四档地板一致。

### 0.3 尺度换算（调参必备）

- 竖直阶跃：只有水平项贡献 → **mag = 10 × Δ**（45° 斜边最强约 20 × Δ）
- 故"理想无噪声下的硬门槛" **Δmin = thr / 10**（斜边约 thr / 20）
- 暗场（mean≈32、σ=4）实测检出率：

| 版本 | Δ=8 | Δ=10 | Δ=12 | 平坦区虚警 |
|---|---|---|---|---|
| v4（192/160/128/96） | 1.1% | 27.2% | 89.9% | 0.00% |
| **v5（现行 144/132/116/96）** | **44.6%** | **95.9%** | **99.8%** | **0.00%** |
| 曲线 D（更激进） | 76.3% | 98.6% | 99.9% | 0.00%（σ=6 时 1.05%） |

### 0.4 资源

LUT ~3200 · FF ~650 · ERAM ~30（6×4 + 判决） · **DSP 0**

### 0.5 与官方例程的差异（答辩口径）

| | 官方 `edge_detect_96` | 我们 |
|---|---|---|
| 分辨率 | 降采样 640 | **全 1280** |
| 算子 | 3×3 Sobel | 等效 5×7 平滑梯度 |
| 阈值 | 固定 80 | **四段自适应地板** |
| 后处理 | 无 | **因果双阈值迟滞** |
| 输出 | 二值 | 二值 / 梯度灰阶 / 四态可切 |

## 1. 算子选型结论（不要再纠结换算子）

**结论：默认算子不动，不用 Scharr 替换。**

归一到同一阶跃响应后的对比：

| 算子 | 阶跃响应 | 噪声 E[\|Gx\|+\|Gy\|] | 等效 SNR |
|---|---|---|---|
| **现行 v5（5×7 平滑梯度）** | 10Δ | ≈10.6 σ | **0.945 Δ/σ** |
| 裸 3×3 Scharr（/16 归一） | 1.0Δ | ≈1.53 σ | 0.653 Δ/σ |

→ Scharr 的 SNR 只有现行的 **0.69×（降约 31%）**。
暗区裕度本来就薄（噪声梯度幅度 ≈106 vs 阈值 144，仅 **1.36×**），换 Scharr 会把残雪推过阈值，**与治雪花目标相反**。

- 要 Scharr 的各向同性，正确做法是"5×5 平滑后再做 3×3 Scharr"（等效 7×7），但每像素要多算 4 个 5×5 和 → 4 像素并行多 16 个 `s25_of`，约 **+600~1000 LUT**，在只剩 ~2300 slice 时**不划算**。
- **幅值保持 `|Gx|+|Gy|`**，不用 `sqrt`（视觉差异极小）。31 个闲置 DSP 留给质心除法与 HSV 转换。

### 1.1 雪花（暗区噪声）治理路线

| 层 | 措施 | 成本 | 性质 |
|---|---|---|---|
| L2（ISP） | **暗区 AWB 增益限幅** —— 噪声是被 awb 增益放大的，源头掐掉 | 近 0 | **治本** |
| L3（算法） | **行列可分离 3 抽头中值**（不是全 3×3 中值） | ~150–250 LUT | 治标 |
| — | 全 3×3 中值（4 像素并行需 4 套 9 元排序网络） | 600–900 LUT | ❌ 不划算 |

### 1.2 "多算法切换"（高阶①）用什么凑

| 算法 | 说明 | 成本 |
|---|---|---|
| A（默认） | 现行 5×5 平滑梯度（弱边缘 / 暗区） | 已付 |
| B | **3×3 形态学梯度（膨胀−腐蚀）** —— 结构完全不像 Sobel、边缘粗、抗噪好、无乘法无新 ERAM | ~200–400 LUT |
| C | 卡通化（扩展①，与检测分开） | ~500 LUT |
| D（可选） | NMS 细边缘模式 —— 做成 A 的一个开关，不单占通路 | ~300–500 LUT |

> NMS **不设为默认**：单像素细线在 720p 观看距离下反而不明显，且会削弱"弱边缘能检出"这个核心卖点。

### 1.3 答辩话术

> 我们没有搬教科书算子，而是按本传感器在暗区的噪声特性设计的：**5×5 盒式平滑 + 基线 2 中心差分的等效 5×7 可分离梯度**，配**四段自适应地板**与**因果双阈值迟滞**。相比官方 Sobel + 固定阈值 80，暗场 Δ=10 的弱边检出率从 27.2% 提到 95.9%，平坦区虚警仍为 0。

被追问"为什么不用 Scharr/Sobel"：
> 3×3 算子支持度太小，在同等信号响应下 SNR 比我们低约 31%，而暗区剩余雪花恰恰卡在阈值边缘。我们把支持度做进算子，而不是在后面加滤波补窟窿。

## 0. 与官方算法对比（红线合规说明）

| 环节 | 官方 lab_ex2（`edge_detect_96.v`） | 我们 v4 | 是否构成"不同算法" |
|---|---|---|---|
| 灰度化 | `R/4 + G/2 + B/4`（移位近似） | 相同 | 灰度是通用前处理，不算核心 |
| 分辨率 | 每 4 像素合 2 对（**水平降采样到 640**） | **不做降采样，全分辨率 1280**（4 像素/拍） | ✅ 不同 |
| 去噪 | 无 | **5×5 均值去噪**（窗口 10 列×7 行） | ✅ 不同 |
| 梯度 | Sobel `\|Gx\|+\|Gy\|` | **均值梯度** `\|S1−S2\|+\|S3−S4\|`（5×5 和之差） | ✅ 不同 |
| **阈值判决** | **固定阈值 80**（全图一个值） | **分段 FLOOR + 亮度项**（thr = 基准 FLOOR + 分段增量 + mean25×K>>5） | ✅ **核心差异** |
| **后处理** | 无 | **因果双阈值迟滞**（弱边缘需与强边缘连通才保留） | ✅ **核心差异** |
| 输出 | 二值（边缘白/非边缘黑） | 相同格式 + **四态可切**（原图/官方/我们/左右分屏） | ✅ 不同 |

**结论**：去噪、梯度、阈值机制、后处理、分辨率处理均与官方不同 → 满足"算法不得与参考例程相同"。
⚠️ **待办（如实）**：官方对比态用的 `OFFICIAL_THR` 参数仍是 80（Sobel 时代的量级），**未按 v4 梯度量级重新标定**（见 1.6）。

## 1. 算法定义（流式、因果，可被 RTL 实现）

> 关键设计原则：**算法必须"因果流式"**——每个输出像素只依赖"当前像素 + 已流过的邻域"，不能依赖未来像素。这样黄金模型与 RTL 才能**逐像素完全一致**。

### 1.1 灰度化（与 RTL 位运算逐位一致）
```
gray = (R >> 2) + (G >> 1) + (B >> 2)      // 范围 0..253，无溢出
```
（R/G/B 各 8bit；该近似与官方相同，硬件成本为零）

### 1.2 总体结构与锚点
- **吞吐**：96bit = 4 像素 RGB888/拍，全分辨率 1280×720。
- **行缓存**：6 块灰度行缓存（line1..6 = 上一行..上六行）+ 1 块判决行缓存，均为 32bit 字宽的 `blk_mem_gen_zhenghe` 块 RAM（下沉链同址读旧值，数据不搬移）。
- **窗口**：10 列 × 7 行（列 4n−3..4n+6，行 y−6..y；n 为 4 像素组的组号）。
- **判决锚像素**：`(4n+i, y−3)`，即四个输出像素各自对齐窗口中心行。
- **总延迟**：3 拍。

### 1.3 5×5 均值去噪 + 均值梯度
每个像素算 4 个 5×5 和（S1..S4），再取差得梯度幅值：
```
S1 = sum25(x+1, y-4..y)     S2 = sum25(x-1, y-4..y)   // 水平差
S3 = sum25(x  , y-4..y)     S4 = sum25(x  , y-6..y-2) // 垂直差
mag = |S1 - S2| + |S3 - S4|    // ≤ 2×12750 → 16 bit
```
语义：5×5 求和本身就是**均值**（去噪），相邻均值之差即**均值梯度**——一次求和同时服务两件事。
硬件实现用"5 列滑动和 × 7 行"的 separable 组织（先横向 5 列和，再纵向 5 行组合；与调研 R3 的分辨率一致）。
**5×5 的取舍**（v3 上板结论）：核从 3×3 扩到 5×5 后，真实台阶边界的梯度幅度比噪声梯度涨得快（信噪比翻倍），
允许把阈值地板抬高挡住残雪、边缘仍有十余倍余量；代价是弱纹理（台阶 3）会丢——"干净 > 细腻"，综合效果最好。

### 1.4 自适应阈值 v5：分段 FLOOR + 亮度项
```
thr    = FLOOR_基准 + 分段增量 + ((mean25 * K) >> 5)
mean25 = S3 >> 4          // ≈ S3/16；工程近似：mean25 只做"亮度坡度"项，绝对地板靠 FLOOR
```
**基准 FLOOR**：`THR_FLOOR` 参数，**模块默认 96**（亮区合成地板）；`isp_top.v` 与 tb 均显式传 96，三处一致。

**分段增量**（按 mean25 分段；括号内为换算回画面亮度的分界）：

| mean25 | 分段参数 | v5 增量 | v5 地板 | v4 增量/地板 | 区段语义 |
|---|---|---|---|---|---|
| < 64（画面灰度 <41） | `THR_ADD_D0` | +48 | **144** | +96 / 192 | 暗区 |
| 64..127（灰度 41–82） | `THR_ADD_D1` | +36 | **132** | +64 / 160 | 中暗 |
| 128..191（灰度 82–123） | `THR_ADD_D2` | +20 | **116** | +32 / 128 | 中亮 |
| ≥ 192（灰度 ≥123） | `THR_ADD_D3` | +0 | **96** | +0 / 96 | 亮区：保细节 |

> **v5 变更（2026-10-18）**：v4 的暗区地板 192 使"竖直阶跃最小可检对比度 Δmin = thr/10 ≈ 19.2 灰度级"，是亮区（96→9.6）的 **2 倍**；而暗场景的对比度本来就小。实测暗场（mean≈32、σ=4）Δ=8 的边只检出 **1.1%**，Δ=10 仅 **27.2%**，平坦区虚警却是 0.00% —— 工作点严重失衡。下调到 144/132/116/96 后同场景 Δ=8 检出 **44.6%**、Δ=10 **95.9%**，虚警仍 0.00%。完整数据与调参指引见 [`archive/19_暗区边缘优化.md`](archive/19_暗区边缘优化.md)。
>
> 四个增量已参数化，**回到 v4 行为只需把 D0/D1/D2 改回 96/64/32**，逻辑不用动。
> 改完必须跑 `tools/check_thr_consistency.py` 确认 RTL 与黄金模型四档一致（不一致 tb 必然失配）。

**物理依据**：散粒噪声随亮度上升、**信噪比随亮度改善** → 暗处最吵、地板较高；亮处干净、地板低。
（v1 曾写反——暗处门槛最低 → 满屏雪花；v4 修正方向，但抬得过高；v5 按实测把幅度调回来。分段值由 `gen_golden_v4.py` 的 `section_floor` 与 RTL 逐字一致。）

**亮度项**：K = `I_k`（0..3 档），`(mean25×K)>>5` 用**移位 + 加法**实现，不占 DSP。
（v2/v3 时代的单纯 `FLOOR + mean×K/32` 是 v4 的分段函数在"单调递增地板"思想下的前身。）

### 1.5 因果双阈值迟滞
```
s = mag >= thr                        // 强边缘
w = mag >= (thr >> 1)                 // 弱边缘（thr 已包含分段地板）
e = s | (w & (左邻已判边 | 上邻 up | 左上 upleft))   // 弱边缘靠连通性保留
```
**因果实现**：左邻 = 同组上一像素 `e_{i-1}`（组内链 e0→e1→e2→e3），跨组左邻 = 上一组 `e3`（一拍寄存）；
上/左上邻来自判决行缓存（1 块，32bit 字只占 4bit）。弱边缘只看**已经处理过的 3 个邻居**——流式扫描的自然顺序，无帧缓存。
效果：**孤立噪点消失**（四周无强边缘支撑），**细边缘更连贯**（弱边缘被强边缘"带出来"）。

### 1.6 四态输出（I_mode）
| I_mode | 态 | 判定 |
|---|---|---|
| 0 | 原图直通 | 在 **isp_top 层**做（mux 选 awb 原始 96bit，不经本模块） |
| 1 | 官方判决 | `mag >= OFFICIAL_THR`（参数，现为 12'd80） |
| 2 | 我们的判决 | 1.3–1.5 的 e |
| 3 | 左右分屏 | 左半屏（out_col < 640）官方判决，右半屏我们的判决 |

输出：边缘 → `24'hFFFFFF`（白）；非边缘 → `24'h000000`（黑）。
⚠️ **待办（如实）**：`OFFICIAL_THR` 未按 v4 的 mag 量级重标定——目前分屏对比只表示"两套判决机制的形态差异"，
不能引用为定量对比结论；重标定前不以"官方漏检 X%"作为 v4 的结果话术。

## 4. 接口（插入官方 ISP 链，即插即用）

```
module edge_adaptive_96 #(
    parameter IMG_WIDTH   = 1280,
    parameter IMG_HEIGHT  = 720,
    parameter [10:0] THR_FLOOR    = 11'd96,   // 亮区合成地板基准（v5：四档 = 144/132/116/96）
    parameter [9:0]  THR_ADD_D0   = 10'd48,   // 暗区  增量 → 144
    parameter [9:0]  THR_ADD_D1   = 10'd36,   // 中暗  增量 → 132
    parameter [9:0]  THR_ADD_D2   = 10'd20,   // 中亮  增量 → 116
    parameter [9:0]  THR_ADD_D3   = 10'd0,    // 亮区  增量 → 96
    parameter [11:0] OFFICIAL_THR = 12'd80    // ⚠️ 待按 v4 量级重标定
)(
    input  wire        I_clk, I_rst_n,
    input  wire [1:0]  I_mode,               // 四态选择（0=原图在 isp_top 层做）
    input  wire [1:0]  I_k,                  // 亮度灵敏度档 0..3
    input  wire        I_tlast, I_tuser,
    input  wire [95:0] I_tdata,              // 4 像素 RGB888：[95:72]=第1个 … [23:0]=第4个
    input  wire        I_tvalid,
    output wire        I_tready,             // 直通下游 O_tready（无反压）
    output reg         O_tlast, O_tuser,
    output reg  [95:0] O_tdata,
    output reg         O_tvalid,
    input  wire        O_tready
);
```

# 19 暗区边缘优化（v4 → v5）

> 触发问题：**"边缘检测稍微暗一点的环境容易检测不出来。"**
> 结论：**这不是错觉，是阈值函数的定量缺陷。v4 在暗区把门槛定成了亮区的 2 倍，Δ≤10 灰度级的弱边基本全丢。**
> 改动：暗区分段地板 192 → 144（另外三档同步下调），四个偏移量参数化。
> 证据：`tools/analyze_dark_threshold.py`（复现判决数学的扫描脚本）+ `tools/gen_golden_v4.py` 新增场景 C/D。

---

## 一、先把"为什么暗就看不见"算清楚

本模块的梯度算子（`edge_adaptive_96.v`）：

```
mag = |S1 - S2| + |S3 - S4|      S1..S4 都是 5×5 求和
```

对**竖直阶跃**（Δ = 两侧灰度差），只有水平项贡献，且 5 行累加：

```
mag = 2Δ × 5 = 10Δ
```

脚本实测验证（无噪声）：

| Δ | mag 峰值 |
|---|---|
| 4 | 40 |
| 8 | 80 |
| 10 | 100 |
| 20 | 200 |

于是**最小可检对比度**就是：

```
Δmin = thr / 10
```

代入 v4 的分段地板：

| 区域 | 灰度范围 | v4 地板 | Δmin（理想无噪声硬门槛） |
|---|---|---|---|
| 暗区 | < 41 | **192** | **≈ 19.2 灰度级** |
| 次暗 | 41–82 | 160 | 16.0 |
| 中 | 82–123 | 128 | 12.8 |
| 亮区 | ≥ 123 | 96 | 9.6 |

> 注：Δmin 是"理想无噪声下的硬门槛"。实际因为噪声 + 迟滞，低于 Δmin 的边也有一定检出率（见下节实测）。45° 斜边两个方向项都贡献，mag 最强约 20Δ，门槛减半。

**问题一目了然：暗区需要的对比度是亮区的 2 倍，而暗场景本身的对比度恰恰更小。** 两头夹击，所以"稍微暗一点就看不见"。

v4 当初把暗区地板抬高，理由是"暗区噪声大、压噪优先"。方向不算错，但**抬得太狠，且没有实测依据**——它是"保守物理初值"（见 `gen_golden_v4.py` 原注释）。

## 三、改了什么

### 3.1 `rtl/edge_adaptive_96.v`（v4 → v5）

把写死的四档偏移量换成 4 个参数，默认值改为曲线 C：

```verilog
parameter [10:0] THR_FLOOR  = 11'd96,   // 亮区地板 = THR_FLOOR + THR_ADD_D3
parameter [9:0]  THR_ADD_D0 = 10'd48,   // 暗区   → 144
parameter [9:0]  THR_ADD_D1 = 10'd36,   // 次暗   → 132
parameter [9:0]  THR_ADD_D2 = 10'd20,   // 中     → 116
parameter [9:0]  THR_ADD_D3 = 10'd0,    // 亮区   → 96
```

**结构零改动**：`thr_calc` 里原来的 `THR_FLOOR + 11'd96` 只是换成 `THR_FLOOR + THR_ADD_D0`，比较器/加法器数量不变，流水级数不变，时序影响应在噪声范围内。

**回滚只需一个参数**：想退回 v4，把 `THR_ADD_D0/D1/D2` 改回 `96/64/32` 即可，不用改逻辑。

### 3.2 `tools/gen_golden_v4.py`（黄金模型，必须同步）

`section_floor` 同步为 144/132/116/96，并在文件头写明与 RTL 参数的换算关系。**两边不同步，tb 比对必然失配。**

同时修了一处**换机器就跑不起来**的问题：原来输出路径写死成 `E:\fpga\contest_s2\sim\tb96\golden_out.txt`（另一台机器的路径），现改为按脚本位置推导。

### 3.3 `src/p1_colorbar/tools/run_tb_96.ps1`

同样修掉硬编码：`$ROOT` 改为按脚本位置推导；`$MS`（ModelSim）和 `$PY` 支持用环境变量 `MODELSIM_BIN` / `PYTHON_EXE` 覆盖，找不到 ModelSim 时给出明确提示而不是报一串找不到文件的错。

## 四、为什么这个缺陷能一路通过测试（重要教训）

**现有测试根本没有覆盖"暗场 + 弱对比"这一档。**

| 场景 | 图案 | 覆盖了什么 |
|---|---|---|
| 场景 A | 亮区锯齿 + 暗区（**对比度 0**）+ 高亮段 + ±3 噪声 | 暗区平坦性（会不会冒雪花） |
| 场景 B | 亮背景 120 + 台阶 **14** | 亮区弱边 |

场景 A 的暗区是**完全平坦**的（只测虚警），场景 B 是**亮背景**（只测亮区灵敏度）。**"暗背景 + 小台阶"这个组合一次都没测过**——而这正是现场最容易遇到的画面。

v5 在黄金模型里补了两个场景：

```
场景C 暗场低对比 无噪声：检出 0/48   ← 恒为 0 属正常
场景D 暗场低对比(背景40/台阶8/±10噪声)：
  v4  192/160/128/96  检出 11/48 = 22.9%
  v5  144/132/116/96  检出 33/48 = 68.8%
```

场景 C 恒为 0 不是 bug，是一个值得知道的设计性质：**因果迟滞没有"强边种子"时不会点亮弱边**。所以纯无噪声的理想弱边反而检不出，必须靠噪声提供种子。这也说明"靠阈值单参数"永远做不出理想的弱边检测——真正的下一步是加空间累积（见第六节）。

## 七、如果调阈值还不够：下一步（按性价比）

阈值只能在"漏检"和"虚警"之间挪，**不能提高信噪比**。真正能提高暗区 SNR 的只有两条：

1. **加大空间平均（★★★★）**
   对一维阶跃边，5×5 求和的信号 ∝ 窗口宽 W，噪声 ∝ √W → **SNR ∝ √W**。5×5 → 7×7 提升 18%，→ 9×9 提升 34%。
   代价：行缓存从 7 行扩到 9/11 行（ERAM 还有 45 块，放得下），面积增加中等。
   参考：`LewisLiuLiuLiu/logikbench` 的 `sobel3x3` 与 `redpower1998/fpga_image` 的 `mean9x9` 都是同一种窗口复用写法。

2. **时域平均（★★★）**
   两帧平均噪声降 1/√2，SNR +41%。DDR 里已有帧缓存，但要改读写时序，架构改动大，**建议扩展功能做完后再考虑**。

3. **连通域后处理（★★★★，但属另一个模块）**
   现在的迟滞只是"左邻 + 上邻"的因果一维传播，很弱。改成小连通域标记可让断掉的弱边连起来。这是 `docs/16` 路线 C 的一部分。

> 判断：**先把阈值调到现场可接受，然后去做扩展项**（扩展现在是 0/2 + 0/5，才是真正的失分点，见 `docs/18`）。7×7 窗口留到扩展做完、资源有余量时再动。

# 26 · 边缘检测算法选型：谱系对比与推荐

> 用途：回答"边缘检测有哪些算法、我们该用哪个"，并作为答辩时"为什么不用 Sobel / 为什么不用 Canny"的依据。
> 约束来源：`需求文档.md` §1（资源与时钟域）· `docs/24`（体检）· `docs/25`（落地书）

## 一、我们的硬约束（选型前先看这个）

| 约束 | 值 | 对选型的影响 |
|---|---|---|
| 数据形态 | 96bit = 4 像素/拍、全 1280、无降采样 | 必须是**流式、固定延迟**的算子，不能反复遍历帧 |
| 反压 | `O_tready` 直通，**无反压** | 算子延迟必须是常数，不能有不确定停顿 |
| 瓶颈资源 | **Slice 78.6%（自研 OSD 后 ~69%，预算约 2300）** | 优先选零/低 LUT 增量的方案 |
| 闲置资源 | DSP 31 个、ERAM 余 48 | 可用 DSP 换 slice，但**不值得为边缘算子开 ERAM** |
| 时序 | WNS +101 ps（自研 OSD 后 +787 ps） | 每加一级都要跑时序报告 |
| **红线** | 官方 lab_ex2 = 灰度 → **Sobel** → 固定阈值 80 | **算子不能与 Sobel 相同** |
| 痛点 | 暗区残留雪花（噪声被 awb 增益放大） | 选型必须**抗噪**，二阶算子直接出局 |

## 二、算法谱系与成本（按 4 像素并行的实测口径估算）

| 族 | 算法 | 核 / 原理 | LUT 量级 | 抗噪 | 与官方差异 | 结论 |
|---|---|---|---|---|---|---|
| 一阶梯度 | Roberts | 2×2 对角差分 | 极低 | 差 | 不同 | ❌ 太糙 |
| | **Sobel** | [1 2 1] ⊗ [1 0 −1] | 低 | 中 | **官方就是这个** | ❌ 红线 |
| | Prewitt | [1 1 1] 不加权 | 低 | 中 | 仅权重微调 | ❌ 说服力弱 |
| | **Scharr** | **[3 10 3]** | 与 Sobel 相同 | 中 | ✅ 核不同 | ⚠️ 见 §八修正 |
| | **5×5 盒式均值差分** | 等效 5×7/7×5 平滑梯度 | 中（已付） | **好** | ✅ 完全不同 | ✅ **你们 v5 现用，保留** |
| 二阶 | Laplacian | 二阶导、零交叉 | 低 | **极差** | 不同 | ❌ 放大噪声 |
| | LoG / DoG | 高斯 + 拉普拉斯 | 中（5×5+） | 好 | 不同 | ❌ 成本高于收益 |
| 多阶段 | **Canny** | 高斯→梯度→**NMS**→双阈值迟滞 | 中高 | 好 | 不同 | ⚠️ 见第四节 |
| 自适应阈值 | Otsu | 全局直方图类间方差 | 中（256 bin ERAM + 除法） | 对整体明暗有效 | — | ❌ 不治光照不均 |
| | **局部均值归一化** | 阈值随局部亮度变化 | **复用现成均值窗口** | 好 | — | ✅ **推荐** |
| | Sauvola / Niblack | 局部均值 + 标准差 | 中高（平方 + 开方） | 最好 | — | ❌ 16 天内不划算 |
| | Bradley（积分图） | 积分图 O(1) 窗口和 | 中（行积分缓冲） | 好 | — | ⚠️ 备选 |
| 形态学 | **形态学梯度** | 膨胀 − 腐蚀（3×3 max/min） | 低 | **好** | ✅ 完全不像 Sobel | ✅ **建议作为第三算法** |
| 学习类 | HED / CNN 边缘 | 网络推理 | 极高 | 好 | 不同 | ❌ 40 DSP 做不了 |

## 三、推荐方案（草案，已被 §八 修正，以 §八 为准）

> ⚠️ **本节结论已按实际 RTL 复核后被推翻**，保留仅作推理记录。**直接看 §八**。

### 原草案：Scharr + 局部均值归一化 + 因果迟滞 + 中值前置

```
3×3 中值 → Scharr 梯度 → 局部均值归一化阈值 → 因果双阈值迟滞 → 二值边缘输出
```

| 级 | 作用 | 成本 | 说明 |
|---|---|---|---|
| 3×3 中值 | 保边去噪，**治雪花** | 复用行缓存 | 中值是脉冲噪声的正规军；均值滤波会模糊边缘，与检测目标相悖 |
| Scharr [3 10 3] | 梯度 | **与 Sobel 完全相同** | 旋转对称性远好于 Sobel；移位加法实现（3=2+1、10=8+2），**0 DSP** |
| 局部均值归一化 | 自适应阈值 | **零额外 ERAM** | `阈值 = base + k×(局部均值 − 全局均值)`，复用已算出的 5×5 均值窗口 |
| 因果双阈值迟滞 | 边缘连接、抑制断裂 | 已验证，**保留不动** | 这是相对官方"固定阈值"的核心差异，别动 |
| 二值输出 | — | 固定延迟 | 保持无反压 |

**收益总结**：几乎零增量成本，同时做到 ①与 Sobel 结构性不同 ②抗噪更强 ③抗光照不均 ④保留已验证的判决体系。

## 四、关于 Canny / NMS 的取舍

**你们的因果迟滞已经是 Canny 的核心步骤之一**，只差非极大值抑制（NMS）。但不建议作为默认路径：

| 理由 | 说明 |
|---|---|
| 演示效果反而变差 | NMS 把边缘压成单像素细线，720p 观看距离下**更不明显** |
| 削弱核心卖点 | 你们的卖点是"弱边缘能检出"（官方漏检 352/352、你们 0），细线会弱化这个对比 |
| 成本 | +300~500 LUT（方向量化 + 邻域比较），而预算只剩约 2300 slice，还有 T3 检测要塞 |

**建议**：做成**可切换模式**（粗边缘 / 细边缘），对比演示本身就是高阶(1) 的加分素材，但不设为默认。

## 八、复核修正（读 `src/p1_colorbar/rtl/edge_adaptive_96.v` 后推翻 §三）

### 8.1 你们现在用的其实不是"Sobel 类"，别自己吓自己

源码 `S1=sum25(x+1,r0..r4)  S2=sum25(x-1,r0..r4)  S3=sum25(x,r0..r4)  S4=sum25(x,r2..r6)`，
`mag = |S1−S2| + |S3−S4|`。展开成等效卷积核：

- `Gx` = 两个中心相距 2 列的 5×5 盒式均值之差 → 行向盒 5 列、列向 `[-1,-1,0,0,0,+1,+1]`，**等效 5×7**
- `Gy` = 两个中心相距 2 行的 5×5 盒式均值之差 → **等效 7×5**
- 判决锚像素 `(4n+i, y−3)`，总延迟 3 拍

即：**"5×5 盒式平滑 + 基线 2 中心差分"，等效支持度 5×7 / 7×5**。这和官方 3×3 Sobel 是**不同族**的东西
（官方：降采样 640 + 固定阈值 80 + 无后处理；我们：全 1280 + 平滑梯度 + 分段 FLOOR + 因果迟滞 + 四态可切）。
**红线无虞，不需要为了"避开 Sobel"去换算子。**

### 8.2 关键量化：换成裸 3×3 Scharr 会让雪花更严重

把两个算子都归一到"同一个阶跃 Δ 的信号响应"再比噪声（σ_g 为进入算子前的灰度噪声）：

| 算子 | 阶跃响应 | 噪声 E[\|Gx\|+\|Gy\|] | 等效 SNR |
|---|---|---|---|
| 现 v5（5×7 平滑梯度） | **10Δ** | ≈ 10.6 σ_g | **0.945 Δ/σ_g** |
| 裸 3×3 Scharr（/16 归一） | 1.0Δ | ≈ 1.53 σ_g | **0.653 Δ/σ_g** |

→ **Scharr 的 SNR 只有现算子的 ~0.69×，下降约 31%。**

而你们暗区的裕度本来就很薄（文件头自述：噪声梯度幅度 ≈106，v5 暗区阈值 144，**仅 1.36×**）。
把噪声抬高 45%（1/0.69）会直接把残雪推过阈值 —— **换 Scharr 与"治雪花"的目标相反**。

### 8.3 那 Scharr 的优点（各向同性）要不要拿？

要拿就得在**同等平滑度**下比。正确做法是"5×5 盒式平滑后再做 3×3 Scharr"（等效 7×7），
但那要每像素多算 4 个 5×5 和 → 4 像素并行多 16 个 `s25_of`（每个 5 个 15bit 加法器），
**估 +600~1000 LUT**。在只剩约 2300 slice、还要塞 T3 检测层的前提下不划算。
**各向同性不是当前痛点，暗区弱边缘检出率才是（那是你们的卖点）。**

### 8.4 修正后的结论

| 决策 | 结论 |
|---|---|
| 换算子到 Scharr | ❌ **不做**（SNR −31%，恶化雪花） |
| 保留现 5×5 平滑梯度为**算法 A（默认）** | ✅ 已上板验证、Sobel 不同族、弱边缘卖点的来源 |
| 治雪花 | ✅ **L2 暗区 AWB 增益限幅**（治本，近零成本）+ **L3 行列可分离 3 抽头中值**（治标，~150–250 LUT） |
| Canny / NMS | 做成 A 的一个开关（细边缘模式），不单占通路 |
| "多算法切换"第二算法 | ✅ **3×3 形态学梯度（膨胀−腐蚀）**，见 §六 |

### 8.5 为什么不用"全 3×3 中值"

全 3×3 中值在 4 像素/拍 并行下要 4 套 9 元排序网络（≈19 比较器 × 8bit），约 **600–900 LUT**。
雪花是**孤立脉冲**，用**行 3 抽头中值 + 列 3 抽头中值**的可分离近似即可（≈150–250 LUT），
效果接近、成本低一个量级。若实测不够再升级为全中值。

### 8.6 答辩话术（比"我们用了 Scharr"更有杀伤力）

> "我们没有直接搬教科书算子，而是按本传感器在暗区的噪声特性设计的：
> **5×5 盒式平滑 + 基线 2 中心差分**的等效 5×7 可分离梯度，配合**四段自适应地板**与**因果双阈值迟滞**。
> 相比官方 Sobel + 固定阈值 80，我们在暗场 Δ=10 的弱边缘上检出率从 27.2% 提到 95.9%，平坦区虚警仍为 0。"

被追问"为什么不用 Scharr/Sobel"：
> "3×3 算子的等效支持度太小，在同等信号响应下 SNR 比我们的低约 31%，
> 而暗区剩余雪花恰恰卡在阈值边缘。我们选择把支持度做进算子，而不是在后面加滤波补窟窿。"
